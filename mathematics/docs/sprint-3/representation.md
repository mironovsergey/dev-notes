# Представление графов

[← К содержанию спринта](README.md)

Способы хранения графа и их стоимость подробно разобраны в
[конспекте алгоритмов](../../../algorithms/docs/sprint-6/representation.md).
Здесь они сведены в таблицу, а основное внимание отдано тому, чего там нет:
матрица смежности - не просто способ хранения, а объект, степени которого
имеют комбинаторный смысл.

---

## 3.2 Представление графов

### 3.2.1 Матрицы смежности и инцидентности

**Матрица смежности** `A` размера `n × n`: `A[i][j] = 1`, если вершины `i` и
`j` смежны, и `0` иначе. Для взвешенного графа вместо единицы хранится вес.

```
   Граф G:                      Матрица смежности A:

       1 ─── 2                         1  2  3  4
        ╲   ╱                      1 [ 0  1  1  0 ]
         ╲ ╱                       2 [ 1  0  1  0 ]
          3                        3 [ 1  1  0  1 ]
          │                        4 [ 0  0  1  0 ]
          4

   Ребра: 1-2, 1-3, 2-3, 3-4      Степени: 2, 2, 3, 1
```

Свойства, следующие прямо из определения:

- для неориентированного графа `A` симметрична;
- сумма элементов строки `i` равна `deg(i)`;
- сумма всех элементов равна `2m` - это лемма о рукопожатиях в матричной
  записи;
- на диагонали нули, если нет петель.

**Матрица инцидентности** `B` размера `n × m`: `B[i][e] = 1`, если вершина `i`
инцидентна ребру `e`. В ориентированном случае вместо единицы ставят `+1` для
конца и `−1` для начала. Используется реже: занимает `O(nm)` памяти и не дает
проверки смежности за `O(1)`.

### 3.2.2 Списки смежности и список ребер

**Список смежности** хранит для каждой вершины перечень ее соседей, **список
ребер** - просто набор пар.

| Представление | Память | Проверка смежности | Обход соседей `v` | Когда применяется |
| --- | --- | --- | --- | --- |
| Матрица смежности | `Θ(n²)` | `O(1)` | `O(n)` | плотные графы, частые проверки смежности |
| Списки смежности | `Θ(n + m)` | `O(deg v)` | `O(deg v)` | разреженные графы, обходы |
| Список ребер | `Θ(m)` | `O(m)` | `O(m)` | алгоритмы, перебирающие ребра |

Выбор определяется [плотностью](basics.md#319-разреженные-и-плотные-графы).
Списки смежности - представление по умолчанию: обходы, из которых состоит
большинство алгоритмов, требуют именно перечисления соседей. Список ребер
удобен там, где вершины вообще не нужны, - например, в
[алгоритме Крускала](../../../algorithms/docs/sprint-6/mst.md#672-алгоритм-крускала),
где ребра сортируются по весу.

### 3.2.3 Степени матрицы смежности

**Теорема.** Элемент `(Aᵏ)[i][j]` равен числу маршрутов длины `k` из вершины
`i` в вершину `j`.

**Доказательство индукцией по `k`.** База `k = 1`: `A[i][j]` равно единице,
если ребро есть, то есть числу маршрутов длины 1.

Переход. Всякий маршрут длины `k + 1` из `i` в `j` однозначно раскладывается
на маршрут длины `k` из `i` в некоторую вершину `t` и ребро `t → j`. Разным
`t` отвечают разные маршруты, и никакой маршрут не пропущен, поэтому по
правилу суммы и правилу произведения

```
   число маршрутов длины k+1 = Σ (Aᵏ)[i][t] · A[t][j]
```

Правая часть - в точности определение элемента `[i][j]` произведения матриц
`Aᵏ · A = Aᵏ⁺¹`. Переход доказан.

Утверждение объясняет, почему умножение матриц определено «строка на столбец»:
для матрицы смежности эта формула и есть перебор промежуточной вершины.

Для графа из [3.2.1](#321-матрицы-смежности-и-инцидентности):

```
        A                      A²                    диагональ A³

   0  1  1  0            2  1  1  1                 (A³)[1][1] = 2
   1  0  1  0            1  2  1  1                 (A³)[2][2] = 2
   1  1  0  1            1  1  3  0                 (A³)[3][3] = 2
   0  0  1  0            1  1  0  1                 (A³)[4][4] = 0
```

Читается так: `(A²)[3][3] = 3`, потому что из вершины 3 есть три маршрута
длины 2, возвращающихся в нее, - по одному через каждого из трех соседей. А
`(A²)[3][4] = 0`, потому что единственный сосед вершины 4 - сама вершина 3, и
маршрута длины 2 между ними нет.

**Подсчет треугольников.** Замкнутый маршрут длины 3 из вершины `i` существует
только тогда, когда `i` входит в треугольник, и каждый треугольник дает ровно
два таких маршрута - по одному на направление обхода. Суммируя по всем
вершинам, каждый треугольник учитываем шесть раз: три стартовые вершины,
умноженные на два направления. Отсюда

```
   число треугольников = tr(A³) / 6
```

В примере `tr(A³) = 2 + 2 + 2 + 0 = 6`, треугольник один - это `{1, 2, 3}`.

**Достижимость.** Если заменить сложение на «или», а умножение на «и»,
степени матрицы отвечают на вопрос о существовании маршрута, а не о их
количестве. Как показано в [3.1.3](basics.md#313-маршруты-пути-циклы),
существование маршрута влечет существование простого пути, длина которого не
превосходит `n − 1`. Значит,

```
   R = A ∨ A² ∨ ... ∨ Aⁿ⁻¹
```

- матрица достижимости, она же
[транзитивное замыкание](../sprint-1/relations.md#136-композиция-и-обратная-функция)
отношения смежности.

**Стоимость.** Одно умножение матриц стоит `O(n³)`, а `Aᵏ` вычисляется
[быстрым возведением в степень](../sprint-1/number-theory.md#176-малая-теорема-ферма-и-быстрое-возведение-в-степень)
за `O(n³ log k)` - тот же двоичный разбор показателя, что и для чисел.
Транзитивное замыкание этим способом обходится в `O(n³ log n)`, тогда как
[алгоритм Флойда-Уоршелла](paths-and-mst.md#363-алгоритм-флойда-уоршелла)
дает `O(n³)`: он использует не длину маршрута, а номер наибольшей
промежуточной вершины, и потому обходится без логарифмического множителя.

### Типичные ошибки

1. **`(Aᵏ)[i][j]` считают числом простых путей.** Считаются маршруты:
   вершины и ребра могут повторяться. Простые пути так не считаются, и
   полиномиального способа их сосчитать не известно.
2. **Треугольники делят на 3, а не на 6.** Учитываются и стартовая вершина, и
   направление обхода.
3. **Матрицу смежности берут для разреженного графа.** При `n = 10⁵` матрица
   требует `10¹⁰` ячеек, тогда как списки смежности - порядка `m`.
4. **В матрице достижимости забывают диагональ.** Вершина достижима из себя
   маршрутом длины 0; если это нужно, диагональ заполняется отдельно.
