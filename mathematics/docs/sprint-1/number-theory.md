# Теория чисел

[← К содержанию спринта](README.md)

Самая прикладная часть дискретной математики. Арифметика остатков лежит в
основе хеширования, контрольных сумм, генераторов псевдослучайных чисел и
криптографии с открытым ключом; алгоритм Евклида и быстрое возведение в
степень входят в стандартный набор приемов наравне с бинарным поиском.

---

## 1.7 Теория чисел

### 1.7.1 Делимость и простые числа

**Делимость.** `a │ b` («`a` делит `b`»), если существует целое `k` с
`b = a · k`.

Основные свойства следуют прямо из определения:

| Свойство | Запись |
| --- | --- |
| Транзитивность | `a │ b` и `b │ c` ⟹ `a │ c` |
| Линейность | `a │ b` и `a │ c` ⟹ `a │ (bx + cy)` при любых целых `x, y` |
| Оценка | `a │ b` и `b ≠ 0` ⟹ `│a│ ≤ │b│` |

Свойство линейности используется постоянно - именно на нем держится
корректность алгоритма Евклида.

**Деление с остатком.** Для любых целого `a` и натурального `b` существуют
единственные `q` и `r` такие, что

```
   a = b·q + r,   0 ≤ r < b
```

Единственность важна: она делает остаток корректно определенной функцией и
позволяет говорить о «том самом» представителе класса вычетов.

**Остаток и оператор `%` - разные вещи.** В JavaScript, как и в C и Java, `%`
возвращает остаток со знаком делимого, а не математический остаток из
определения выше:

```js
7 % 3;      //  1
-7 % 3;     // -1, а математический остаток равен 2
```

Правильный модуль записывается как `((a % m) + m) % m`. Ошибка проявляется
при индексации по кольцу и при вычислении хеша от отрицательного значения.

**Простые числа.** Число `p > 1` **простое**, если его единственные
натуральные делители - 1 и `p`. Единица не считается ни простой, ни составной:
иначе разложение перестало бы быть единственным, так как к нему можно было бы
приписывать любое число единиц.

**Основная теорема арифметики.** Всякое `n > 1` разлагается в произведение
простых, и притом единственным образом с точностью до порядка множителей.

```
   n = p₁^a₁ · p₂^a₂ · ... · p_k^a_k
```

Из разложения сразу получается число делителей: делитель задается выбором
показателя `0 ≤ bᵢ ≤ aᵢ` независимо для каждого простого, поэтому

```
   d(n) = (a₁ + 1)(a₂ + 1) ... (a_k + 1)
```

Например, `360 = 2³ · 3² · 5` имеет `4 · 3 · 2 = 24` делителя.

Алгоритмическая сторона - проверка простоты за `O(√n)` и
[решето Эратосфена](../../../algorithms/docs/sprint-1/primes.md#182-решето-эратосфена) -
разобрана в конспекте по алгоритмам.

### 1.7.2 НОД, НОК и алгоритм Евклида

**НОД** `gcd(a, b)` - наибольшее число, делящее оба аргумента. **НОК**
`lcm(a, b)` - наименьшее число, делящееся на оба. Они связаны тождеством

```
   gcd(a, b) · lcm(a, b) = a · b
```

которое и служит способом вычислять НОК: прямой перебор кратных не нужен.

**Алгоритм Евклида** опирается на равенство

```
   gcd(a, b) = gcd(b, a mod b),   gcd(a, 0) = a
```

**Почему оно верно.** Пусть `a = bq + r`. Если `d` делит `a` и `b`, то по
свойству линейности `d` делит `r = a − bq`. Обратно, если `d` делит `b` и `r`,
то `d` делит `a = bq + r`. Значит, у пар `(a, b)` и `(b, r)` **совпадают
множества общих делителей**, а потому совпадают и наибольшие из них. Это
сильнее, чем равенство НОД, и именно поэтому рассуждение проходит без
дополнительных условий.

```
   gcd(1071, 462)

   1071 = 2 · 462 + 147
    462 = 3 · 147 +  21
    147 = 7 ·  21 +   0     →   gcd = 21
```

```js
/**
 * Возвращает наибольший общий делитель двух неотрицательных чисел.
 *
 * Время: O(log min(a, b)) итераций. Память: O(1).
 *
 * @param {number} a Первое число.
 * @param {number} b Второе число.
 * @returns {number} Наибольший общий делитель.
 */
function gcd(a, b) {
  while (b !== 0) {
    // Одновременное присваивание сохраняет инвариант gcd(a, b) = gcd(b, a mod b).
    [a, b] = [b, a % b];
  }

  return a;
}
```

**Сколько шагов.** По теореме Ламе число делений не превосходит впятеро
количества десятичных цифр меньшего аргумента, то есть алгоритм работает за
`O(log min(a, b))`. Худший случай достигается на **соседних числах
Фибоначчи**: там каждое частное равно единице, и остаток убывает медленнее
всего. Пара `(F₃₀, F₂₉) = (832040, 514229)` - наибольшая такая пара в пределах
миллиона - требует 28 делений. Исчерпывающий перебор всех пар до 3000
подтверждает закономерность: максимум всегда достигается на соседних числах
Фибоначчи, для этого диапазона это `(2584, 1597) = (F₁₈, F₁₇)` с 16
делениями.

Это тот же `φ` из [формулы Бине](recurrences.md#163-формула-бине): аргумент
уменьшается не менее чем в `φ ≈ 1.618` раза за шаг, откуда и берется
логарифмическая оценка.

### 1.7.3 Расширенный алгоритм Евклида

**Соотношение Безу.** Для любых `a, b` существуют целые `x, y` с

```
   a·x + b·y = gcd(a, b)
```

Расширенный алгоритм находит такие `x` и `y` попутно с самим НОД.

**Вывод формул пересчета.** Пусть рекурсивный вызов для пары `(b, a mod b)`
вернул `x₁, y₁` с

```
   b·x₁ + (a mod b)·y₁ = g
```

Подставим `a mod b = a − ⌊a/b⌋·b`:

```
   b·x₁ + (a − ⌊a/b⌋·b)·y₁ = g
   a·y₁ + b·(x₁ − ⌊a/b⌋·y₁) = g
```

Отсюда коэффициенты для пары `(a, b)`:

```
   x = y₁,   y = x₁ − ⌊a/b⌋·y₁
```

```js
/**
 * Возвращает НОД и коэффициенты соотношения Безу: a·x + b·y = g.
 *
 * Время: O(log min(a, b)). Память: O(log min(a, b)) на стек вызовов.
 *
 * @param {number} a Первое число.
 * @param {number} b Второе число.
 * @returns {{g: number, x: number, y: number}} НОД и коэффициенты.
 */
function extendedGcd(a, b) {
  if (b === 0) {
    return { g: a, x: 1, y: 0 };
  }

  const { g, x, y } = extendedGcd(b, a % b);

  // Коэффициенты переставляются согласно выводу выше.
  return { g, x: y, y: x - Math.floor(a / b) * y };
}

extendedGcd(1071, 462);   // { g: 21, x: -3, y: 7 }: 1071·(−3) + 462·7 = 21
```

Уравнение `a·x + b·y = c` разрешимо в целых числах тогда и только тогда, когда
`gcd(a, b) │ c`: левая часть всегда делится на НОД, поэтому условие
необходимо, а домножение соотношения Безу на `c / gcd(a, b)` показывает, что
оно достаточно.

### 1.7.4 Арифметика по модулю и сравнения

**Сравнение по модулю.** `a ≡ b (mod m)`, если `m │ (a − b)`.

Это [отношение эквивалентности](relations.md#133-отношение-эквивалентности-и-разбиение):
рефлексивность, симметричность и транзитивность проверяются напрямую. Классы
эквивалентности - **классы вычетов**, их ровно `m`, и в качестве
представителей берут `0, 1, ..., m − 1`.

Сравнения **согласованы с арифметическими операциями**: из `a ≡ b` и `c ≡ d`
следует

```
   a + c ≡ b + d,    a − c ≡ b − d,    a · c ≡ b · d   (mod m)
```

Именно это позволяет брать остаток на каждом шаге вычисления, а не в конце, -
прием, без которого не обходится ни одна реализация полиномиального хеша.

**Деления в этом списке нет.** Сокращать обе части сравнения на общий
множитель нельзя:

```
   2 · 3 ≡ 2 · 0  (mod 6),   но   3 ≢ 0  (mod 6)
```

Верное правило требует делить и модуль:

```
   a·c ≡ b·c (mod m)   ⟹   a ≡ b  (mod m / gcd(c, m))
```

В примере `gcd(2, 6) = 2`, и сокращение законно только по модулю 3: `3 ≡ 0
(mod 3)` - действительно верно.

**Переполнение при умножении.** Числа с плавающей точкой хранят целые точно
лишь до `2⁵³ ≈ 9 · 10¹⁵`. Произведение двух остатков по модулю порядка `10⁹`
достигает `10¹⁸` и теряет младшие разряды **до** взятия остатка:

```js
const m = 1_000_000_007;
(999_999_937 * 999_999_893) % m;                    // 8023 - неверно
Number((999_999_937n * 999_999_893n) % BigInt(m));  // 7980 - верно
```

Это ровно то ограничение, из-за которого при
[выборе констант](../../../algorithms/docs/sprint-4/string-hashing.md#выбор-констант)
полиномиального хеша модуль берут не больше `~10⁶`, либо переходят к `BigInt`.

### 1.7.5 Обратный элемент и решение сравнений

**Обратный элемент** `a⁻¹` по модулю `m` - решение сравнения `a · x ≡ 1
(mod m)`.

**Критерий существования:** обратный элемент существует тогда и только тогда,
когда `gcd(a, m) = 1`. Доказательство в обе стороны дает соотношение Безу:
если `gcd(a, m) = 1`, то `a·x + m·y = 1`, и взятие остатка по модулю `m` дает
`a·x ≡ 1`; обратно, из `a·x ≡ 1 (mod m)` следует `a·x − m·y = 1`, а левая
часть делится на `gcd(a, m)`, значит, этот НОД делит единицу.

Отсюда способ вычисления: обратный элемент - это коэффициент `x` из
расширенного алгоритма Евклида, приведенный к диапазону `[0, m)`.

**Линейное сравнение** `a·x ≡ b (mod m)` разрешимо тогда и только тогда, когда
`g = gcd(a, m)` делит `b`; в этом случае решений ровно `g` по модулю `m`.

```
   4x ≡ 6 (mod 10)

   g = gcd(4, 10) = 2,   2 │ 6   →   решения есть, их ровно два

   сокращаем на 2:   2x ≡ 3 (mod 5)
   обратный к 2 по модулю 5 - это 3, так как 2 · 3 = 6 ≡ 1
   x ≡ 3 · 3 = 9 ≡ 4 (mod 5)

   ответ:  x ≡ 4  и  x ≡ 9  (mod 10)
```

Проверка: `4 · 4 = 16 ≡ 6`, `4 · 9 = 36 ≡ 6 (mod 10)`.

### 1.7.6 Малая теорема Ферма и быстрое возведение в степень

**Малая теорема Ферма.** Если `p` простое и `p ∤ a`, то

```
   a^(p−1) ≡ 1  (mod p)
```

Практическое следствие: `a⁻¹ ≡ a^(p−2) (mod p)`. Для простого модуля обратный
элемент считается одним возведением в степень, без расширенного Евклида.

**Функция Эйлера** `φ(m)` - количество чисел от 1 до `m`, взаимно простых с
`m`.

| Аргумент | Значение |
| --- | --- |
| `φ(p)` для простого `p` | `p − 1` |
| `φ(pᵏ)` | `pᵏ − pᵏ⁻¹` |
| `φ(a·b)` при `gcd(a, b) = 1` | `φ(a) · φ(b)` |

**Теорема Эйлера** обобщает теорему Ферма на составной модуль: при
`gcd(a, m) = 1` выполняется `a^φ(m) ≡ 1 (mod m)`. При простом `m` это в
точности малая теорема Ферма, поскольку `φ(p) = p − 1`.

**Быстрое возведение в степень** вычисляет `aⁿ` за `O(log n)` умножений,
используя двоичную запись показателя:

```
   a¹³ = a^(1101₂) = a⁸ · a⁴ · a¹
```

```js
/**
 * Возводит основание в степень по модулю за логарифмическое число умножений.
 *
 * Вычисления ведутся в BigInt: произведение двух остатков по модулю порядка
 * 10⁹ выходит за точный диапазон чисел с плавающей точкой.
 *
 * Время: O(log exponent). Память: O(1).
 *
 * @param {bigint} base Основание.
 * @param {bigint} exponent Неотрицательный показатель.
 * @param {bigint} modulus Модуль, больший единицы.
 * @returns {bigint} Значение base^exponent по модулю modulus.
 */
function modularPower(base, exponent, modulus) {
  let result = 1n;
  let current = base % modulus;

  while (exponent > 0n) {
    if (exponent % 2n === 1n) {
      result = (result * current) % modulus;
    }

    current = (current * current) % modulus;
    exponent /= 2n;
  }

  return result;
}

modularPower(2n, 10n, 1000n);   // 24n, так как 1024 mod 1000 = 24
```

**Тест Ферма и почему он не доказательство.** Из малой теоремы следует, что
при простом `p` сравнение `a^(p−1) ≡ 1 (mod p)` выполняется для всех
подходящих `a`. Обратное неверно. **Числа Кармайкла** проходят тест при любом
`a`, взаимно простом с ними, оставаясь составными; наименьшее из них

```
   561 = 3 · 11 · 17
```

Все 320 значений `a`, взаимно простых с 561, дают `a⁵⁶⁰ ≡ 1 (mod 561)` -
проверено перебором. Поэтому тест Ферма отвечает «составное» надежно, а
«простое» - лишь предположительно; на практике используют тест
Миллера-Рабина.

### Типичные ошибки

1. **`%` принимается за математический остаток.** Для отрицательных значений
   `%` возвращает отрицательный результат; нужен `((a % m) + m) % m`.
2. **Сокращение сравнения на общий множитель.** Делить можно только вместе с
   модулем, на `gcd(c, m)`.
3. **Обратный элемент ищется при `gcd(a, m) ≠ 1`.** Его не существует;
   расширенный Евклид в этом случае дает коэффициенты для НОД, а не для
   единицы.
4. **Умножение по модулю в обычных числах.** При модуле порядка `10⁹`
   произведение теряет точность до взятия остатка.
5. **Тест Ферма считается доказательством простоты.** Числа Кармайкла
   проходят его при всех допустимых основаниях.
6. **Единица считается простым числом.** Тогда разложение на простые
   перестает быть единственным.
