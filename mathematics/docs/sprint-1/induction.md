# Математическая индукция

[← К содержанию спринта](README.md)

Индукция - основной способ доказывать утверждения о натуральных числах и о
рекурсивно построенных объектах. Для программиста она интересна прежде всего
тем, что доказательство корректности рекурсивной функции устроено ровно так же,
как индуктивное доказательство, и распадается на те же две части.

---

## 1.4 Математическая индукция

### 1.4.1 Принцип индукции, база и переход

**Принцип математической индукции.** Пусть `P(n)` - утверждение о натуральном
`n`. Если

1. `P(n₀)` истинно (**база индукции**) и
2. для всякого `k ≥ n₀` из `P(k)` следует `P(k + 1)` (**индукционный
   переход**),

то `P(n)` истинно для всех `n ≥ n₀`.

**Почему это работает.** Принцип не постулат из ниоткуда: он равносилен тому,
что всякое непустое подмножество `ℕ` имеет наименьший элемент. Пусть при
выполненных условиях множество контрпримеров непусто и `m` - его наименьший
элемент. Тогда `m ≠ n₀`, потому что база проверена. Значит, `m − 1 ≥ n₀`, и
`m − 1` контрпримером не является, то есть `P(m − 1)` истинно. Но переход из
`P(m − 1)` дает `P(m)` - противоречие с тем, что `m` контрпример.

Запись доказательства всегда содержит четыре части: формулировка `P(n)`,
проверка базы, формулировка предположения, вывод `P(k + 1)`.

**Пример 1. Сумма первых `n` натуральных чисел.**

```
   P(n):  1 + 2 + ... + n = n(n + 1) / 2
```

База, `n = 1`: слева `1`, справа `1 · 2 / 2 = 1`.

Переход. Пусть `P(k)` верно. Тогда

```
   1 + ... + k + (k + 1) = k(k + 1)/2 + (k + 1)
                         = (k + 1) · (k/2 + 1)
                         = (k + 1)(k + 2)/2
```

- это в точности `P(k + 1)`.

**Пример 2. Неравенство `2ⁿ ≥ n²`.** Здесь важно, где стоит база.

```
   n  │ 1  2  3   4   5   6
   ───┼─────────────────────
   2ⁿ │ 2  4  8  16  32  64
   n² │ 1  4  9  16  25  36
```

При `n = 3` неравенство ложно, поэтому база берется при `n = 4`, где обе части
равны 16.

Переход. Пусть `2ᵏ ≥ k²` при `k ≥ 4`. Тогда `2ᵏ⁺¹ = 2 · 2ᵏ ≥ 2k²`. Осталось
показать `2k² ≥ (k + 1)²`, то есть `k² − 2k − 1 ≥ 0`. Корни трехчлена -
`1 ± √2`, больший из них меньше 2.5, значит, при `k ≥ 3` неравенство
выполняется, и тем более при `k ≥ 4`.

Шаг с трехчленом выписан отдельно намеренно: именно такие места и пропускают,
а без них переход не доказан.

### 1.4.2 Сильная индукция

В обычном переходе используется только `P(k)`. **Сильная индукция** разрешает
опираться на все предыдущие значения сразу:

```
   из  P(n₀) ∧ P(n₀+1) ∧ ... ∧ P(k)   следует   P(k + 1)
```

Новой аксиомы это не требует: сильная индукция получается из обычной, если
применить ее к утверждению `Q(n) = P(n₀) ∧ ... ∧ P(n)`. Разница в удобстве, а
не в силе.

Сильная индукция нужна там, где задача сводится не к предыдущему значению, а к
существенно меньшему и заранее неизвестному.

**Пример. Всякое `n ≥ 2` разложимо в произведение простых.**

База, `n = 2`: число простое, произведение из одного множителя.

Переход. Пусть утверждение верно для всех значений от 2 до `k`. Рассмотрим
`k + 1`. Если оно простое, разложение состоит из него самого. Если составное,
то `k + 1 = a · b`, где `2 ≤ a, b ≤ k`. К обоим множителям применимо
предположение, и объединение их разложений дает разложение для `k + 1`.

Обычная индукция здесь не проходит: `P(k)` о числе `k` ничего не говорит про
делители `k + 1`.

Та же схема доказывает корректность алгоритмов «разделяй и властвуй»:
[сортировка слиянием](../../../algorithms/docs/sprint-3/sorting.md#324-сортировка-слиянием)
вызывает себя на массивах длины `⌊n/2⌋` и `⌈n/2⌉`, и предположение требуется
сразу для всех меньших длин.

### 1.4.3 Структурная индукция и связь с рекурсией

Индукция применима не только к числам. Если множество задано **рекурсивным
определением** - базовые объекты плюс правила порождения новых, - то для
доказательства свойства достаточно проверить его на базовых объектах и
показать, что правила его сохраняют. Это **структурная индукция**.

**Пример.** Полное бинарное дерево определяется так: одна вершина - дерево;
если `L` и `R` - деревья, то новая вершина с потомками `L` и `R` - дерево.
Утверждение: число листьев на единицу больше числа внутренних вершин.

База: дерево из одной вершины имеет 1 лист и 0 внутренних вершин.

Переход: пусть у `L` листьев `l₁` и внутренних вершин `i₁`, у `R` -
соответственно `l₂` и `i₂`, причем `l₁ = i₁ + 1` и `l₂ = i₂ + 1`. В новом
дереве листьев `l₁ + l₂`, внутренних вершин `i₁ + i₂ + 1` (добавился корень).
Тогда

```
   l₁ + l₂ = (i₁ + 1) + (i₂ + 1) = (i₁ + i₂ + 1) + 1
```

**Рекурсия и индукция - одно рассуждение.** Рекурсивная функция состоит из
[базового и рекурсивного случаев](../../../algorithms/docs/sprint-3/recursion.md#311-рекурсивный-и-базовый-случаи),
и доказательство ее корректности повторяет эту структуру:

| Индукция | Рекурсия |
| --- | --- |
| База `P(n₀)` | Базовый случай возвращает верный ответ |
| Предположение `P(k)` | Рекурсивный вызов считается работающим верно |
| Переход `P(k) → P(k+1)` | Из результата вызова собирается ответ текущего уровня |
| Утверждение верно для всех `n` | Функция верна на любом входе |

Условие завершения рекурсии тоже приходит отсюда: аргумент вызова должен
убывать по такому порядку, в котором нельзя спускаться бесконечно. Для чисел
это обычное `<` на `ℕ`, для структур - переход к собственной части, для
графов - убывание числа непосещенных вершин.

### 1.4.4 Типичные ошибки

**1. Пропущенная база.** Один переход не доказывает ничего. Для утверждения
`P(n): n = n + 1` переход проходит безупречно: из `n = n + 1` прибавлением
единицы получается `n + 1 = n + 2`. Утверждение при этом ложно при каждом `n`
- нет базы.

**2. База проверена не в той точке.** Если переход обоснован лишь при
`k ≥ 4`, а база взята при `n = 1`, доказательства нет: цепочка от `n = 1` до
`n = 4` не построена. В примере с `2ⁿ ≥ n²` это не формальность - при `n = 3`
утверждение действительно ложно.

**3. Переход, ломающийся на малых значениях.** Классический ложный вывод:
«в любом наборе из `n` чисел все числа равны». База `n = 1` верна. Переход:
взяв набор из `n + 1` чисел, удалим последнее - по предположению первые `n`
равны; удалим первое - равны последние `n`; значит, равны все. Ошибка в том,
что рассуждение неявно требует общего элемента у двух подмножеств, а при
`n + 1 = 2` подмножества `{a}` и `{b}` не пересекаются. Переход верен для всех
`n ≥ 2` и неверен ровно при `n = 1` - там, где он и нужен.

**4. Предположение подменяется доказываемым.** Использовать `P(k + 1)` при
выводе `P(k + 1)` нельзя ни в каком виде, в том числе неявно - через формулу,
справедливость которой сама зависит от `P(k + 1)`.

**5. Слишком слабое предположение.** Иногда переход не проходит именно потому,
что утверждение слишком слабое, и доказать более сильное утверждение проще:
предположение тогда дает больше. Прием стандартный и на первый взгляд
парадоксальный; в динамическом программировании ему соответствует
[расширение состояния](../../../algorithms/docs/sprint-7/dynamic.md).
