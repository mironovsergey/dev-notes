## 8.3 Поиск шаблона в строке

**Задача.** Дан текст `text` длины `n` и шаблон `pattern` длины `m`. Найти, в
каких позициях текста встречается шаблон.

Это самая частая операция над строками: поиск в редакторе, `grep`,
подсветка совпадений, фильтрация логов.

---

### 8.3.1 Поиск первого вхождения шаблона в строку

**Наивный алгоритм.** Прикладываем шаблон к каждой позиции текста и посимвольно
сравниваем.

```
   text    = a b a b a b c a
   pattern = a b a b c

   pos = 0:  a b a b a b c a
             a b a b c
             ✓ ✓ ✓ ✓ ✗        расхождение на 5-м символе

   pos = 1:  a b a b a b c a
               a b a b c
               ✗              расхождение сразу

   pos = 2:  a b a b a b c a
                 a b a b c
                 ✓ ✓ ✓ ✓ ✓    совпадение, ответ 2
```

```js
/**
 * Возвращает позицию первого вхождения шаблона в текст, начиная с позиции start.
 *
 * Шаблон прикладывается к каждой позиции текста и сравнивается посимвольно.
 * Одного несовпадения достаточно, чтобы прекратить проверку текущей позиции.
 *
 * Время: O((n − m + 1)·m), в худшем случае O(n·m). Память: O(1).
 *
 * @param {string} text Текст, в котором выполняется поиск.
 * @param {string} pattern Искомый шаблон.
 * @param {number} start Позиция, начиная с которой ведется поиск.
 * @returns {number} Позиция вхождения либо -1, если вхождений нет.
 */
function find(text, pattern, start = 0) {
  // Шаблон длиннее текста поместиться не может
  if (pattern.length > text.length) {
    return -1;
  }

  for (let pos = start; pos <= text.length - pattern.length; pos++) {
    let matched = true;

    for (let offset = 0; offset < pattern.length; offset++) {
      if (text[pos + offset] !== pattern[offset]) {
        matched = false;
        break;
      }
    }

    if (matched) {
      return pos;
    }
  }

  return -1;
}
```

Значение `-1` для «не найдено» - общепринятое соглашение: позиции `-1` в строке
не существует, и его нельзя спутать с настоящим ответом. Так же ведет себя
встроенный `indexOf`.

Пустой шаблон по этой реализации находится в позиции `start` - согласуется с
`indexOf` и с математическим определением: пустая строка является префиксом
любой.

### 8.3.2 Поиск всех вхождений шаблона в строку

Повторяем поиск, каждый раз сдвигая начало.

```js
/**
 * Возвращает позиции всех вхождений шаблона в текст.
 *
 * Поиск продолжается с позиции, следующей за началом найденного вхождения,
 * а не за его концом: вхождения могут перекрываться.
 *
 * Время: O(n·m). Память: O(числа вхождений).
 *
 * @param {string} text Текст, в котором выполняется поиск.
 * @param {string} pattern Искомый шаблон.
 * @returns {number[]} Позиции вхождений по возрастанию.
 */
function findAll(text, pattern) {
  const occurrences = [];
  let start = 0;

  for (;;) {
    const pos = find(text, pattern, start);

    if (pos === -1) {
      return occurrences;
    }

    occurrences.push(pos);
    start = pos + 1;
  }
}
```

#### Перекрывающиеся вхождения

Строка `start = pos + 1` выглядит мелочью, но это содержательное решение.

```
   text    = a a a a
   pattern = a a

   start = pos + 1:  вхождения 0, 1, 2   - все три
   start = pos + m:  вхождения 0, 2      - перекрытия пропущены
```

Какой вариант верен, определяется условием задачи. Формулировка «найти все
вхождения» почти всегда означает **включая перекрывающиеся**; формулировка
«разбить на части» или «заменить все» - обычно нет. Встроенный
`String.prototype.replaceAll` работает по второму правилу.

---

### Сложность наивного алгоритма

Позиций для проверки - `n − m + 1`, на каждой до `m` сравнений. Итого
`O(n·m)`.

На практике алгоритм ведет себя гораздо лучше: обычно расхождение находится на
первом-втором символе, и внутренний цикл почти сразу прерывается.

Но худший случай реален и достижим:

```
   text    = a a a a a a a a a b      (n символов)
   pattern = a a a a b                (m символов)

   На каждой из n − m + 1 позиций совпадают первые m − 1 символов
   и расходится последний. Итого ≈ n·m сравнений.
```

При `m ≈ n/2` это `Θ(n²)`. Для `n = 10⁵` - порядка `10⁹` операций, за лимит.

Причина неэффективности **не в переборе позиций, а в потере информации**. Когда
на позиции `pos` совпали первые `k` символов и произошло расхождение, мы уже
знаем `k` символов текста - и все равно начинаем следующую проверку с нуля,
сдвинувшись всего на одну позицию.

Именно эту потерю устраняет [префикс-функция](prefix-function.md#84-префикс-функция):
она заранее вычисляет, на сколько можно сдвинуть шаблон, не потеряв возможных
вхождений, и снижает сложность до `O(n + m)`.
