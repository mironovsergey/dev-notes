## Строка как структура данных

**Строка** - последовательность символов некоторого алфавита `Σ`. Длина строки
`s` обозначается `|s|`.

Обозначение полуинтервалом: `s[j, k)` - подстрока из символов с `j`-го по
`(k − 1)`-й включительно. Та же конвенция, что у
[бинарного поиска](../sprint-1/search.md#инвариант): левая граница включена,
правая исключена, длина равна `k − j`.

### Неизменяемость и ее последствия

В JavaScript, как и в большинстве языков, строки **неизменяемы**: изменить
символ на месте нельзя, любая «модификация» создает новую строку.

Отсюда важное практическое следствие: **приписывание символа к строке стоит
`O(n)`, а не `O(1)`**. Цикл вида

```js
// Так делать нельзя при большом n
let result = '';

for (const char of source) {
  result += char;
}
```

в общем случае дает `O(n²)`. Правильный прием - накопить части в массиве и
один раз склеить:

```js
const parts = [];

for (const char of source) {
  parts.push(char);
}

const result = parts.join('');
```

Современные движки частично оптимизируют конкатенацию, но полагаться на это
нельзя - на длинных строках разница проявляется.

### Вставка в середину строки

Вставка подстроки в середину требует **сдвига хвоста**, и потому стоит `O(n)` -
ровно как [вставка в середину массива](../sprint-2/arrays.md#211-вставки-и-удаления-в-динамических-массивах).
Строка и есть массив символов.

```js
/**
 * Вставляет подстроку в строку перед заданной позицией.
 *
 * Строки в JavaScript неизменяемы, поэтому «сдвиг хвоста» выполняется неявно:
 * результат собирается из трех частей. Сложность от этого не меняется -
 * копируются все символы строки.
 *
 * Время: O(|string| + |substring|). Память: O(|string| + |substring|).
 *
 * @param {string} string Исходная строка.
 * @param {number} index Позиция вставки, от 0 до длины строки включительно.
 * @param {string} substring Вставляемая подстрока.
 * @returns {string} Новая строка со вставленной подстрокой.
 */
function insert(string, index, substring) {
  if (index < 0 || index > string.length) {
    throw new RangeError('Нет такой позиции');
  }

  return string.slice(0, index) + substring + string.slice(index);
}
```

Если вставок много, каждая из них `O(n)`, и суммарно получается `O(k·n)`. Когда
все позиции вставки известны заранее, вся серия выполняется за один проход:
пройти по исходной строке, вставляя нужные куски в нужных местах, и склеить
результат один раз.

## 8.1 Сравнение строк

Две строки **равны**, если совпадают их длины и все символы попарно.

```js
/**
 * Проверяет равенство двух строк посимвольно.
 *
 * Сравнение длин выполняется первым: строки разной длины заведомо не равны,
 * и это отсекает большинство случаев за O(1).
 *
 * Время: O(min(|first|, |second|)). Память: O(1).
 *
 * @param {string} first Первая строка.
 * @param {string} second Вторая строка.
 * @returns {boolean} true, если строки совпадают.
 */
function isEqual(first, second) {
  if (first.length !== second.length) {
    return false;
  }

  for (let i = 0; i < first.length; i++) {
    if (first[i] !== second[i]) {
      return false;
    }
  }

  return true;
}
```

Оператор `===` в JavaScript делает ровно это же. Писать сравнение вручную нужно
только тогда, когда правило сравнения нестандартное.

### Лексикографический порядок

Строки упорядочиваются, как слова в словаре: сравниваются первые символы, при
равенстве - вторые, и так далее. Если одна строка закончилась, а расхождений не
нашлось, **более короткая считается меньшей**.

```
   «abc»  <  «abd»      различие в третьем символе
   «ab»   <  «abc»      первая закончилась, оставшись префиксом второй
   «abc»  =  «abc»
```

```js
/**
 * Сравнивает строки лексикографически.
 *
 * Время: O(min(|first|, |second|)). Память: O(1).
 *
 * @param {string} first Первая строка.
 * @param {string} second Вторая строка.
 * @returns {number} -1, если first раньше second; 1, если позже; 0 при равенстве.
 */
function compare(first, second) {
  const common = Math.min(first.length, second.length);

  for (let i = 0; i < common; i++) {
    if (first[i] !== second[i]) {
      return first[i] < second[i] ? -1 : 1;
    }
  }

  // Расхождений нет: короче - значит раньше
  if (first.length === second.length) {
    return 0;
  }

  return first.length < second.length ? -1 : 1;
}
```

Сложность `O(min(|s|, |t|))` в худшем случае - когда строки совпадают на всем
общем префиксе. Если сравнений много, эту оценку можно улучшить до
`O(log)` на запрос; так решается
[задача 8.7](string-compare.md#87-быстрое-сравнение-двух-строк).

> **Осторожно со сравнением символов.** Оператор `<` сравнивает символы по их
> кодам, а не по алфавиту. Для строчных латинских букв это совпадает, но
> `'Z' < 'a'` истинно, потому что заглавные буквы идут в таблице раньше
> строчных. Для естественных языков нужен `Intl.Collator`.

## 8.2 Подстроки, префиксы и суффиксы

Три понятия, на которых держится весь спринт.

**Подстрока** - непрерывный участок строки. Порядок символов сохраняется,
пропусков нет.

**Префикс** - начальный участок строки, то есть подстрока вида `s[0, k)`.

**Суффикс** - конечный участок, то есть подстрока вида `s[k, n)`.

Для строки `«frontend»`:

```
   строка:      f r o n t e n d

   префиксы:    «», «f», «fr», «fro», «fron», «front», «fronte»,
                «fronten», «frontend»                       - всего 9

   суффиксы:    «», «d», «nd», «end», «tend», «ntend», «ontend»,
                «rontend», «frontend»                       - всего 9

   подстроки:   «front», «end», «onte», «fro», «d», «» и другие
```

Различие с **подпоследовательностью** принципиально: подстрока идет подряд,
подпоследовательность допускает пропуски. Для `«frontend»` строка `«fed»` -
подпоследовательность, но не подстрока. Задача о
[наибольшей общей подпоследовательности](../sprint-7/lcs.md#723-наибольшая-общая-подпоследовательность)
и задача о наибольшей общей подстроке - разные задачи с разными решениями.

### Количество

| | Сколько |
| --- | --- |
| Префиксов | `n + 1` (включая пустой и всю строку) |
| Суффиксов | `n + 1` |
| Подстрок | `n·(n + 1) / 2 + 1`, то есть `Θ(n²)` |

Подстрок квадратично много, и это сразу говорит: алгоритм, перебирающий все
подстроки, не может быть быстрее `O(n²)`.

### Собственный префикс

**Собственный префикс** - любой префикс, кроме самой строки. Аналогично
определяется собственный суффикс.

Уточнение выглядит формальным, но без него [префикс-функция](prefix-function.md#84-префикс-функция)
теряет смысл: наибольшим префиксом, совпадающим с суффиксом, всегда была бы вся
строка целиком.

### Ключевое утверждение

> **Любая подстрока есть префикс некоторого суффикса.**

Подстрока `s[j, k)` - это префикс длины `k − j` суффикса `s[j, n)`.

```
   s = f r o n t e n d
             └───────┘   суффикс s[3, 8) = «ntend»
             └───┘       его префикс длины 3 = «nte» - подстрока s[3, 6)
```

Утверждение простое, но именно оно связывает поиск подстрок с работой над
префиксами и суффиксами. На нем построены и
[алгоритм КМП](prefix-function.md#85-эффективный-поиск-шаблона-в-строке), и
суффиксные структуры данных: раз всякая подстрока - префикс суффикса, то,
организовав все суффиксы в [префиксное дерево](trie.md#86-префиксное-дерево),
мы получаем доступ ко всем подстрокам сразу.
