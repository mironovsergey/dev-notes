## 8.7 Быстрое сравнение двух строк

**Условие.** Дан набор строк. Поступает много запросов вида «сравнить строку
`i` со строкой `j` лексикографически». Отвечать нужно быстро.

Прямое [посимвольное сравнение](strings.md#81-сравнение-строк) стоит
`O(min(|s|, |t|))` на запрос. Если строк `n` длины до `m` и запросов `q`, это
`O(q·m)` - при `q = 10⁵` и `m = 10⁵` уже `10¹⁰` операций.

### Ключевое наблюдение

Лексикографическое сравнение полностью определяется **длиной наибольшего общего
префикса** двух строк. Пусть она равна `L`. Тогда:

- если `L` равна длинам обеих строк - строки равны;
- если `L` равна длине одной из них - эта строка является префиксом другой и
  потому меньше;
- иначе достаточно сравнить символы на позиции `L` - первые различающиеся.

```
   s = «abcxy»,  t = «abdz»

   общий префикс «ab», L = 2
   s[2] = «c», t[2] = «d»  →  «c» < «d»  →  s меньше
```

Значит, вся задача сводится к тому, чтобы быстро находить `L`.

### Как искать длину общего префикса за `O(log m)`

Работает связка из двух приемов, оба уже встречались.

**Прием 1: [полиномиальные хеши префиксов](../sprint-4/string-hashing.md#хеши-подстрок-за-o1).**
Предподсчет за `O(m)` на строку дает возможность за `O(1)` сравнивать любые два
префикса.

**Прием 2: [бинарный поиск](../sprint-1/search.md#17-бинарный-поиск) по длине.**
Свойство «префиксы длины `k` совпадают» **монотонно**: если совпадают префиксы
длины `k`, то совпадают и все более короткие. Монотонность и есть условие
применимости бинарного поиска.

```
   длина k:      0    1    2    3    4    5
   совпадают?    да   да   да   нет  нет  нет
                           ↑
                    искомая граница L = 2
```

### Реализация

```js
const HASH_BASE = 31;
// Модуль ограничен так, чтобы произведение двух остатков не превышало 2^53
const HASH_MODULO = 1_000_003;

/**
 * Вычисляет хеши всех префиксов строки.
 *
 * Остаток берется на каждом шаге. Без него значение растет экспоненциально:
 * уже на строке из 20 символов оно превышает 2^53, разные строки начинают
 * получать одинаковые хеши, и сравнение становится неверным.
 *
 * Время: O(|s|). Память: O(|s|).
 *
 * @param {string} s Строка.
 * @returns {number[]} Массив длины |s| + 1; элемент с индексом k - хеш
 *   префикса длины k.
 */
function prefixHashes(s) {
  const hashes = new Array(s.length + 1).fill(0);

  for (let i = 0; i < s.length; i++) {
    hashes[i + 1] = (hashes[i] * HASH_BASE + s.charCodeAt(i)) % HASH_MODULO;
  }

  return hashes;
}

/**
 * Возвращает длину наибольшего общего префикса двух строк.
 *
 * Свойство «префиксы длины k совпадают» монотонно по k, поэтому граница
 * ищется бинарным поиском. Сравнение префиксов заданной длины выполняется
 * за O(1) по предвычисленным хешам.
 *
 * Время: O(log min(|first|, |second|)). Память: O(1).
 *
 * @param {number[]} firstHashes Хеши префиксов первой строки.
 * @param {number[]} secondHashes Хеши префиксов второй строки.
 * @param {number} maxLength Наименьшая из длин строк.
 * @returns {number} Длина наибольшего общего префикса.
 */
function commonPrefixLength(firstHashes, secondHashes, maxLength) {
  let left = 0;
  let right = maxLength + 1;

  // Инвариант: префиксы длины left совпадают, длины right - нет
  while (right - left > 1) {
    const middle = left + Math.floor((right - left) / 2);

    if (firstHashes[middle] === secondHashes[middle]) {
      left = middle;
    } else {
      right = middle;
    }
  }

  return left;
}

/**
 * Сравнивает две строки лексикографически по предвычисленным хешам.
 *
 * Время: O(log min(|first|, |second|)). Память: O(1).
 *
 * @param {string} first Первая строка.
 * @param {string} second Вторая строка.
 * @param {number[]} firstHashes Хеши префиксов первой строки.
 * @param {number[]} secondHashes Хеши префиксов второй строки.
 * @returns {number} -1, если first раньше second; 1, если позже; 0 при равенстве.
 */
function compareByHashes(first, second, firstHashes, secondHashes) {
  const common = commonPrefixLength(
    firstHashes,
    secondHashes,
    Math.min(first.length, second.length),
  );

  // Обе строки закончились одновременно - они равны
  if (common === first.length && common === second.length) {
    return 0;
  }

  // Одна закончилась раньше - она является префиксом другой и потому меньше
  if (common === first.length) {
    return -1;
  }

  if (common === second.length) {
    return 1;
  }

  return first[common] < second[common] ? -1 : 1;
}

/**
 * Отвечает на серию запросов о сравнении строк.
 *
 * Хеши префиксов вычисляются один раз для всех строк, после чего каждый запрос
 * обрабатывается за логарифмическое время.
 *
 * Время: O(L + q·log m), где L - суммарная длина строк, q - число запросов,
 * m - наибольшая длина строки. Память: O(L).
 *
 * @param {string[]} strings Набор строк.
 * @param {Array<[number, number]>} queries Запросы в виде пар индексов.
 * @returns {number[]} Результаты сравнений в порядке запросов.
 */
function compareStrings(strings, queries) {
  const hashes = strings.map(prefixHashes);
  const results = [];

  for (const [i, j] of queries) {
    results.push(compareByHashes(strings[i], strings[j], hashes[i], hashes[j]));
  }

  return results;
}

compareStrings(['abc', 'abd', 'ab'], [[0, 1], [0, 2], [1, 2]]);
// [-1, 1, 1]
```

### Три места, где легко ошибиться

**Хеш без взятия остатка.** Значение `hash · base + code` растет
экспоненциально. Уже на строке из 20 символов оно достигает `10³⁰` - далеко за
пределами точного представления целых чисел, - и **разные строки получают
одинаковые хеши**. Проверить это просто: строки из 16 символов, различающиеся
последним, дадут совпадающий хеш. Ошибка не проявляется на коротких примерах и
потому особенно неприятна.

**Массив хешей смещен на единицу.** Удобно хранить `hashes[k]` как хеш префикса
**длины** `k`, а не хеш, оканчивающийся на позиции `k`. Тогда `hashes[0] = 0` -
хеш пустого префикса, - и в бинарном поиске не нужны поправки на единицу.

**Коллизии.** Равенство хешей не гарантирует равенства строк. Вероятность
ошибки примерно `1 / modulo` на сравнение; при большом числе запросов ее
снижают
[двойным хешированием](../sprint-4/string-hashing.md#коллизии-и-их-подбор) по
двум разным модулям. Если требуется гарантия, а не вероятностный ответ, вместо
хешей берут суффиксный массив.

### Итог

| | Посимвольное сравнение | Хеши и бинарный поиск |
| --- | --- | --- |
| Предподсчет | нет | `O(L)` |
| Запрос | `O(m)` | **`O(log m)`** |
| Гарантия точности | **абсолютная** | вероятностная |

Прием окупается, когда запросов много: один и тот же предподсчет обслуживает
все запросы. Ради единственного сравнения строить хеши бессмысленно.
