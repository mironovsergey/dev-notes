## 5.3 Обход дерева

**Обход** - посещение всех вершин дерева в определенном порядке. Порядок
определяется тем, в какой момент обрабатывается сама вершина относительно
своих поддеревьев.

Все обходы ниже иллюстрируются на одном дереве:

```
              (1)
             /   \
          (2)     (3)
         /   \
      (4)    (5)
```

---

### 5.3.1 Прямой обход

Сначала вершина, потом поддеревья (preorder). Вершина обрабатывается в момент,
когда мы приходим в нее **впервые**.

```js
/**
 * Печатает значения вершин в прямом порядке: корень, затем поддеревья.
 *
 * Время: O(n). Память: O(h) на кадры стека вызовов.
 *
 * @param {Node|null} node Корень поддерева.
 * @returns {void}
 */
function printPreorder(node) {
  if (node === null) {
    return;
  }

  console.log(node.value);
  printPreorder(node.left);
  printPreorder(node.right);
}

// Для дерева выше: 1 2 4 5 3
```

Применяется, когда родителя нужно обработать раньше детей: копирование дерева,
сериализация структуры, печать иерархии с отступами.

---

### 5.3.2 Обратный обход

Сначала поддеревья, потом вершина (postorder). Вершина обрабатывается в момент,
когда мы уходим из нее **навсегда**.

```js
/**
 * Печатает значения вершин в обратном порядке: поддеревья, затем корень.
 *
 * Время: O(n). Память: O(h).
 *
 * @param {Node|null} node Корень поддерева.
 * @returns {void}
 */
function printPostorder(node) {
  if (node === null) {
    return;
  }

  printPostorder(node.left);
  printPostorder(node.right);
  console.log(node.value);
}

// Для дерева выше: 4 5 2 3 1
```

Применяется, когда результат для вершины зависит от результатов детей:
[вычисление высоты](binary-trees.md#базовые-операции) и размеров поддеревьев,
удаление дерева, вычисление арифметического выражения по его дереву разбора.

Прямой и обратный обходы - это в точности
[прямой и обратный ход рекурсии](../sprint-3/recursion.md#прямой-и-обратный-ход):
действие до рекурсивных вызовов дает preorder, после - postorder.

---

### 5.3.3 Центрированный обход

Левое поддерево, вершина, правое поддерево (inorder). Обход определен только
для бинарных деревьев: у вершины произвольной арности нет «центральной оси».

Два варианта:

- **LMR** (left-middle-right) - слева направо;
- **RML** (right-middle-left) - справа налево.

```js
/**
 * Печатает значения вершин в центрированном порядке LMR.
 *
 * Время: O(n). Память: O(h).
 *
 * @param {Node|null} node Корень поддерева.
 * @returns {void}
 */
function printInorder(node) {
  if (node === null) {
    return;
  }

  printInorder(node.left);
  console.log(node.value);
  printInorder(node.right);
}

// Для дерева выше: 4 2 5 1 3
```

### 5.3.4 Обходы дерева поиска

Вот ради чего центрированный обход важен: **LMR-обход дерева поиска выдает
ключи в порядке возрастания**.

Доказательство прямо следует из свойства BST. Для любой вершины все левое
поддерево меньше ее, все правое - больше. LMR печатает сначала левое, потом
вершину, потом правое, то есть меньшие ключи раньше больших. Рекурсивно то же
верно внутри каждого поддерева.

```
        (8)
       /   \
    (3)     (10)
   /   \       \
 (1)   (6)     (14)

LMR: 1 3 6 8 10 14   ← по возрастанию
RML: 14 10 8 6 3 1   ← по убыванию
```

Следствия:

- дерево поиска можно «прочитать» как отсортированный массив за `O(n)`;
- вставив `n` элементов в BST и обойдя его в порядке LMR, получаем сортировку
  за `O(n log n)` в среднем - правда, с `O(n)` памяти и деградацией до `O(n²)`
  на отсортированном входе;
- проверить, что дерево является деревом поиска, можно, убедившись в
  монотонности его LMR-обхода.

```js
/**
 * Проверяет, является ли дерево деревом поиска.
 *
 * Проверка ведется по допустимому интервалу ключей, сужающемуся при спуске:
 * сравнения только с непосредственными детьми недостаточно, нарушение может
 * находиться сколь угодно глубоко.
 *
 * Время: O(n). Память: O(h).
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} min Нижняя граница допустимых ключей, исключительно.
 * @param {number} max Верхняя граница допустимых ключей, исключительно.
 * @returns {boolean} true, если поддерево является деревом поиска.
 */
function isBST(node, min = -Infinity, max = Infinity) {
  if (node === null) {
    return true;
  }

  if (node.key <= min || node.key >= max) {
    return false;
  }

  return (
    isBST(node.left, min, node.key) && isBST(node.right, node.key, max)
  );
}
```

### 5.3.5 Поиск элементов в интервале

Задача: вывести все ключи из отрезка `[low, high]` в порядке возрастания.
Например, найти все товары ценой от 1500 до 1900 рублей.

```
                   (1600)
                  /      \
           (1400)          (2000)
          /      \        /      \
      (900)   (1550)  (1600)   (2200)
                          \
                         (1800)

Интервал [1500, 1900] → 1550, 1600, 1600, 1800
```

Наивное решение - обойти все дерево за `O(n)` и отфильтровать. Дерево поиска
позволяет лучше: **спуск в поддерево, заведомо лежащее вне интервала, можно не
выполнять**.

```js
/**
 * Собирает все ключи из отрезка [low, high] в порядке возрастания.
 *
 * Поддерево не посещается, если его ключи заведомо вне интервала: при
 * node.key <= low весь левый спуск бесполезен, при node.key >= high - правый.
 * Обход остается центрированным, поэтому результат сразу упорядочен.
 *
 * Время: O(h + k), где k - количество ключей в интервале. Память: O(h).
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} low Нижняя граница интервала, включительно.
 * @param {number} high Верхняя граница интервала, включительно.
 * @param {number[]} result Накопитель результата.
 * @returns {number[]} Ключи интервала в порядке возрастания.
 */
function findInRange(node, low, high, result = []) {
  if (node === null) {
    return result;
  }

  // В левом поддереве все ключи меньше node.key: спускаться туда
  // имеет смысл, только если там могут быть ключи не меньше low
  if (node.key > low) {
    findInRange(node.left, low, high, result);
  }

  if (node.key >= low && node.key <= high) {
    result.push(node.key);
  }

  if (node.key < high) {
    findInRange(node.right, low, high, result);
  }

  return result;
}
```

#### Разбор сложности

Оценка `O(h + k)` складывается из двух частей:

- **`O(h)`** - спуск до границ интервала. Путей, частично попадающих в
  интервал, всего два: к левой границе и к правой, каждый длины `h`.
- **`O(k)`** - все вершины, целиком лежащие внутри интервала; их ровно `k`,
  и каждая посещается один раз.

Это существенно лучше `O(n)`, когда интервал узкий. Если же в интервал попадает
все дерево, `k = n`, и выигрыша нет - но и хуже не становится.

Отсечение - то же самое, что и в
[переборе с возвратом](../sprint-3/recursion.md#отсечение): не строить ветви,
про которые заранее известно, что они ничего не дадут.

### Обход без рекурсии

Рекурсивный обход расходует `O(h)` стека и на вырожденном дереве с `n = 10⁵`
переполнит его. Рекурсию заменяет
[явный стек](../sprint-2/stack-and-queue.md#23-стек):

```js
/**
 * Возвращает ключи дерева в центрированном порядке LMR без рекурсии.
 *
 * Стек хранит вершины, к которым предстоит вернуться после обработки их левых
 * поддеревьев, - ровно те кадры, которые создавала бы рекурсия.
 *
 * Время: O(n). Память: O(h).
 *
 * @param {Node|null} root Корень дерева.
 * @returns {number[]} Ключи в порядке возрастания.
 */
function inorderIterative(root) {
  const result = [];
  const stack = [];
  let node = root;

  while (node !== null || stack.length > 0) {
    // Спускаемся влево до упора, запоминая путь
    while (node !== null) {
      stack.push(node);
      node = node.left;
    }

    node = stack.pop();
    result.push(node.key);
    node = node.right;
  }

  return result;
}
```
