## 5.4 Сбалансированные деревья поиска

Все операции дерева поиска стоят `O(h)`. Значит, вся польза от структуры
определяется тем, насколько мала высота.

Нижняя граница очевидна: бинарное дерево высоты `h` вмещает не более `2ʰ − 1`
вершин, откуда для `n` вершин

```
h ≥ ⌈log₂(n + 1)⌉
```

Дерево называется **сбалансированным**, если его высота есть `O(log n)`, то
есть с точностью до константы совпадает с этим минимумом. Тогда операции
выполняются за `O(log n)`.

Проблема в том, что высота зависит от порядка вставки, и
[отсортированный вход вырождает дерево в список](bst.md#стоимость-операций).
Сбалансированное дерево поиска - это дерево, которое **само** восстанавливает
малую высоту после каждой модификации.

---

### 5.4.1 Критерии сбалансированности дерева

Что именно требовать от дерева? Есть два разумных критерия, и они дают
принципиально разный результат.

#### 5.4.1.1 Критерий по количеству вершин

**Требование:** у любой вершины количество потомков в левом и правом поддеревьях
различается не более чем на единицу.

Такое дерево называется **идеально сбалансированным**. Оно дает минимально
возможную высоту, но поддерживать его слишком дорого.

Причина в том, что почти любая вставка ломает критерий и требует глобальной
перестройки. Рассмотрим дерево:

```
              (12)
             /    \
          (8)      (14)
         /   \
      (6)   (10)
```

Свободных мест для вставки семь, но идеальную сбалансированность сохранит
только одно - левый ребенок вершины `14`. И ключ туда подходит не любой: он
должен быть меньше `14` (левое поддерево) и больше `12` (правое поддерево
корня), то есть строго `13`.

Вставка **любого другого ключа** нарушит критерий и потребует перестройки,
которая может затронуть все дерево, то есть стоить `O(n)`. Ради `O(log n)` на
поиск платить `O(n)` за вставку бессмысленно.

#### 5.4.1.2 Критерий по высоте дерева

**Требование:** у любой вершины высоты левого и правого поддеревьев различаются
не более чем на единицу.

Это ослабленный критерий, и в этом вся суть: он допускает гораздо больше форм
дерева, поэтому восстанавливается локально, за `O(log n)`, а не глобальной
перестройкой.

Дерево, удовлетворяющее этому критерию, называется **АВЛ-деревом** - по
фамилиям Адельсона-Вельского и Ландиса.

Величина

```
balanceFactor(v) = height(v.left) − height(v.right)
```

называется **балансовым множителем**. Критерий АВЛ: `|balanceFactor(v)| ≤ 1`
для каждой вершины.

Ослабление стоит недорого. Можно доказать, что высота АВЛ-дерева из `n` вершин
не превышает примерно `1,44 · log₂(n + 2)`, то есть отличается от идеальной
меньше чем в полтора раза. За это дерево платит лишь одним дополнительным полем
в вершине.

```js
class Node {
  /**
   * @param {number} key Ключ узла.
   * @param {Node|null} left Левый потомок.
   * @param {Node|null} right Правый потомок.
   */
  constructor(key, left = null, right = null) {
    this.key = key;
    this.left = left;
    this.right = right;
    // Высота поддерева в вершинах: у листа она равна 1
    this.height = 1;
  }
}
```

Высота хранится в вершине, а не вычисляется: вычисление стоило бы `O(n)` на
каждую проверку и обесценило бы всю конструкцию.

### 5.4.2 Балансировка АВЛ-дерева

После вставки или удаления высоты меняются, и у какой-то вершины балансовый
множитель может стать равным `±2`. Такое поддерево нужно перестроить -
**повернуть**.

Вращение меняет форму поддерева, сохраняя порядок ключей. Всего требуется
четыре вращения: два малых и два больших, симметричных друг другу.

Вспомогательные функции, используемые всеми вращениями:

```js
/**
 * Возвращает высоту поддерева, корректно обрабатывая пустое.
 *
 * Отдельная функция вместо обращения к node.height обязательна: у пустого
 * поддерева нет объекта, а его высота равна нулю.
 *
 * Время: O(1).
 *
 * @param {Node|null} node Корень поддерева.
 * @returns {number} Высота в вершинах, 0 для пустого поддерева.
 */
function height(node) {
  return node === null ? 0 : node.height;
}

/**
 * Пересчитывает высоту вершины по высотам ее детей.
 *
 * Время: O(1).
 *
 * @param {Node} node Вершина, высота которой устарела.
 * @returns {void}
 */
function updateHeight(node) {
  node.height = 1 + Math.max(height(node.left), height(node.right));
}

/**
 * Возвращает балансовый множитель вершины.
 *
 * Положительное значение означает перевес влево, отрицательное - вправо.
 *
 * Время: O(1).
 *
 * @param {Node} node Вершина.
 * @returns {number} Разность высот левого и правого поддеревьев.
 */
function balanceFactor(node) {
  return height(node.left) - height(node.right);
}
```

> **О пересчете высот.** Высоты можно корректировать приращениями, зная, какие
> именно поддеревья поменялись местами, - так делается ради экономии. Но правила
> приращений различны для каждого вращения и для каждого соотношения высот, и
> ошибиться в них легко. Пересчет по формуле `1 + max(высоты детей)` стоит те же
> `O(1)`, работает одинаково во всех случаях и не ломается на пустых
> поддеревьях. Дальше используется только он.

---

#### 5.4.2.1 Малое левое вращение

**Когда применяется:** правое поддерево выше левого на 2, и при этом у правого
ребенка **правое** поддерево не ниже левого. То есть перевес идет «прямой
линией» вправо-вправо.

```
        (a)                                  (b)
       /   \                                /   \
     [L]   (b)          ──────►          (a)     [R]
          /   \                         /   \
        [C]   [R]                     [L]   [C]

   h(b) − h(L) = 2                 корнем стала b
   h(C) ≤ h(R)                     a ушла в левые дети
```

Порядок ключей сохраняется: было `L < a < C < b < R`, стало `L < a < C < b < R`.
Поддерево `C` переезжает от `b` к `a`, потому что его ключи больше `a`, но
меньше `b`.

```js
/**
 * Выполняет малое левое вращение и возвращает новый корень поддерева.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} a Корень перебалансируемого поддерева.
 * @returns {Node} Новый корень поддерева.
 */
function rotateLeft(a) {
  const b = a.right;

  a.right = b.left;
  b.left = a;

  // Порядок важен: высота a должна быть пересчитана раньше,
  // потому что a стала ребенком b
  updateHeight(a);
  updateHeight(b);

  return b;
}
```

---

#### 5.4.2.2 Малое правое вращение

Зеркальный случай: левое поддерево выше правого на 2, и у левого ребенка
**левое** поддерево не ниже правого - перевес «влево-влево».

```
          (a)                                (b)
         /   \                              /   \
      (b)    [R]         ──────►         [L]     (a)
     /   \                                      /   \
   [L]   [C]                                  [C]   [R]
```

```js
/**
 * Выполняет малое правое вращение и возвращает новый корень поддерева.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} a Корень перебалансируемого поддерева.
 * @returns {Node} Новый корень поддерева.
 */
function rotateRight(a) {
  const b = a.left;

  a.left = b.right;
  b.right = a;

  updateHeight(a);
  updateHeight(b);

  return b;
}
```

---

#### 5.4.2.3 Большое левое вращение

**Когда применяется:** правое поддерево выше на 2, но у правого ребенка выше
**левое** поддерево. Перевес идет «зигзагом» вправо-влево.

Малое левое вращение здесь не поможет: оно просто перенесет перекос на другую
сторону. Нужно сначала выпрямить зигзаг.

```
        (a)                                    (c)
       /   \                                 /     \
     [L]   (b)                            (a)       (b)
          /   \          ──────►         /   \     /   \
        (c)   [R]                      [L]  [M]  [N]   [R]
       /   \
     [M]   [N]

   h(b) − h(L) = 2
   h(c) > h(R)
```

Корнем становится `c` - вершина, лежавшая «в середине» зигзага. Ее поддеревья
`M` и `N` расходятся: `M` уходит к `a` (ключи больше `a`, меньше `c`), `N` -
к `b` (ключи больше `c`, меньше `b`).

Большое вращение - это **композиция двух малых**:

```js
/**
 * Выполняет большое левое вращение и возвращает новый корень поддерева.
 *
 * Реализуется как малое правое вращение правого поддерева, выпрямляющее зигзаг,
 * с последующим малым левым вращением всего поддерева.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} a Корень перебалансируемого поддерева.
 * @returns {Node} Новый корень поддерева.
 */
function bigRotateLeft(a) {
  a.right = rotateRight(a.right);

  return rotateLeft(a);
}
```

Первое вращение превращает зигзаг `вправо-влево` в прямую линию
`вправо-вправо`, после чего работает обычное малое левое вращение. Записывать
большое вращение отдельной функцией с явным переприсваиванием шести ссылок тоже
можно, но композиция короче и не требует отдельного разбора корректности.

---

#### 5.4.2.4 Большое правое вращение

Зеркальный случай: левое поддерево выше на 2, но у левого ребенка выше
**правое** поддерево - зигзаг влево-вправо.

```
          (a)                                  (c)
         /   \                               /     \
      (b)    [R]                          (b)       (a)
     /   \             ──────►           /   \     /   \
   [L]   (c)                           [L]  [M]  [N]   [R]
        /   \
      [M]   [N]
```

```js
/**
 * Выполняет большое правое вращение и возвращает новый корень поддерева.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} a Корень перебалансируемого поддерева.
 * @returns {Node} Новый корень поддерева.
 */
function bigRotateRight(a) {
  a.left = rotateLeft(a.left);

  return rotateRight(a);
}
```

#### 5.4.2.5 Дерево решений

Какое вращение применить, определяется двумя балансовыми множителями: самой
вершины и того ее ребенка, в сторону которого перевес.

```
                 balanceFactor(v)
                        │
        ┌───────────────┼───────────────┐
      = −2            |·| ≤ 1          = +2
   (перевес вправо)  сбалансировано  (перевес влево)
        │                                │
   balanceFactor(v.right)          balanceFactor(v.left)
        │                                │
   ┌────┴────┐                      ┌────┴────┐
  ≤ 0       > 0                    ≥ 0       < 0
малое      большое                малое     большое
левое      левое                  правое    правое
```

```js
/**
 * Восстанавливает балансировку вершины и возвращает новый корень поддерева.
 *
 * Высота вершины пересчитывается до проверки: балансовый множитель считается
 * по актуальным высотам детей, которые уже сбалансированы рекурсией.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} node Вершина, у которой могла нарушиться балансировка.
 * @returns {Node} Корень сбалансированного поддерева.
 */
function balance(node) {
  updateHeight(node);

  const factor = balanceFactor(node);

  if (factor === -2) {
    // Перевес вправо: зигзаг требует большого вращения, прямая линия - малого
    return balanceFactor(node.right) > 0
      ? bigRotateLeft(node)
      : rotateLeft(node);
  }

  if (factor === 2) {
    return balanceFactor(node.left) < 0
      ? bigRotateRight(node)
      : rotateRight(node);
  }

  return node;
}
```

Обратите внимание на строгость сравнений: при `balanceFactor(node.right) === 0`
поддеревья правого ребенка равны по высоте, и достаточно малого вращения.
Большое понадобилось бы только при строгом перевесе в противоположную сторону.

#### Вставка и удаление

Балансировка встраивается в уже знакомые
[вставку](bst.md#521-вставка-элемента) и
[удаление](bst.md#522-удаление-элемента) одной строкой: на обратном ходу
рекурсии каждая вершина пути балансируется.

```js
/**
 * Вставляет ключ в АВЛ-дерево и возвращает корень сбалансированного дерева.
 *
 * Балансировка выполняется на обратном ходу рекурсии для каждой вершины пути
 * вставки - снизу вверх, поэтому к моменту балансировки вершины ее поддеревья
 * уже сбалансированы.
 *
 * Время: O(log n). Память: O(log n) на кадры стека вызовов.
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} key Вставляемый ключ.
 * @returns {Node} Корень поддерева после вставки.
 */
function insert(node, key) {
  if (node === null) {
    return new Node(key);
  }

  if (key < node.key) {
    node.left = insert(node.left, key);
  } else if (key > node.key) {
    node.right = insert(node.right, key);
  } else {
    // Ключ уже есть: дерево не меняется
    return node;
  }

  return balance(node);
}

/**
 * Удаляет ключ из АВЛ-дерева и возвращает корень сбалансированного дерева.
 *
 * Время: O(log n). Память: O(log n).
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} key Удаляемый ключ.
 * @returns {Node|null} Корень поддерева после удаления.
 */
function remove(node, key) {
  if (node === null) {
    return null;
  }

  if (key < node.key) {
    node.left = remove(node.left, key);
  } else if (key > node.key) {
    node.right = remove(node.right, key);
  } else {
    if (node.left === null) {
      return node.right;
    }

    if (node.right === null) {
      return node.left;
    }

    const successor = findMin(node.right);

    successor.right = removeMin(node.right);
    successor.left = node.left;

    return balance(successor);
  }

  return balance(node);
}

/**
 * Возвращает вершину с наименьшим ключом поддерева.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {Node} node Корень непустого поддерева.
 * @returns {Node} Самая левая вершина.
 */
function findMin(node) {
  let current = node;

  while (current.left !== null) {
    current = current.left;
  }

  return current;
}

/**
 * Удаляет из поддерева вершину с наименьшим ключом, сохраняя балансировку.
 *
 * Время: O(log n). Память: O(log n).
 *
 * @param {Node} node Корень непустого поддерева.
 * @returns {Node|null} Корень поддерева после удаления минимума.
 */
function removeMin(node) {
  if (node.left === null) {
    return node.right;
  }

  node.left = removeMin(node.left);

  return balance(node);
}
```

Существенное отличие от обычного BST - **один вызов `balance` при вставке
достаточен**: после вставки высота дерева могла вырасти не более чем на
единицу, и одно вращение ее восстанавливает. При удалении так не получается:
вращение может уменьшить высоту поддерева, и балансировать приходится всю
цепочку до корня. Именно поэтому `balance` вызывается на каждом уровне
возврата.

#### 5.4.2.6 Повторяющиеся ключи

Если договориться, что в левом поддереве ключи **строго меньше**, а в правом
**строго больше**, то дерево из одинаковых ключей построить невозможно: все они
обязаны быть одной вершиной.

Если же разрешить равные ключи только в одну сторону (скажем, `>=` вправо), то
дерево из `n` одинаковых ключей выродится в цепочку вправо - и вращения его не
спасут, потому что ключи нельзя переставить, не нарушив соглашение.

Отсюда три рабочих решения:

1. **Запретить дубликаты.** Повторная вставка ничего не делает. Простейший
   вариант, и именно он используется в задачах курса.
2. **Хранить счетчик в вершине.** Вершина хранит ключ и количество его
   повторений. Дерево остается сбалансированным, память тратится экономно.
3. **Разрешить равные ключи в обоих поддеревьях.** Вставка направляет
   дубликат в более низкое поддерево, что сохраняет балансировку. Плата
   существенна: поиск больше не может отбросить половину при совпадении ключа
   и обязан спускаться в **оба** поддерева, а значит, перестает быть `O(log n)`
   и становится `O(log n + k)`, где `k` - число вхождений.

Второй вариант почти всегда лучше третьего: он дает те же возможности дешевле.
