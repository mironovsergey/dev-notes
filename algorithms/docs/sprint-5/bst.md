## 5.2 Бинарные деревья поиска

Обычное бинарное дерево не помогает искать: чтобы найти значение, приходится
обойти все вершины за `O(n)`. **Бинарное дерево поиска** (binary search tree,
BST) добавляет к структуре порядок, который позволяет на каждом шаге
отбрасывать целое поддерево.

### Свойство дерева поиска

Дерево является деревом поиска, если для **каждой** вершины со значением `X`:

- все ключи левого поддерева меньше `X`;
- все ключи правого поддерева больше `X`;
- оба поддерева сами являются деревьями поиска.

```
                  (8)
                 /   \
        все < 8 /     \ все > 8
              (3)     (10)
             /   \       \
          (1)    (6)     (14)
```

Условие должно выполняться **для всего поддерева, а не только для детей**. Это
типичная ошибка: дерево, где каждая вершина больше левого ребенка и меньше
правого, деревом поиска быть не обязано.

```
        (8)
       /   \
    (3)     (10)
   /   \
 (1)   (9)     ← 9 > 8, но лежит в левом поддереве восьмерки
```

Проверка «каждый ребенок в правильную сторону» здесь пройдет, а дерево поиска
сломано: поиск ключа `9` уйдет вправо от корня и девятку не найдет.

### Повторяющиеся ключи

Определение выше запрещает дубликаты. Если они нужны, договариваются об одном
из вариантов:

- дубликаты не хранятся вовсе - повторная вставка игнорируется;
- равные ключи идут в правое поддерево (`<` влево, `>=` вправо);
- в вершине хранится счетчик повторов.

**Здесь и далее** используется первый вариант - ключи уникальны. Он проще
всего, и именно его требуют задачи курса. Тонкости, возникающие при дубликатах
в сбалансированном дереве, разбираются
[отдельно](balanced.md#5426-повторяющиеся-ключи).

### Поиск

Сравниваем ключ с вершиной и спускаемся в ту сторону, где он может находиться.
Вторая половина отбрасывается целиком.

```js
/**
 * Ищет узел с заданным ключом в дереве поиска.
 *
 * Время: O(h), где h - высота дерева. Память: O(1).
 *
 * @param {Node|null} root Корень дерева.
 * @param {number} key Искомый ключ.
 * @returns {Node|null} Найденный узел либо null.
 */
function findNode(root, key) {
  let node = root;

  while (node !== null && node.key !== key) {
    node = key < node.key ? node.left : node.right;
  }

  return node;
}
```

Итеративная запись предпочтительнее рекурсивной: рекурсия здесь хвостовая, а
[JavaScript ее не оптимизирует](../sprint-3/recursion.md#хвостовая-рекурсия-и-почему-на-практике-пишут-цикл),
так что рекурсивный вариант впустую расходует `O(h)` стека.

### Минимум и максимум

Минимум - самая левая вершина, максимум - самая правая.

```js
/**
 * Возвращает узел с наименьшим ключом поддерева.
 *
 * Время: O(h). Память: O(1).
 *
 * @param {Node} node Корень непустого поддерева.
 * @returns {Node} Самый левый узел.
 */
function findMin(node) {
  let current = node;

  while (current.left !== null) {
    current = current.left;
  }

  return current;
}
```

### Стоимость операций

Все операции дерева поиска стоят `O(h)`, где `h` - высота. А высота зависит от
порядка вставки:

```
Вставка 1, 2, 3, 4, 5      Вставка 3, 2, 4, 1, 5
по возрастанию:            вперемешку:

  (1)                            (3)
     \                          /   \
     (2)                     (2)     (4)
        \                    /          \
        (3)               (1)           (5)
           \
           (4)            h = 3, поиск за 3 сравнения
              \
              (5)

  h = 5, вырождение в список
```

При вставке отсортированных данных дерево превращается в связный список, и все
операции деградируют до `O(n)`. Обиднее всего, что отсортированный вход - самый
частый на практике. Отсюда необходимость
[балансировки](balanced.md#54-сбалансированные-деревья-поиска).

### 5.2.1 Вставка элемента

Спускаемся по дереву так же, как при поиске, пока не упремся в отсутствующее
поддерево. Там и создаем вершину.

Ключ вставляется **ровно туда, где его стал бы искать поиск** - иначе
последующий поиск его не найдет.

```
Вставляем 39 в дерево:

        (35)                    (35)
       /    \                  /    \
    (20)    (42)     →      (20)    (42)
            /                       /
         (37)                    (37)
                                     \
                                     (39)   ← новая вершина

35 < 39 → вправо;  42 > 39 → влево;  37 < 39 → вправо, места нет
```

```js
/**
 * Вставляет ключ в дерево поиска и возвращает корень измененного дерева.
 *
 * Повторный ключ не вставляется: дерево хранит уникальные ключи.
 *
 * Время: O(h). Память: O(h) на кадры стека вызовов.
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} key Вставляемый ключ.
 * @returns {Node} Корень поддерева после вставки.
 */
function insert(node, key) {
  if (node === null) {
    return new Node(key);
  }

  if (key < node.key) {
    node.left = insert(node.left, key);
  } else if (key > node.key) {
    node.right = insert(node.right, key);
  }

  return node;
}
```

Прием с возвратом корня - стандартный для рекурсивной работы с деревьями:
вызывающая сторона просто присваивает результат обратно в поле ребенка. Это
избавляет от отдельной обработки случая «вставка изменила корень» и от хранения
ссылок на родителей.

### 5.2.2 Удаление элемента

Самая сложная из трех операций. При удалении вершины все входящие и исходящие
из нее ребра становятся недействительными, и дерево может распасться на части.

Разбирается три случая по числу детей удаляемой вершины.

#### Случай 1: нет детей

Лист просто отсоединяется - распадаться нечему.

```
      (5)              (5)
     /   \      →     /
  (3)    (8)       (3)
```

#### Случай 2: один ребенок

Единственное поддерево занимает место удаленной вершины. Свойство дерева поиска
сохраняется: все ключи поддерева уже лежали по нужную сторону от родителя.

```
      (5)              (5)
     /   \      →     /   \
  (3)    (8)       (3)    (6)
         /
      (6)
```

#### Случай 3: два ребенка

Здесь и возникает распад: удаляем вершину - остаются два осиротевших поддерева.
На ее место нужно поставить вершину, которая сохранит порядок, то есть такую,
чей ключ:

- больше всех ключей левого поддерева,
- меньше всех ключей правого.

Таких вершин ровно две:

- **максимум левого поддерева** - самая правая вершина слева (предшественник);
- **минимум правого поддерева** - самая левая вершина справа (преемник).

```
Удаляем 12. Подойдут 11 или 13:

           (12)                    (11)                (13)
          /    \                  /    \              /    \
       (7)     (15)     →      (7)     (15)   или  (7)     (15)
      /   \    /   \          /   \    /   \      /   \       \
   (5)  (11) (13) (20)     (5)   ·  (13) (20)  (5)  (11)     (20)
```

Ключевое наблюдение: **у выбранной замены не может быть двух детей**. Минимум
правого поддерева - самая левая вершина, значит, левого ребенка у нее нет.
Поэтому ее собственное удаление сводится к случаю 1 или 2, и рекурсия не
углубляется дальше.

```js
/**
 * Удаляет ключ из дерева поиска и возвращает корень измененного дерева.
 *
 * Вершина с двумя детьми заменяется преемником - минимумом правого поддерева.
 * У преемника заведомо нет левого ребенка, поэтому его удаление сводится
 * к простому случаю и рекурсия не углубляется.
 *
 * Время: O(h). Память: O(h) на кадры стека вызовов.
 *
 * @param {Node|null} node Корень поддерева.
 * @param {number} key Удаляемый ключ.
 * @returns {Node|null} Корень поддерева после удаления.
 */
function remove(node, key) {
  if (node === null) {
    return null;
  }

  if (key < node.key) {
    node.left = remove(node.left, key);
    return node;
  }

  if (key > node.key) {
    node.right = remove(node.right, key);
    return node;
  }

  // Ключ найден: случаи 1 и 2 обрабатываются одинаково -
  // на место вершины встает единственное поддерево либо null
  if (node.left === null) {
    return node.right;
  }

  if (node.right === null) {
    return node.left;
  }

  // Случай 3: заменяем вершину преемником
  const successor = findMin(node.right);

  successor.right = removeMin(node.right);
  successor.left = node.left;

  return successor;
}

/**
 * Удаляет из поддерева вершину с наименьшим ключом.
 *
 * Время: O(h). Память: O(h) на кадры стека вызовов.
 *
 * @param {Node} node Корень непустого поддерева.
 * @returns {Node|null} Корень поддерева после удаления минимума.
 */
function removeMin(node) {
  if (node.left === null) {
    return node.right;
  }

  node.left = removeMin(node.left);

  return node;
}
```

#### Перенос значения вместо перестройки ссылок

Существует более короткий вариант случая 3: скопировать ключ преемника в
удаляемую вершину и рекурсивно удалить преемника из правого поддерева.

```js
// Короче, но удаляет не тот объект
const successorKey = findMin(node.right).key;

node.key = successorKey;
node.right = remove(node.right, successorKey);

return node;
```

Он проще, но **физически удаляет другую вершину**: объект, на который указывал
`node`, остается в дереве с чужим ключом. Если вершины хранят что-то помимо
ключа или на них есть внешние ссылки, такая подмена приведет к ошибке. Задачи
курса требуют именно перестройки ссылок, а не переноса значений.
