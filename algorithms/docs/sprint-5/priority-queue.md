## 5.5 Приоритетная очередь

**Приоритетная очередь** - структура данных, хранящая элементы с приоритетами и
позволяющая быстро извлекать наиболее приоритетный.

В отличие от [обычной очереди](../sprint-2/stack-and-queue.md#24-очередь-и-дек),
порядок извлечения определяется не временем поступления, а приоритетом.

| Операция | Смысл | Сложность |
| --- | --- | --- |
| `push(value)` | Добавить элемент | `O(log n)` |
| `popMax()` | Извлечь наиболее приоритетный | `O(log n)` |
| `peekMax()` | Посмотреть наиболее приоритетный | `O(1)` |
| `size()` | Количество элементов | `O(1)` |

Почему не подходят уже известные структуры:

| Реализация | `push` | `popMax` |
| --- | --- | --- |
| Неупорядоченный массив | `O(1)` | `O(n)` - поиск максимума |
| Упорядоченный массив | `O(n)` - вставка со сдвигом | `O(1)` |
| Дерево поиска | `O(log n)` | `O(log n)`, но требует балансировки |
| **Двоичная куча** | `O(log n)` | `O(log n)` |

Дерево поиска справилось бы, но оно избыточно: оно поддерживает **полный**
порядок, тогда как для очереди нужно знать лишь максимум. Куча поддерживает
более слабое условие и потому проще, компактнее и быстрее по константе.

---

### 5.5.1 Дерево на массиве

Вершины дерева обычно разбросаны по памяти и связаны ссылками. Но
[почти полное](binary-trees.md#полные-и-почти-полные-деревья) бинарное дерево
можно хранить в массиве, вычисляя связи арифметически.

Договоренность (индексация с единицы):

```
индекс родителя вершины i  =  ⌊i / 2⌋
индекс левого потомка i    =  2i
индекс правого потомка i   =  2i + 1
```

```
             (3)₁
            /    \
        (5)₂      (1)₃
       /    \     /
   (6)₄   (9)₅ (2)₆

массив:  [ · ,  3 ,  5 ,  1 ,  6 ,  9 ,  2 ]
индекс:    0    1    2    3    4    5    6
```

Нулевая ячейка не используется - она фиктивная. Ценой одной потерянной ячейки
формулы получаются простыми; при индексации с нуля они принимают вид
`2i + 1`, `2i + 2` и `⌊(i − 1) / 2⌋`, что читается хуже.

**Достоинства:**

- не хранятся ссылки - экономия памяти и отсутствие выделений под узлы;
- переход между вершинами - арифметика вместо разыменования указателя;
- элементы лежат подряд, что хорошо согласуется с кэшем процессора.

**Ограничения:**

- подходит только для бинарных деревьев;
- при сильной несбалансированности массив заполняется дырами. Дерево-цепочка
  высоты `h` потребовало бы массива на `2ʰ` ячеек ради `h` элементов.

Поэтому представление массивом применяют именно там, где дерево гарантированно
почти полное, - то есть для кучи.

---

### 5.5.2 Очередь с приоритетом

**Двоичная куча** (пирамида) - почти полное бинарное дерево, удовлетворяющее
**свойству кучи**: ключ в любой вершине не менее приоритетен, чем ключи ее
детей.

Куча на максимум (max-heap) держит в корне максимум, куча на минимум (min-heap)
- минимум.

```
max-heap:                min-heap:

        (50)                    (3)
       /    \                  /   \
    (30)    (20)            (5)     (8)
   /    \                  /   \
 (15)   (10)            (17)   (45)
```

Два условия, и оба обязательны:

1. **Свойство кучи** - родитель приоритетнее детей. Гарантирует, что в корне
   лежит наиболее приоритетный элемент.
2. **Почти полнота** - все уровни, кроме последнего, заполнены полностью,
   последний заполняется слева направо. Гарантирует, что высота равна
   `⌊log₂ n⌋ + 1`, и что массив заполнен плотно от начала до конца.

Свойство кучи **слабее** свойства дерева поиска: оно упорядочивает только пары
«родитель - ребенок» и ничего не говорит про соседей. Поэтому массив,
представляющий кучу, **не отсортирован** - куча не дает быстрого поиска
произвольного элемента, только максимума.

```
Куча [·, 50, 30, 20, 15, 10] - корректная, но массив не отсортирован
```

Восстановление свойства кучи после изменения выполняется двумя операциями:
**просеиванием вверх** и **просеиванием вниз**.

---

#### 5.5.2.1 Вставка элемента

Новый элемент дописывается в конец массива - единственное место, где почти
полнота не нарушается. Свойство кучи при этом может нарушиться, и элемент
**просеивается вверх**: пока он приоритетнее родителя, они меняются местами.

```
Вставляем 60 в кучу [·, 50, 30, 20, 15, 10]:

        (50)                (50)                (60)
       /    \              /    \              /    \
    (30)    (20)   →    (60)    (20)   →    (50)    (20)
   /   \   /           /   \   /           /   \   /
 (15) (10) (60)     (15) (10) (30)      (15) (10) (30)

  60 > 30, меняем      60 > 50, меняем     корень достигнут
```

```js
/**
 * Просеивает элемент вверх до восстановления свойства кучи.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {number[]} heap Куча с фиктивным нулевым элементом.
 * @param {number} index Индекс просеиваемого элемента.
 * @returns {number} Индекс, на котором элемент остановился.
 */
function siftUp(heap, index) {
  let current = index;

  while (current > 1) {
    const parent = Math.floor(current / 2);

    if (heap[parent] >= heap[current]) {
      break;
    }

    [heap[parent], heap[current]] = [heap[current], heap[parent]];
    current = parent;
  }

  return current;
}

/**
 * Добавляет элемент в кучу.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {number[]} heap Куча с фиктивным нулевым элементом.
 * @param {number} value Добавляемое значение.
 * @returns {number} Индекс добавленного элемента после просеивания.
 */
function heapAdd(heap, value) {
  heap.push(value);

  return siftUp(heap, heap.length - 1);
}
```

На каждом уровне выполняется одно сравнение, а высота кучи - `⌊log₂ n⌋ + 1`,
поэтому вставка стоит `O(log n)`.

---

#### 5.5.2.2 Удаление элемента

Извлекается всегда корень. Чтобы не образовалась дыра, на его место ставится
**последний** элемент массива, после чего он **просеивается вниз**: пока он
менее приоритетен, чем кто-то из детей, он меняется местами с наиболее
приоритетным из них.

Выбор наиболее приоритетного ребенка обязателен. Обмен с менее приоритетным
поставил бы того выше своего брата и нарушил свойство кучи заново.

```
Извлекаем 50 из кучи [·, 50, 45, 20, 17, 14]:

        (50)                (14)                (45)                (45)
       /    \              /    \              /    \              /    \
    (45)    (20)   →    (45)    (20)   →    (14)    (20)   →    (17)    (20)
   /   \               /                   /                   /
 (17)  (14)         (17)                (17)                (14)

 корень уходит   последний наверх   14 < 45, меняем   14 < 17, меняем
```

```js
/**
 * Просеивает элемент вниз до восстановления свойства кучи.
 *
 * Обмен выполняется с наиболее приоритетным из детей: обмен с менее
 * приоритетным поставил бы его выше собственного брата и нарушил бы свойство
 * кучи заново.
 *
 * Время: O(log n). Память: O(1).
 *
 * Граница size задается явно, а не берется из длины массива: пирамидальной
 * сортировке нужно просеивать по префиксу массива, оставляя отсортированный
 * хвост нетронутым.
 *
 * @param {number[]} heap Куча с фиктивным нулевым элементом.
 * @param {number} index Индекс просеиваемого элемента.
 * @param {number} size Количество элементов кучи, то есть индекс последнего.
 * @returns {number} Индекс, на котором элемент остановился.
 */
function siftDown(heap, index, size = heap.length - 1) {
  let current = index;

  for (;;) {
    const left = 2 * current;
    const right = 2 * current + 1;
    let largest = current;

    if (left <= size && heap[left] > heap[largest]) {
      largest = left;
    }

    if (right <= size && heap[right] > heap[largest]) {
      largest = right;
    }

    if (largest === current) {
      return current;
    }

    [heap[current], heap[largest]] = [heap[largest], heap[current]];
    current = largest;
  }
}

/**
 * Извлекает наиболее приоритетный элемент кучи.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {number[]} heap Куча с фиктивным нулевым элементом.
 * @returns {number|null} Максимум либо null, если куча пуста.
 */
function popMax(heap) {
  if (heap.length <= 1) {
    return null;
  }

  const max = heap[1];
  const last = heap.pop();

  // Проверка нужна для кучи из одного элемента: он уже извлечен,
  // возвращать его на место нельзя
  if (heap.length > 1) {
    heap[1] = last;
    siftDown(heap, 1);
  }

  return max;
}
```

Просеивание вниз выполняет **два** сравнения на уровень против одного при
просеивании вверх - отсюда вдвое большая константа, хотя асимптотика та же
`O(log n)`.

Условия остановки просеивания вниз:

1. текущий элемент приоритетнее обоих детей;
2. у текущего элемента нет детей, то есть `2 · current > size`.
