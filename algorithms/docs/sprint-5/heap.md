## 5.6 Куча

Двоичная куча описана в предыдущем разделе как реализация
[приоритетной очереди](priority-queue.md#552-очередь-с-приоритетом). Здесь
разбираются два оставшихся вопроса: как построить кучу из готового массива и
как превратить ее в алгоритм сортировки.

### Построение кучи из массива

Прямолинейный способ - добавить элементы по одному:

```js
const heap = [null];

for (const value of array) {
  heapAdd(heap, value);
}
```

Это `n` вставок по `O(log n)`, итого `O(n log n)`.

Существует способ лучше - **алгоритм Флойда**. Массив объявляется кучей как
есть, после чего просеиваются вниз все вершины, у которых есть дети, в порядке
**от последней к первой**.

```js
/**
 * Превращает массив в кучу на максимум на месте.
 *
 * Листья просеивать не нужно: поддерево из одной вершины уже является кучей.
 * Последняя вершина, имеющая детей, - это родитель последнего элемента,
 * то есть ⌊(n) / 2⌋ при индексации с единицы.
 *
 * Обход идет от последней такой вершины к первой, поэтому к моменту
 * просеивания вершины оба ее поддерева уже являются корректными кучами -
 * ровно то, что требует siftDown.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number[]} heap Массив с фиктивным нулевым элементом.
 * @returns {number[]} Тот же массив, упорядоченный как куча.
 */
function buildHeap(heap) {
  const size = heap.length - 1;

  for (let i = Math.floor(size / 2); i >= 1; i--) {
    siftDown(heap, i, size);
  }

  return heap;
}
```

#### Почему это `O(n)`, а не `O(n log n)`

Оценка «`n / 2` просеиваний по `O(log n)`» верна, но груба. Стоимость
просеивания вершины ограничена не высотой **дерева**, а высотой ее собственного
поддерева, и почти все вершины лежат близко ко дну.

На высоте `h` находится не более `⌈n / 2ʰ⌉` вершин, и каждая требует `O(h)`
работы. Суммарно

```
∑ (n / 2ʰ) · h  =  n · ∑ h / 2ʰ  ≤  n · 2  =  O(n)
```

потому что ряд `∑ h / 2ʰ` сходится к 2. Половина вершин - листья, требующие
нулевой работы; лишь одна вершина, корень, требует полных `log n` шагов.

### 5.6.1 Пирамидальная сортировка

**Пирамидальная сортировка** (heapsort) использует кучу как механизм выбора
очередного элемента: пока куча не пуста, извлекаем максимум и помещаем его в
конец результата.

#### Прямолинейная версия

```js
/**
 * Сортирует массив пирамидальной сортировкой по возрастанию.
 *
 * Куча на максимум отдает элементы по убыванию, поэтому результат
 * разворачивается. Альтернатива - построить кучу на минимум.
 *
 * Время: O(n log n). Память: O(n) на кучу и результат.
 *
 * @param {number[]} array Исходный массив; не изменяется.
 * @returns {number[]} Новый отсортированный массив.
 */
function heapsortSimple(array) {
  const heap = [null, ...array];
  const result = new Array(array.length);

  buildHeap(heap);

  for (let i = array.length - 1; i >= 0; i--) {
    result[i] = popMax(heap);
  }

  return result;
}
```

Заполнение результата **с конца** существенно: куча на максимум извлекает
элементы по убыванию, а требуется возрастание. Если заполнять с начала,
получится массив, отсортированный по убыванию, - расхождение между кучей на
максимум и заявленным порядком сортировки является типичной ошибкой.

#### Версия на месте

`O(n)` дополнительной памяти не нужны. Извлеченный максимум можно класть в ту
самую ячейку, которая освобождается при сокращении кучи, - в ее конец.

```
[ куча (не отсортировано) | отсортированный хвост ]
                          ↑
                    граница сдвигается влево
```

```js
/**
 * Сортирует массив пирамидальной сортировкой по возрастанию, на месте.
 *
 * Массив делится на префикс-кучу и отсортированный суффикс. На каждом шаге
 * максимум кучи меняется местами с ее последним элементом, граница сдвигается
 * влево, и новый корень просеивается вниз.
 *
 * Время: O(n log n) во всех случаях. Память: O(1).
 *
 * @param {number[]} array Сортируемый массив; изменяется на месте.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function heapsort(array) {
  // Фиктивный нулевой элемент, чтобы работали формулы 2i и 2i + 1
  const heap = [null, ...array];

  buildHeap(heap);

  for (let size = array.length; size > 1; size--) {
    [heap[1], heap[size]] = [heap[size], heap[1]];

    // Граница передается явно: элемент на позиции size уже занял свое
    // окончательное место и в просеивании больше не участвует
    siftDown(heap, 1, size - 1);
  }

  for (let i = 0; i < array.length; i++) {
    array[i] = heap[i + 1];
  }

  return array;
}
```

Извлеченный максимум оказывается на позиции `size`, то есть сразу на своем
окончательном месте: он больше всех оставшихся в куче.

#### Свойства

| | |
| --- | --- |
| Лучший, средний, худший | `O(n log n)` |
| Память | `O(1)` в версии на месте |
| Устойчивость | **неустойчива** |

Неустойчивость возникает из-за обменов на большие расстояния - по той же
причине, что и у [сортировки выбором](../sprint-3/sorting.md#323-сортировка-выбором).

Место среди других сортировок:

| | Слиянием | Быстрая | Пирамидальная |
| --- | --- | --- | --- |
| Худший случай | `O(n log n)` | `O(n²)` | **`O(n log n)`** |
| Память | `O(n)` | `O(log n)` | **`O(1)`** |
| Устойчивость | да | нет | нет |
| Скорость на практике | средняя | **высокая** | ниже |

Пирамидальная сортировка - единственная из трех, дающая **одновременно**
гарантию `O(n log n)` и `O(1)` памяти. Проигрывает она на практике из-за
обращений к памяти вразнобой: индексы `i`, `2i`, `4i` расходятся все дальше, и
кэш процессора работает плохо, тогда как быстрая сортировка читает память
последовательно.

Отсюда типичное применение: гибридные сортировки переключаются на
пирамидальную, когда [быстрая сортировка](../sprint-3/sorting.md#325-быстрая-сортировка)
уходит на слишком большую глубину рекурсии. Так гарантируется `O(n log n)` в
худшем случае без потери скорости в среднем - и это согласуется с
[нижней границей `Ω(n log n)`](../sprint-3/sorting.md#нижняя-граница-для-сортировок-сравнением)
для сортировок сравнением.
