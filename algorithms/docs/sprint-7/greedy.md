## 7.1 Жадные алгоритмы

**Жадный алгоритм** строит ответ по шагам, и на каждом шаге выбирает вариант,
который выглядит лучшим **прямо сейчас**, не пересматривая уже сделанный выбор.

Различие, которое проясняет суть:

- **тактика** - действие, оптимальное в текущий момент, без оглядки на будущее;
- **стратегия** - действие, которое может быть невыгодно сейчас, но приводит к
  лучшему результату в целом.

Жадный алгоритм - это чистая тактика. Поэтому главный вопрос не «как написать
жадный алгоритм» (это обычно очевидно), а **«дает ли он правильный ответ»**.
Ответ «нет» гораздо чаще, чем кажется.

### Два условия применимости

Жадный алгоритм дает оптимальный ответ, если задача обладает двумя свойствами.

**1. Свойство жадного выбора.** Существует оптимальное решение, содержащее
жадный выбор первого шага. Иначе говоря: сделав локально лучший выбор, мы не
теряем возможности достичь глобального оптимума.

**2. Оптимальная подструктура.** После жадного выбора остается задача того же
вида, и ее оптимальное решение вместе со сделанным выбором дает оптимальное
решение исходной задачи.

Первое свойство - сильное, и именно оно обычно нарушается. Второе свойство
слабее и требуется также
[динамическому программированию](dynamic.md#два-условия-применимости): разница
в том, что динамика **перебирает** все варианты первого шага, а жадность
**угадывает** нужный.

### Как доказывают жадные алгоритмы

Стандартный прием - **обменный аргумент** (exchange argument).

Схема рассуждения: берем произвольное оптимальное решение `O`. Если оно уже
содержит жадный выбор - все доказано. Если нет, показываем, что можно **обменять**
элемент из `O` на жадный выбор, не ухудшив результат. Получаем оптимальное
решение, содержащее жадный выбор. Дальше повторяем рассуждение для оставшейся
подзадачи.

Ниже этот прием применяется дважды - к задаче о расписании и к дробному рюкзаку.

Обратная сторона: чтобы **опровергнуть** жадный алгоритм, достаточно одного
контрпримера. Поэтому перед тем как доказывать, всегда стоит потратить минуту
на попытку сломать.

### 7.1.1 Задача о расписании

**Условие.** Дан набор заявок, каждая с временем начала и конца. В один момент
времени можно выполнять только одну заявку. Выбрать наибольшее количество
попарно непересекающихся заявок.

```
   время →   0    2    4    6    8   10   12   14   16

   A         ├─────────┤                                (1, 4)
   B                ├────┤                              (3, 5)
   C         ├──────────────┤                           (0, 6)
   D                   ├─────┤                          (5, 7)
   E                ├──────────────────┤                (3, 9)
   F                        ├──────────┤                (6, 10)
   G                             ├──────────┤           (8, 11)
   H                                  ├─────────┤       (12, 16)
```

#### Какие жадные стратегии приходят в голову

Прежде чем брать правильную, полезно увидеть, почему не подходят другие:

| Стратегия | Контрпример |
| --- | --- |
| Брать самые **короткие** заявки | `(0,10)`, `(9,11)`, `(10,20)` - короткая `(9,11)` мешает обеим длинным. Ответ 1 вместо 2 |
| Брать заявки с **ранним началом** | `(0,20)`, `(1,2)`, `(3,4)` - первая же заявка занимает все. Ответ 1 вместо 2 |
| Брать заявки с **наименьшим числом пересечений** | Ломается на более хитрых примерах, к тому же дороже считается |
| Брать заявки с **ранним концом** | **работает** |

#### Правильная стратегия

Сортируем заявки по времени **окончания** и берем каждую, которая не
пересекается с последней взятой.

```js
/**
 * Возвращает наибольший набор попарно непересекающихся заявок.
 *
 * Заявки перебираются в порядке возрастания времени окончания: та, что
 * освобождает ресурс раньше всех, оставляет максимум времени остальным.
 *
 * Время: O(n·log n) на сортировку. Память: O(n) на результат.
 *
 * @param {Array<{start: number, end: number}>} tasks Заявки.
 * @returns {Array<{start: number, end: number}>} Выбранные заявки.
 */
function selectTasks(tasks) {
  const sorted = [...tasks].sort((a, b) => a.end - b.end);
  const selected = [];
  let lastEnd = -Infinity;

  for (const task of sorted) {
    if (task.start >= lastEnd) {
      selected.push(task);
      lastEnd = task.end;
    }
  }

  return selected;
}
```

Для набора выше алгоритм выбирает `A(1,4)`, `D(5,7)`, `G(8,11)`, `H(12,16)` -
четыре заявки.

#### Доказательство

*Свойство жадного выбора.* Пусть `f` - заявка с самым ранним концом, и `O` -
некоторое оптимальное решение. Если `f ∈ O`, доказывать нечего. Иначе пусть
`g` - первая по времени окончания заявка в `O`. Так как `f` заканчивается не
позже `g`, а все остальные заявки в `O` начинаются не раньше конца `g`, то они
начинаются и не раньше конца `f`. Значит, заменив `g` на `f`, мы снова получим
корректный набор того же размера. Он оптимален и содержит `f`. ∎

*Оптимальная подструктура.* После выбора `f` остается та же задача на заявках,
начинающихся не раньше конца `f`. Оптимальное решение этой подзадачи вместе с
`f` дает оптимальное решение исходной: будь у исходной решение лучше, отбросив
из него `f`, мы получили бы лучшее решение подзадачи. ∎

Сложность - `O(n·log n)`, целиком за счет сортировки; сам проход линеен.

### 7.1.2 Задача о рюкзаке

**Условие.** Рюкзак выдерживает вес не более `W`. Есть `n` предметов, предмет
`i` имеет вес `wᵢ` и стоимость `vᵢ`. Набрать предметы так, чтобы суммарная
стоимость была наибольшей, а суммарный вес не превышал `W`.

У задачи два варианта, и они ведут себя **принципиально по-разному**:

- **дробный** - предмет можно взять частично;
- **целочисленный** (0-1) - предмет берется целиком либо не берется.

Разница в одном слове условия, а разница в решении - между `O(n·log n)` жадным
алгоритмом и динамическим программированием. Это лучший пример того, насколько
хрупка применимость жадного подхода.

---

#### 7.1.2.1 Задача о рюкзаке с дробными элементами

**Жадная стратегия:** брать предметы в порядке убывания **удельной стоимости**
`vᵢ / wᵢ` - стоимости единицы веса. Последний предмет, который не влезает
целиком, берется частично, ровно до заполнения рюкзака.

```js
/**
 * Возвращает наибольшую стоимость, которую можно унести, если предметы
 * разрешено брать частями.
 *
 * Предметы берутся в порядке убывания удельной стоимости: каждая единица
 * вместимости заполняется самым ценным из доступного.
 *
 * Время: O(n·log n) на сортировку. Память: O(n).
 *
 * @param {Array<{value: number, weight: number}>} items Предметы.
 * @param {number} capacity Вместимость рюкзака.
 * @returns {number} Наибольшая достижимая стоимость.
 */
function fractionalKnapsack(items, capacity) {
  const sorted = [...items].sort(
    (a, b) => b.value / b.weight - a.value / a.weight,
  );

  let remaining = capacity;
  let total = 0;

  for (const item of sorted) {
    if (remaining === 0) {
      break;
    }

    // Предмет либо помещается целиком, либо берется ровно на остаток
    const taken = Math.min(item.weight, remaining);

    total += item.value * (taken / item.weight);
    remaining -= taken;
  }

  return total;
}
```

*Доказательство обменом.* Пусть `a` - предмет с наибольшей удельной стоимостью,
и в некотором оптимальном решении он взят не полностью, а какой-то предмет `b`
с меньшей удельной стоимостью взят в количестве `x > 0`. Заменим `x` единиц
веса предмета `b` на `x` единиц предмета `a` (это возможно, пока `a` взят не
весь). Вес не изменился, а стоимость изменилась на
`x·(vₐ/wₐ − v_b/w_b) ≥ 0`, то есть не уменьшилась. Повторяя обмены, приходим к
жадному решению, не ухудшив ответ. ∎

Ключ к доказательству - **делимость**: только она позволяет обменять «столько
же веса» и получить корректный набор.

---

#### 7.1.2.2 Задача о рюкзаке с целыми элементами

Здесь предметы неделимы, и обменный аргумент рушится: заменить часть предмета
`b` на часть предмета `a` больше нельзя.

**И жадный алгоритм действительно дает неверный ответ.** Контрпример:

```
   Вместимость рюкзака W = 10

   предмет   вес   стоимость   удельная стоимость
      A       6        30            5,0
      B       5        20            4,0
      C       5        20            4,0

   Жадно: берем A (вес 6). Ни B, ни C уже не влезают - остается 4 единицы.
          Итог: 30.

   Оптимально: берем B и C (вес 5 + 5 = 10).
          Итог: 40.
```

Жадность проиграла, потому что предмет с лучшей удельной стоимостью занял
место, которое выгоднее было отдать двум другим. Никакой другой порядок
сортировки не спасает: можно построить контрпример к любому фиксированному
правилу выбора.

Причина глубже частного примера: **свойство жадного выбора здесь не
выполняется**. Локально лучший предмет может не входить ни в одно оптимальное
решение.

Что остается:

- **перебор всех подмножеств** - `2ⁿ` вариантов, при `n = 40` уже неприемлемо;
- **динамическое программирование** - перебирает те же варианты, но не
  пересчитывает одно и то же, и работает за `O(n·W)`.

Именно это и разбирается в [следующем разделе](dynamic.md#72-динамическое-программирование),
а сама задача - в [разделе про рюкзак](knapsack.md#722-задача-о-рюкзаке).

### Когда жадность работает, а когда нет

| Задача | Жадность | Почему |
| --- | --- | --- |
| Расписание заявок | **да** | Ранний конец оставляет максимум места |
| Дробный рюкзак | **да** | Делимость позволяет обмен |
| Целочисленный рюкзак | нет | Обмен невозможен, выбор может «занять» нужное место |
| [Дейкстра](../sprint-6/shortest-paths.md#661-алгоритм-дейкстры) | **да** | При неотрицательных весах минимум окончателен |
| Дейкстра с отрицательными ребрами | нет | Отрицательное ребро может улучшить готовый ответ |
| [Прим и Крускал](../sprint-6/mst.md#67-минимальное-остовное-дерево) | **да** | Свойство разреза |
| Размен монет произвольными номиналами | нет | См. ниже |

Показательный пример последней строки. Пусть номиналы `1, 3, 4`, набрать нужно
6. Жадный алгоритм берет наибольшую монету: `4 + 1 + 1` - три монеты.
Оптимально - `3 + 3`, две монеты. Для «обычных» наборов номиналов вроде
`1, 2, 5, 10` жадность работает, и именно поэтому ошибка так легко
проскакивает: алгоритм верен на всех примерах, которые приходят в голову, и
неверен в общем случае.

**Практический вывод.** Жадное решение нужно либо доказывать обменным
аргументом, либо ломать контрпримером. Третьего - «работает на моих примерах,
наверное, верно» - не бывает.
