## 7.2.3 Наибольшая общая подпоследовательность

**Подпоследовательность** - то, что остается от последовательности после
удаления некоторых элементов; порядок оставшихся сохраняется.

Важно не путать с [подстрокой](../sprint-8/strings.md#82-подстроки-префиксы-и-суффиксы):
подстрока идет **подряд**, подпоследовательность - нет.

```
   строка:               A B C B D A B

   подстрока:              C B D          - идет подряд
   подпоследовательность:  B   D   B      - идет в том же порядке, но с пропусками
```

**Условие.** Даны две последовательности. Найти наибольшую по длине
последовательность, являющуюся подпоследовательностью обеих.

```
   X = A B C B D A B
   Y = B D C A B A

   Общие подпоследовательности: «BCA», «BCBA», «BDAB», …
   Наибольшая - длины 4, например «BCBA»
```

Задача лежит в основе `diff`, сравнения версий текста и алгоритмов поиска
различий в биологических последовательностях.

Полный перебор безнадежен: у строки длины `n` ровно `2ⁿ` подпоследовательностей.

---

### Применяем рецепт

Идем по [пяти шагам](dynamic.md#рецепт-из-пяти-шагов).

**1. Состояние.**

> `dp[i][j]` - длина наибольшей общей подпоследовательности первых `i` символов
> строки `X` и первых `j` символов строки `Y`.

Как и в [рюкзаке](knapsack.md#722-задача-о-рюкзаке), одного индекса не хватает:
нужно независимо отслеживать положение в каждой строке.

**2. База.** `dp[0][j] = 0` и `dp[i][0] = 0`: у пустой строки нет общих
подпоследовательностей ни с чем.

**3. Переход.** Спросим: что происходит с **последними** символами
рассматриваемых префиксов, `X[i]` и `Y[j]`?

- **Символы совпадают.** Тогда их выгодно взять в общую подпоследовательность:
  существует оптимальный ответ, в котором эта пара использована. Остается
  задача для префиксов на единицу короче:

  ```
     dp[i][j] = dp[i − 1][j − 1] + 1
  ```

- **Символы различаются.** Тогда хотя бы один из них в ответ не входит.
  Рассматриваем оба случая и берем лучший:

  ```
     dp[i][j] = max( dp[i − 1][j],  dp[i][j − 1] )
  ```

Почему при совпадении не нужно рассматривать варианты «не берем»? Потому что
взять совпавшую пару никогда не хуже: любой ответ, не использующий ее, можно
дополнить или переделать под нее без потери длины. Это опять
[обменный аргумент](greedy.md#как-доказывают-жадные-алгоритмы), только внутри
динамики.

**4. Порядок.** По возрастанию `i`, внутри - по возрастанию `j`. Все три ячейки,
на которые ссылается переход - `[i−1][j−1]`, `[i−1][j]`, `[i][j−1]` - лежат выше
или левее текущей.

```
        j−1    j
      ┌─────┬─────┐
  i−1 │  ↘  │  ↓  │
      ├─────┼─────┤
   i  │  →  │  ?  │
      └─────┴─────┘
```

**5. Ответ.** `dp[n][m]`, где `n` и `m` - длины строк.

```js
/**
 * Строит таблицу длин наибольших общих подпоследовательностей префиксов.
 *
 * Состояние dp[i][j] - длина НОП первых i символов first и первых j символов
 * second. Переход разбирает случай по последним символам префиксов: при
 * совпадении пара берется в ответ, иначе отбрасывается один из символов.
 *
 * Время: O(n·m). Память: O(n·m).
 *
 * @param {string} first Первая последовательность.
 * @param {string} second Вторая последовательность.
 * @returns {number[][]} Таблица размера (n + 1) × (m + 1).
 */
function lcsTable(first, second) {
  const n = first.length;
  const m = second.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(m + 1).fill(0));

  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= m; j++) {
      if (first[i - 1] === second[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }

  return dp;
}
```

### Трассировка

`X = «ABCBDAB»`, `Y = «BDCABA»`. Строки нумеруются с единицы, нулевая строка и
нулевой столбец - база.

```
              j:  0   1   2   3   4   5   6
                  ε   B   D   C   A   B   A
            ┌───────────────────────────────
    i=0  ε  │  0   0   0   0   0   0   0
    i=1  A  │  0   0   0   0   1   1   1
    i=2  B  │  0   1   1   1   1   2   2
    i=3  C  │  0   1   1   2   2   2   2
    i=4  B  │  0   1   1   2   2   3   3
    i=5  D  │  0   1   2   2   2   3   3
    i=6  A  │  0   1   2   2   3   3   4
    i=7  B  │  0   1   2   2   3   4   4
                                        ↑
                                      ответ 4
```

Как читать отдельные ячейки:

```
   dp[2][1]:  X[2] = «B», Y[1] = «B» - совпадение
              dp[2][1] = dp[1][0] + 1 = 0 + 1 = 1

   dp[4][5]:  X[4] = «B», Y[5] = «B» - совпадение
              dp[4][5] = dp[3][4] + 1 = 2 + 1 = 3

   dp[5][4]:  X[5] = «D», Y[4] = «A» - различаются
              dp[5][4] = max(dp[4][4], dp[5][3]) = max(2, 2) = 2
```

Значения в таблице никогда не убывают вправо и вниз, и соседние отличаются не
более чем на единицу. Это удобная проверка при отладке: нарушение означает
ошибку в переходе.

### Восстановление подпоследовательности

Идем от правого нижнего угла к левому верхнему, повторяя логику перехода в
обратную сторону.

```js
/**
 * Восстанавливает наибольшую общую подпоследовательность по таблице.
 *
 * Проход идет от правого нижнего угла. Совпадение символов означает, что
 * значение получено переходом по диагонали и символ входит в ответ; иначе
 * сдвигаемся туда, откуда пришло значение.
 *
 * Символы собираются от конца к началу, поэтому результат разворачивается.
 *
 * Время: O(n + m). Память: O(длины ответа).
 *
 * @param {number[][]} dp Таблица из lcsTable.
 * @param {string} first Первая последовательность.
 * @param {string} second Вторая последовательность.
 * @returns {string} Одна из наибольших общих подпоследовательностей.
 */
function restoreLcs(dp, first, second) {
  const result = [];
  let i = first.length;
  let j = second.length;

  while (i > 0 && j > 0) {
    if (first[i - 1] === second[j - 1]) {
      result.push(first[i - 1]);
      i--;
      j--;
      continue;
    }

    // Идем туда, откуда пришло текущее значение
    if (dp[i - 1][j] >= dp[i][j - 1]) {
      i--;
    } else {
      j--;
    }
  }

  return result.reverse().join('');
}
```

Наибольших общих подпоследовательностей может быть несколько - здесь `«BCBA»` и
`«BDAB»` обе длины 4. Алгоритм возвращает одну из них, конкретную выбирает
условие `>=` в сравнении.

### Экономия памяти

Строка `i` зависит только от строки `i − 1`, поэтому для вычисления **длины**
хватает двух строк:

```js
/**
 * Возвращает длину наибольшей общей подпоследовательности.
 *
 * Хранятся только две строки таблицы: текущая и предыдущая. Восстановить сам
 * ответ при этом невозможно - промежуточные строки не сохраняются.
 *
 * Время: O(n·m). Память: O(min(n, m)).
 *
 * @param {string} first Первая последовательность.
 * @param {string} second Вторая последовательность.
 * @returns {number} Длина наибольшей общей подпоследовательности.
 */
function lcsLength(first, second) {
  // Меньшая строка становится осью столбцов: память равна ее длине
  const [shorter, longer] =
    first.length <= second.length ? [first, second] : [second, first];

  let previous = new Array(shorter.length + 1).fill(0);
  let current = new Array(shorter.length + 1).fill(0);

  for (let i = 1; i <= longer.length; i++) {
    for (let j = 1; j <= shorter.length; j++) {
      current[j] =
        longer[i - 1] === shorter[j - 1]
          ? previous[j - 1] + 1
          : Math.max(previous[j], current[j - 1]);
    }

    [previous, current] = [current, previous];
  }

  return previous[shorter.length];
}
```

Обмен строк местами вместо создания новой избавляет от `n` выделений памяти.
Заметьте, что после обмена результат оказывается в `previous`, а не в `current`
- это место, где легко ошибиться на единицу.

### Расстояние Левенштейна

Та же схема решает соседнюю задачу: за сколько операций одну строку можно
превратить в другую. Разрешены вставка, удаление и замена одного символа.

**1. Состояние.** `dp[i][j]` - минимальное число операций, превращающих первые
`i` символов `X` в первые `j` символов `Y`.

**2. База.** `dp[i][0] = i` - удалить все `i` символов. `dp[0][j] = j` -
вставить все `j` символов. Здесь база нетривиальна, в отличие от НОП.

**3. Переход.** Разбор по последней операции:

```
   если X[i] = Y[j]:   dp[i][j] = dp[i − 1][j − 1]                    ничего не делаем

   иначе:              dp[i][j] = 1 + min( dp[i − 1][j],      удаление
                                           dp[i][j − 1],      вставка
                                           dp[i − 1][j − 1] )  замена
```

```js
/**
 * Возвращает расстояние Левенштейна между двумя строками.
 *
 * Состояние dp[i][j] - минимальное число вставок, удалений и замен,
 * превращающих первые i символов first в первые j символов second.
 * Переход разбирает случаи по последней выполненной операции.
 *
 * Время: O(n·m). Память: O(n·m).
 *
 * @param {string} first Исходная строка.
 * @param {string} second Целевая строка.
 * @returns {number} Минимальное число операций редактирования.
 */
function levenshteinDistance(first, second) {
  const n = first.length;
  const m = second.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(m + 1).fill(0));

  // Пустую строку можно получить только удалением всех символов
  for (let i = 0; i <= n; i++) {
    dp[i][0] = i;
  }

  // И наоборот: из пустой строки - только вставками
  for (let j = 0; j <= m; j++) {
    dp[0][j] = j;
  }

  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= m; j++) {
      if (first[i - 1] === second[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1];
        continue;
      }

      dp[i][j] =
        1 + Math.min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]);
    }
  }

  return dp[n][m];
}
```

Сравнение двух задач показывает, насколько схема универсальна:

| | НОП | Расстояние Левенштейна |
| --- | --- | --- |
| Что оптимизируем | максимум | минимум |
| База | нули | `dp[i][0] = i`, `dp[0][j] = j` |
| Совпадение символов | `dp[i−1][j−1] + 1` | `dp[i−1][j−1]` |
| Несовпадение | `max` из двух | `1 + min` из **трех** |

Третий вариант в переходе - это замена, диагональный переход при несовпадении.
В НОП его нет, потому что «заменять» там нечего.

### Двумерная динамика в целом

НОП и расстояние Левенштейна - представители широкого класса задач, где
состояние задается двумя индексами, а переход смотрит на соседей сверху, слева
и по диагонали.

Сюда же относятся задачи о пути по таблице: собрать максимум значений, двигаясь
из угла в угол только вправо и вверх. Состояние - `dp[i][j]` для клетки,
переход - максимум из двух соседей плюс значение клетки. Именно такие задачи
идут в этом спринте под именами «Поле с цветочками».

Общая схема двумерной динамики:

```
   1. Состояние     dp[i][j] - ответ для префиксов длины i и j
                    (либо для клетки (i, j))
   2. База          нулевая строка и нулевой столбец
   3. Переход       смотрит на [i−1][j], [i][j−1], [i−1][j−1]
   4. Порядок       по строкам сверху вниз, внутри строки слева направо
   5. Ответ         dp[n][m]
```

Меняются операция (`max`, `min`, `+`) и условия - схема остается.
