## 6.6 Алгоритмы кратчайших путей

Задача: во взвешенном графе найти кратчайшие по **весу** пути от стартовой
вершины `s` до всех остальных.

[BFS](bfs.md#65-поиск-в-ширину--bfs) здесь не годится: он минимизирует
количество ребер, а не их суммарный вес.

Результат работы - **дерево кратчайших путей** (shortest-path tree, SPT):
подграф, содержащий `s` и все достижимые из нее вершины, в котором путь от `s`
до любой вершины совпадает по весу с кратчайшим в исходном графе. Дерево задается
массивом предшественников: у каждой вершины остается одно входящее ребро - то,
по которому в нее ведет кратчайший путь.

### Релаксация

Обоим алгоритмам этого раздела нужна одна и та же операция - **релаксация
ребра**. Она проверяет, не дает ли путь через `u` более короткую дорогу до `v`:

```
если dist[u] + weight(u, v) < dist[v]:
    dist[v] = dist[u] + weight(u, v)
    previous[v] = u
```

```js
/**
 * Пытается улучшить известное расстояние до вершины через ребро (u, v).
 *
 * Время: O(1).
 *
 * @param {number[]} dist Текущие расстояния; изменяется на месте.
 * @param {number[]} previous Предшественники; изменяется на месте.
 * @param {number} u Начало ребра.
 * @param {number} v Конец ребра.
 * @param {number} weight Вес ребра.
 * @returns {boolean} true, если расстояние удалось уменьшить.
 */
function relax(dist, previous, u, v, weight) {
  if (dist[u] + weight >= dist[v]) {
    return false;
  }

  dist[v] = dist[u] + weight;
  previous[v] = u;

  return true;
}
```

Алгоритмы различаются только **порядком** релаксаций.

### 6.6.1 Алгоритм Дейкстры

**Идея.** Поддерживаем множество вершин, до которых кратчайший путь уже точно
найден. На каждом шаге берем из оставшихся вершину с наименьшим текущим
расстоянием, объявляем это расстояние окончательным и релаксируем все исходящие
из нее ребра.

**Почему выбор минимума дает окончательный ответ.** Пусть `u` - непосещенная
вершина с наименьшим `dist[u]`. Любой другой путь до `u` должен выйти за
пределы посещенного множества через какую-то непосещенную вершину `w`, а
`dist[w] ≥ dist[u]`. Поскольку веса неотрицательны, добавление оставшегося
хвоста пути расстояние только увеличит. Значит, лучше `dist[u]` уже не станет.

Именно здесь и требуется **неотрицательность весов** - это ровно то место, где
рассуждение ломается при отрицательном ребре.

```js
/**
 * Находит кратчайшие пути от стартовой вершины методом Дейкстры.
 *
 * Реализация с поиском минимума перебором: подходит для плотных графов.
 *
 * Время: O(|V|² + |E|). Память: O(|V|).
 *
 * @param {Array<Array<{to: number, weight: number}>>} adjacency Списки
 *   смежности графа с неотрицательными весами.
 * @param {number} n Количество вершин.
 * @param {number} start Стартовая вершина.
 * @returns {{dist: number[], previous: number[]}} Расстояния и предшественники.
 */
function dijkstra(adjacency, n, start) {
  const dist = new Array(n + 1).fill(Infinity);
  const previous = new Array(n + 1).fill(0);
  const visited = new Array(n + 1).fill(false);

  dist[start] = 0;

  for (let step = 0; step < n; step++) {
    let u = 0;

    for (let v = 1; v <= n; v++) {
      if (!visited[v] && dist[v] < (u === 0 ? Infinity : dist[u])) {
        u = v;
      }
    }

    // Все оставшиеся вершины недостижимы
    if (u === 0) {
      break;
    }

    visited[u] = true;

    for (const { to, weight } of adjacency[u]) {
      relax(dist, previous, u, to, weight);
    }
  }

  return { dist, previous };
}
```

#### Версия на приоритетной очереди

Поиск минимума перебором стоит `O(|V|)` на шаг. Для разреженного графа это
основная статья расходов, и ее убирает
[приоритетная очередь](../sprint-5/priority-queue.md#55-приоритетная-очередь).

Вершина добавляется в очередь при каждом улучшении ее расстояния, поэтому одна
вершина может попасть в очередь несколько раз. Устаревшие записи отбрасываются
при извлечении - это проще, чем изменять приоритет уже лежащего в куче
элемента.

```js
/**
 * Находит кратчайшие пути от стартовой вершины методом Дейкстры
 * на приоритетной очереди.
 *
 * Куча хранит пары «расстояние, вершина». Одна вершина может попасть в кучу
 * несколько раз - при каждом улучшении расстояния; устаревшие записи
 * отбрасываются при извлечении по признаку visited.
 *
 * Время: O((|V| + |E|)·log|E|). Память: O(|V| + |E|).
 *
 * @param {Array<Array<{to: number, weight: number}>>} adjacency Списки
 *   смежности графа с неотрицательными весами.
 * @param {number} n Количество вершин.
 * @param {number} start Стартовая вершина.
 * @returns {{dist: number[], previous: number[]}} Расстояния и предшественники.
 */
function dijkstraWithHeap(adjacency, n, start) {
  const dist = new Array(n + 1).fill(Infinity);
  const previous = new Array(n + 1).fill(0);
  const visited = new Array(n + 1).fill(false);

  dist[start] = 0;

  // Куча на минимум: [null, [расстояние, вершина], …]
  const heap = [null, [0, start]];

  while (heap.length > 1) {
    const [, u] = popMin(heap);

    if (visited[u]) {
      continue;
    }

    visited[u] = true;

    for (const { to, weight } of adjacency[u]) {
      if (relax(dist, previous, u, to, weight)) {
        heapAdd(heap, [dist[to], to]);
      }
    }
  }

  return { dist, previous };
}
```

#### Сложность

| Хранение очереди | Время |
| --- | --- |
| Массив, поиск минимума перебором | `O(\|V\|² + \|E\|)` |
| Двоичная куча | `O((\|V\| + \|E\|)·log\|E\|)` |

Для связного графа `|E| ≥ |V| − 1`, поэтому вторую оценку записывают как
`O(|E|·log|V|)`: `log|E| ≤ log|V|² = 2·log|V|`, а константа отбрасывается.

Что выбирать:

- **плотный граф** (`|E| ≈ |V|²`) - версия на массиве: `O(|V|²)` против
  `O(|V|²·log|V|)` у кучи;
- **разреженный граф** (`|E| ≈ |V|`) - версия на куче: `O(|V|·log|V|)` против
  `O(|V|²)`.

#### Ограничение

**Дейкстра неприменим к графам с отрицательными весами.** Вершина объявляется
посещенной навсегда, а отрицательное ребро может позже дать более короткий
путь - и алгоритм этого уже не заметит.

```
        (a)
       ↗   ↘
      1     4
     ↗       ↘
   (s)       (c)
     ↘       ↗
      2   (−3)
       ↘ ↗
        (b)

   Дейкстра: берет a (dist 1), релаксирует c → 5.
   Затем берет b (dist 2), релаксирует c → 2 - 3 = −1.
   Здесь ошибки еще нет; она возникает, когда отрицательное ребро ведет
   в уже посещенную вершину - тогда ее расстояние остается завышенным.
```

Отрицательные ребра обрабатывает алгоритм Беллмана-Форда.

### 6.6.2 Алгоритм Беллмана-Форда

**Идея.** Не выбирать, какое ребро релаксировать следующим, а просто
релаксировать **все** ребра подряд, и повторить это `|V| − 1` раз.

**Почему `|V| − 1` проходов достаточно.** Кратчайший путь в графе без
отрицательных циклов является простым, то есть содержит не более `|V| − 1`
ребер. Индукция по числу проходов: после `k`-го прохода корректно вычислены все
кратчайшие пути, содержащие не более `k` ребер. На первом проходе релаксируется
первое ребро любого кратчайшего пути, на втором - второе, и так далее.
Следовательно, после `|V| − 1` проходов найдены все кратчайшие пути.

```js
/**
 * Находит кратчайшие пути от стартовой вершины методом Беллмана-Форда.
 *
 * Допускает ребра отрицательного веса и обнаруживает отрицательные циклы.
 *
 * Досрочный выход при проходе без единой релаксации существен: без него
 * алгоритм всегда выполнял бы |V| - 1 проход, тогда как на практике
 * расстояния стабилизируются гораздо раньше.
 *
 * Время: O(|V|·|E|). Память: O(|V|).
 *
 * @param {Array<[number, number, number]>} edges Ребра в виде [from, to, weight].
 * @param {number} n Количество вершин.
 * @param {number} start Стартовая вершина.
 * @returns {{dist: number[], previous: number[], hasNegativeCycle: boolean}}
 *   Расстояния, предшественники и признак достижимого отрицательного цикла.
 */
function bellmanFord(edges, n, start) {
  const dist = new Array(n + 1).fill(Infinity);
  const previous = new Array(n + 1).fill(0);

  dist[start] = 0;

  for (let pass = 0; pass < n - 1; pass++) {
    let changed = false;

    for (const [from, to, weight] of edges) {
      // Недостижимую вершину релаксировать нельзя: Infinity + weight
      // даст Infinity и создаст ложные пути от недостижимых вершин
      if (dist[from] !== Infinity && relax(dist, previous, from, to, weight)) {
        changed = true;
      }
    }

    if (!changed) {
      break;
    }
  }

  // Дополнительный проход: если расстояние все еще уменьшается,
  // значит, существует достижимый цикл отрицательного веса
  let hasNegativeCycle = false;

  for (const [from, to, weight] of edges) {
    if (dist[from] !== Infinity && dist[from] + weight < dist[to]) {
      hasNegativeCycle = true;
      break;
    }
  }

  return { dist, previous, hasNegativeCycle };
}
```

#### Отрицательные циклы

Если в графе есть цикл суммарного отрицательного веса, достижимый из старта, то
кратчайшего пути **не существует**: проходя по циклу еще раз, путь всегда можно
удешевить.

```
        (a)──2──→(b)
         ↑         │
         │         1
        −4         ↓
         └───────(c)

   Вес цикла a → b → c → a равен 2 + 1 − 4 = −1.
   Каждый оборот уменьшает стоимость пути на 1 - минимума не существует.
```

Беллман-Форд обнаруживает такую ситуацию: после `|V| − 1` проходов расстояния
обязаны стабилизироваться, и если `|V|`-й проход все еще что-то улучшает,
отрицательный цикл есть. Это самостоятельно ценное свойство - например, для
поиска арбитражных цепочек в обменных курсах.

#### Сравнение

| | Дейкстра | Беллман-Форд |
| --- | --- | --- |
| Отрицательные веса | **нет** | да |
| Обнаружение отрицательных циклов | нет | **да** |
| Время | `O(\|E\|·log\|V\|)` | `O(\|V\|·\|E\|)` |
| Представление графа | списки смежности | **список ребер** |
| Порядок обработки | жадный, по минимуму | все ребра подряд |

Беллман-Форд заметно медленнее, поэтому его берут только тогда, когда есть
отрицательные веса или нужно поймать отрицательный цикл. В остальных случаях -
Дейкстра.
