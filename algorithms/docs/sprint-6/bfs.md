## 6.5 Поиск в ширину - BFS

**Поиск в ширину** (breadth-first search) обходит граф слоями: сначала стартовую
вершину, затем всех ее соседей, затем соседей соседей и так далее.

Формально вершины разбиваются на слои по расстоянию от старта `s`:

```
   L₀ = {s}
   L₁ = вершины на расстоянии 1
   L₂ = вершины на расстоянии 2
   …
   L∞ = недостижимые вершины
```

```
              L₀        L₁         L₂        L₃         L∞

                      (v₂)──────→(v₆)
                     ↗                                (v₇)──→(v₈)
             (v₁)
                     ↘
                      (v₄)──────→(v₃)──────→(v₅)

   L₀ = {v₁}   L₁ = {v₂, v₄}   L₂ = {v₃, v₆}   L₃ = {v₅}   L∞ = {v₇, v₈}
```

Отличие от [DFS](dfs.md#63-поиск-в-глубину--dfs) только в структуре данных:
DFS хранит запланированные вершины в стеке, BFS - в
[очереди](../sprint-2/stack-and-queue.md#24-очередь-и-дек). Стек отдает
последнюю добавленную вершину и уводит вглубь; очередь отдает первую и
удерживает обход на текущем слое.

Именно порядок по слоям дает главное свойство BFS: **в невзвешенном графе BFS
находит кратчайшие пути от старта до всех вершин**.

### 6.5.1 Алгоритм BFS

1. Создать очередь `planned` и положить в нее стартовую вершину, покрасив ее в
   серый.
2. Пока очередь не пуста:
   - извлечь вершину `u` из начала очереди;
   - для каждого ребра `(u, v)`: если `v` белая, покрасить ее в серый, записать
     расстояние и предшественника, добавить в конец очереди;
   - покрасить `u` в черный.

Смысл цветов тот же, что в DFS, но серый здесь означает «вершина уже в очереди».
Проверка цвета перед добавлением обязательна: без нее вершина попадала бы в
очередь столько раз, сколько в нее входит ребер, и расстояние могло бы быть
перезаписано большим значением.

```js
const WHITE = 0;
const GRAY = 1;
const BLACK = 2;

/**
 * Обходит граф в ширину, вычисляя расстояния и предшественников.
 *
 * Расстояние записывается в момент добавления вершины в очередь. Это корректно
 * именно из-за порядка по слоям: вершина обнаруживается впервые с того слоя,
 * который к ней ближе всего, и переоткрыть ее короче уже нельзя.
 *
 * Время: O(|V| + |E|). Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности.
 * @param {number} n Количество вершин.
 * @param {number} start Стартовая вершина.
 * @returns {{distance: number[], previous: number[]}} Расстояния от старта
 *   (Infinity для недостижимых) и предшественники (0 для старта
 *   и недостижимых).
 */
function breadthFirstSearch(adjacency, n, start) {
  const color = new Array(n + 1).fill(WHITE);
  const distance = new Array(n + 1).fill(Infinity);
  const previous = new Array(n + 1).fill(0);

  // Указатель на голову вместо shift: shift сдвигает весь массив за O(|V|),
  // что превратило бы обход в O(|V|²)
  const planned = [start];
  let head = 0;

  color[start] = GRAY;
  distance[start] = 0;

  while (head < planned.length) {
    const u = planned[head];
    head++;

    for (const v of adjacency[u]) {
      if (color[v] === WHITE) {
        color[v] = GRAY;
        distance[v] = distance[u] + 1;
        previous[v] = u;
        planned.push(v);
      }
    }

    color[u] = BLACK;
  }

  return { distance, previous };
}

/**
 * Восстанавливает кратчайший путь от старта до вершины.
 *
 * Массив предшественников хранит путь в обратную сторону, поэтому вершины
 * собираются от конца к началу и разворачиваются.
 *
 * Время: O(длины пути). Память: O(длины пути).
 *
 * @param {number[]} previous Предшественники из breadthFirstSearch.
 * @param {number} start Стартовая вершина.
 * @param {number} target Конечная вершина.
 * @returns {number[]} Путь от start до target либо пустой массив,
 *   если пути нет.
 */
function restorePath(previous, start, target) {
  if (start !== target && previous[target] === 0) {
    return [];
  }

  const path = [];

  for (let v = target; v !== 0; v = previous[v]) {
    path.push(v);
  }

  return path.reverse();
}
```

#### Ловушка с `shift`

Очередь на массиве с `shift()` выглядит естественно, но `shift` сдвигает все
оставшиеся элементы и стоит `O(длины очереди)`. На графе с `|V| = 10⁵` это
превращает `O(|V| + |E|)` в `O(|V|²)`.

Решение - не удалять элементы, а двигать указатель на голову, как в
[очереди на динамическом массиве](../sprint-2/stack-and-queue.md#241-очередь-на-динамическом-массиве).
Память при этом `O(|V|)`, потому что каждая вершина попадает в очередь не более
одного раза.

#### Разбор сложности

Инициализация массивов - `O(|V|)`. Каждая вершина попадает в очередь не более
одного раза, значит, извлекается тоже не более одного раза. При обработке
вершины перебираются ее исходящие ребра; суммарно по всем вершинам это `O(|E|)`.
Итого `O(|V| + |E|)` времени и `O(|V|)` памяти.

#### Почему BFS дает кратчайшие пути

Докажем индукцией по слоям, что в момент добавления вершины `v` в очередь
значение `distance[v]` равно истинному расстоянию от `s`.

Вершины извлекаются из очереди в порядке неубывания расстояния - это следует из
того, что очередь пополняется только значениями `distance[u] + 1`, а `u`
извлекаются по порядку. Значит, когда обрабатывается вершина `u` с
`distance[u] = k`, все вершины слоев `0 … k` уже обнаружены. Белая соседка `v`
не принадлежит ни одному из них, а ребро `(u, v)` дает путь длины `k + 1`,
следовательно, `v` лежит ровно в слое `k + 1`.

**Свойство ломается на взвешенном графе.** BFS считает все ребра одинаковыми, и
путь из одного ребра веса 100 он предпочтет пути из двух ребер веса 1. Для
взвешенных графов нужен [алгоритм Дейкстры](shortest-paths.md#661-алгоритм-дейкстры).

Частный случай: если веса - целые и небольшие, ребро веса `w` можно заменить
цепочкой из `w` ребер веса 1 и все же применить BFS. А для графа с весами
только 0 и 1 работает **0-1 BFS**: вместо очереди берется
[дек](../sprint-2/stack-and-queue.md#дек-на-кольцевом-буфере), вершины по ребрам
веса 0 добавляются в начало, веса 1 - в конец.

#### DFS или BFS

| | DFS | BFS |
| --- | --- | --- |
| Структура | стек | очередь |
| Порядок | вглубь | по слоям |
| Кратчайшие пути | нет | **да**, в невзвешенном графе |
| Память | `O(глубины)` | `O(ширины слоя)` |
| Времена входа-выхода, топологическая сортировка, поиск циклов | **да** | нет |

На «длинном» графе (цепочка) экономнее BFS, на «широком» (звезда) - DFS.
