## 6.2 Способы представления графов в памяти

Один и тот же граф хранят тремя способами. Выбор определяется плотностью графа и
тем, какие операции должны быть быстрыми.

Все три способа иллюстрируются на одном графе:

```
   Ориентированный взвешенный граф

        5        11
   (1)─────→(2)─────→(6)
    │         ↑       │
  10│        2│      4│
    ↓         │       ↓
   (4)───────(3)     (5)
        4      ↑      │
               │2    6│
               └──────┘
```

---

### 6.2.1 Представление в виде матрицы смежности

Двумерный массив `A` размера `|V| × |V|`. Элемент `A[i][j]` содержит признак
наличия ребра из `i` в `j`, а для взвешенного графа - его вес.

```
        1   2   3   4   5   6
      ┌───────────────────────
   1  │ 0   5   0  10   0   0
   2  │ 0   0   0   0   0  11
   3  │ 0   2   0   0   0   0
   4  │ 0   0   4   0   0   0
   5  │ 0   0   2   0   0   6
   6  │ 0   0   0   0   4   0
```

Для **неориентированного** графа матрица **симметрична**: `A[i][j] = A[j][i]`.
Поэтому достаточно хранить половину - например, элементы выше главной
диагонали.

```js
/**
 * Строит матрицу смежности взвешенного графа.
 *
 * Время: O(|V|² + |E|). Память: O(|V|²).
 *
 * @param {number} n Количество вершин, нумерация с единицы.
 * @param {Array<[number, number, number]>} edges Ребра в виде [from, to, weight].
 * @param {boolean} directed Ориентирован ли граф.
 * @returns {number[][]} Матрица размера (n + 1) × (n + 1); нулевая строка
 *   и нулевой столбец не используются.
 */
function createAdjacencyMatrix(n, edges, directed = true) {
  const matrix = Array.from({ length: n + 1 }, () => new Array(n + 1).fill(0));

  for (const [from, to, weight] of edges) {
    matrix[from][to] = weight;

    if (!directed) {
      matrix[to][from] = weight;
    }
  }

  return matrix;
}
```

**Достоинство:** проверка наличия ребра за `O(1)`.

**Недостатки:** память `O(|V|²)` независимо от числа ребер, и перебор соседей
вершины стоит `O(|V|)` - приходится просматривать всю строку, включая нули.

Ноль как «ребра нет» годится, только если нулевой вес невозможен. Иначе нужен
отдельный признак - `null` либо `Infinity`.

Для `|V| = 10⁵` матрица потребовала бы `10¹⁰` ячеек - сотни гигабайт. Матрица
применима лишь к небольшим или плотным графам.

### 6.2.2 Представление в виде списков смежности

Для каждой вершины хранится список смежных с ней вершин. Весь граф - массив
списков, индексированный номером вершины.

```
   1: [2, 4]
   2: [6]
   3: [2]
   4: [3]
   5: [3, 6]
   6: [5]
```

Для взвешенного графа рядом с номером вершины хранится вес ребра:

```
   1: [{to: 2, weight: 5}, {to: 4, weight: 10}]
   2: [{to: 6, weight: 11}]
   3: [{to: 2, weight: 2}]
   4: [{to: 3, weight: 4}]
   5: [{to: 3, weight: 2}, {to: 6, weight: 6}]
   6: [{to: 5, weight: 4}]
```

```js
/**
 * Строит списки смежности взвешенного графа.
 *
 * Время: O(|V| + |E|). Память: O(|V| + |E|).
 *
 * @param {number} n Количество вершин, нумерация с единицы.
 * @param {Array<[number, number, number]>} edges Ребра в виде [from, to, weight].
 * @param {boolean} directed Ориентирован ли граф.
 * @returns {Array<Array<{to: number, weight: number}>>} Списки смежности.
 */
function createAdjacencyList(n, edges, directed = true) {
  const adjacency = Array.from({ length: n + 1 }, () => []);

  for (const [from, to, weight] of edges) {
    adjacency[from].push({ to, weight });

    if (!directed) {
      adjacency[to].push({ to: from, weight });
    }
  }

  return adjacency;
}
```

**Достоинства:** память `O(|V| + |E|)` - пропорционально реальному размеру
графа; перебор соседей вершины `v` стоит ровно `O(deg v)`, без просмотра
отсутствующих ребер.

**Недостаток:** проверка наличия конкретного ребра требует просмотра списка -
`O(deg v)`, а не `O(1)`.

Это представление используется по умолчанию: большинство реальных графов
разрежены, а обходы перебирают именно соседей.

### 6.2.3 Представление в виде списка ребер

Просто список всех ребер, без группировки по вершинам.

```
   {from: 1, to: 2, weight: 5}
   {from: 1, to: 4, weight: 10}
   {from: 2, to: 6, weight: 11}
   {from: 3, to: 2, weight: 2}
   {from: 4, to: 3, weight: 4}
   {from: 5, to: 3, weight: 2}
   {from: 5, to: 6, weight: 6}
   {from: 6, to: 5, weight: 4}
```

**Достоинства:** минимальная память `O(|E|)`, простейший ввод-вывод - именно в
таком виде граф обычно задается в условии задачи.

**Недостаток:** соседей конкретной вершины найти нельзя иначе как просмотром
всего списка за `O(|E|)`, поэтому обходы по такому представлению не делают.

Но есть алгоритмы, которым списки смежности не нужны вовсе, а нужен именно
перебор всех ребер: [алгоритм Крускала](mst.md#672-алгоритм-крускала)
сортирует ребра по весу, а [алгоритм Беллмана-Форда](shortest-paths.md#662-алгоритм-беллмана-форда)
многократно проходит по всем ребрам. Для них список ребер - естественная форма.

### Сравнение

| Операция | Матрица смежности | Списки смежности | Список ребер |
| --- | --- | --- | --- |
| Память | `Θ(\|V\|²)` | `Θ(\|V\| + \|E\|)` | `Θ(\|E\|)` |
| Проверить ребро `(u, v)` | **`O(1)`** | `O(deg u)` | `O(\|E\|)` |
| Перебрать соседей `u` | `O(\|V\|)` | **`O(deg u)`** | `O(\|E\|)` |
| Перебрать все ребра | `O(\|V\|²)` | `O(\|V\| + \|E\|)` | **`O(\|E\|)`** |
| Добавить ребро | `O(1)` | `O(1)` | `O(1)` |

Как выбирать:

- **разреженный граф, нужны обходы** - списки смежности; это выбор по умолчанию;
- **плотный граф или частые проверки «есть ли ребро»** - матрица смежности;
- **алгоритм работает со всеми ребрами сразу** - список ребер.

Сложность обхода прямо зависит от представления: DFS и BFS по спискам смежности
работают за `O(|V| + |E|)`, а по матрице - за `O(|V|²)`, потому что для каждой
вершины приходится просматривать всю строку.
