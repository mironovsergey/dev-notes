## 6.3 Поиск в глубину - DFS

**Поиск в глубину** (depth-first search) обходит граф, уходя от текущей вершины
как можно дальше и возвращаясь назад только тогда, когда идти больше некуда.

Это в точности [прямой обход дерева](../sprint-5/traversal.md#531-прямой-обход),
дополненный отметками о посещении: в графе, в отличие от дерева, в одну вершину
можно прийти несколькими путями, и без отметок обход зациклится.

### Цвета вершин

Состояние вершины удобно описывать тремя цветами:

| Цвет | Значение |
| --- | --- |
| **белый** | вершина не посещена |
| **серый** | вершина посещена, но обработка не завершена - рекурсия из нее еще не вернулась |
| **черный** | вершина обработана полностью, все ее соседи посещены |

Серые вершины - это в точности те, что лежат на текущем пути от корня обхода до
текущей вершины. Именно поэтому цвета несут больше информации, чем булев флаг
«посещена»: серый цвет позволяет [обнаруживать циклы](#633-поиск-цикла-и-времена-входа-выхода).

Цвета хранятся в массиве, индексированном номером вершины, - доступ за `O(1)`.
Список посещенных вершин расходовал бы меньше памяти в лучшем случае, но
проверка принадлежности стоила бы `O(|V|)`.

### 6.3.1 Алгоритм DFS

```js
const WHITE = 0;
const GRAY = 1;
const BLACK = 2;

/**
 * Обходит граф в глубину, посещая все вершины.
 *
 * Внешний цикл нужен для несвязных графов: обход из одной вершины достигает
 * только ее компоненты, поэтому запуск повторяется из каждой еще белой вершины.
 *
 * Время: O(|V| + |E|) при списках смежности. Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности, нумерация вершин с единицы.
 * @param {number} n Количество вершин.
 * @returns {number[]} Вершины в порядке посещения.
 */
function depthFirstSearch(adjacency, n) {
  const color = new Array(n + 1).fill(WHITE);
  const order = [];

  const visit = (v) => {
    color[v] = GRAY;
    order.push(v);

    for (const u of adjacency[v]) {
      if (color[u] === WHITE) {
        visit(u);
      }
    }

    color[v] = BLACK;
  };

  for (let v = 1; v <= n; v++) {
    if (color[v] === WHITE) {
      visit(v);
    }
  }

  return order;
}
```

#### Разбор сложности

Каждая вершина красится в серый ровно один раз, поэтому тело `visit`
выполняется `|V|` раз. Для каждой вершины перебираются ее исходящие ребра;
суммарно это `|E|` переборов при списках смежности. Итого `O(|V| + |E|)`.

В неориентированном графе каждое ребро встречается дважды - по разу с каждого
конца, - но `O(|V| + 2|E|) = O(|V| + |E|)`.

При хранении графа матрицей смежности перебор соседей одной вершины стоит
`O(|V|)`, и сложность вырастает до `O(|V|²)`.

Дополнительная память - массив цветов `O(|V|)` плюс стек вызовов глубиной до
`|V|`.

### 6.3.2 Алгоритм DFS без рекурсии

Глубина рекурсии равна длине самого длинного пути и в худшем случае составляет
`|V|`. При `|V| = 10⁵` это [переполнит стек вызовов](../sprint-2/stack-and-queue.md#применение-стек-вызовов),
поэтому обход разворачивают в цикл с явным стеком.

Сложность в том, что к каждой вершине нужно обратиться **дважды**: при входе
(покрасить в серый) и при выходе (покрасить в черный). Между этими моментами
алгоритм занят другими вершинами. Решение - класть вершину в стек дважды.

```js
/**
 * Обходит граф в глубину без рекурсии.
 *
 * Каждая вершина попадает в стек дважды: перед обработкой соседей и повторно,
 * чтобы алгоритм на обратном пути вспомнил, что ее пора закрывать. Извлеченная
 * белая вершина обрабатывается и возвращается в стек серой; извлеченная серая -
 * закрывается.
 *
 * Время: O(|V| + |E|). Память: O(|V| + |E|) на стек.
 *
 * @param {number[][]} adjacency Списки смежности.
 * @param {number} start Стартовая вершина.
 * @param {number[]} color Массив цветов вершин; изменяется на месте.
 * @returns {void}
 */
function depthFirstSearchIterative(adjacency, start, color) {
  const stack = [start];

  while (stack.length > 0) {
    const v = stack.pop();

    if (color[v] === WHITE) {
      color[v] = GRAY;

      // Возврат вершины в стек: она будет извлечена снова, когда все ее
      // поддерево обработано, и тогда ее нужно будет закрыть
      stack.push(v);

      for (const u of adjacency[v]) {
        if (color[u] === WHITE) {
          stack.push(u);
        }
      }
    } else if (color[v] === GRAY) {
      color[v] = BLACK;
    }
  }
}
```

Два момента, в которых легко ошибиться:

**Красить нужно при извлечении, а не при добавлении.** Если красить вершину в
момент помещения в стек, порядок обхода изменится и перестанет совпадать с
рекурсивным.

**Одна вершина может попасть в стек много раз.** Белая вершина добавляется
столько раз, сколько у нее непосещенных предшественников. Серой она станет
только один раз - при первом извлечении, и это будет последнее из добавленных
вхождений. Остальные вхождения извлекутся позже, обнаружат черный цвет и ничего
не сделают.

Отсюда и оценка памяти `O(|V| + |E|)`: размер стека ограничен не числом вершин,
а числом ребер.

Порядок обхода соседей в итеративной версии обратный рекурсивной: стек отдает
последнее добавленное. Если порядок важен, соседей добавляют в обратном
порядке.

### 6.3.3 Поиск цикла и времена входа-выхода

#### Поиск цикла

Ребро, ведущее в **серую** вершину, означает цикл. Серые вершины - это текущий
путь обхода, поэтому ребро в серую вершину замыкает этот путь в кольцо.

```
        (a)──→(b)──→(c)
               ↑      │
               │      ↓
              (e)←──(d)

   Обход: a → b → c → d → e. Из e есть ребро в b.
   Вершина b серая: она на текущем пути a-b-c-d-e. Значит, цикл b-c-d-e-b.
```

Ребро в **черную** вершину цикла не означает: та вершина уже полностью
обработана и на текущем пути не лежит.

```js
/**
 * Проверяет, содержит ли ориентированный граф цикл.
 *
 * Ребро в серую вершину замыкает текущий путь обхода и означает цикл. Ребро
 * в черную вершину цикла не означает: она уже обработана и на текущем пути
 * не лежит.
 *
 * Время: O(|V| + |E|). Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности.
 * @param {number} n Количество вершин.
 * @returns {boolean} true, если в графе есть цикл.
 */
function hasCycle(adjacency, n) {
  const color = new Array(n + 1).fill(WHITE);

  const visit = (v) => {
    color[v] = GRAY;

    for (const u of adjacency[v]) {
      if (color[u] === GRAY) {
        return true;
      }

      if (color[u] === WHITE && visit(u)) {
        return true;
      }
    }

    color[v] = BLACK;

    return false;
  };

  for (let v = 1; v <= n; v++) {
    if (color[v] === WHITE && visit(v)) {
      return true;
    }
  }

  return false;
}
```

Для **неориентированного** графа критерий другой: ребро в серую вершину, которая
является родителем текущей, - это то же самое ребро, по которому мы пришли, и
циклом не считается. Родителя нужно исключать явно.

#### Времена входа и выхода

Заведем счетчик `time`, увеличивающийся при каждом входе в вершину и каждом
выходе из нее, и два массива: `entry[v]` - момент покраски в серый, `leave[v]` -
момент покраски в черный.

```js
/**
 * Вычисляет времена входа и выхода для всех вершин графа.
 *
 * Время: O(|V| + |E|). Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности.
 * @param {number} n Количество вершин.
 * @returns {{entry: number[], leave: number[]}} Времена входа и выхода.
 */
function computeTimings(adjacency, n) {
  const color = new Array(n + 1).fill(WHITE);
  const entry = new Array(n + 1).fill(0);
  const leave = new Array(n + 1).fill(0);
  let time = 0;

  const visit = (v) => {
    entry[v] = ++time;
    color[v] = GRAY;

    for (const u of adjacency[v]) {
      if (color[u] === WHITE) {
        visit(u);
      }
    }

    leave[v] = ++time;
    color[v] = BLACK;
  };

  for (let v = 1; v <= n; v++) {
    if (color[v] === WHITE) {
      visit(v);
    }
  }

  return { entry, leave };
}
```

Времена образуют **правильную скобочную структуру**: интервалы
`[entry[v], leave[v]]` двух вершин либо не пересекаются, либо один вложен в
другой. Пересечение «внахлест» невозможно, потому что рекурсия закрывает вершины
в порядке, обратном открытию.

```
   a: [1 .......................... 10]
   b:    [2 ......... 7]
   c:       [3 ... 4]
   d:                    [8 ... 9]
```

Отсюда главное следствие:

> **`v` является предком `u` в дереве обхода ⟺ `entry[v] < entry[u]` и
> `leave[v] > leave[u]`**, то есть интервал `u` вложен в интервал `v`.

Проверка отношения «предок - потомок» за `O(1)` - это и есть то, ради чего
времена вычисляют. На ней построено решение задачи
[«Железные дороги»](railways.md), и там же разобрано, чего эта проверка **не**
означает.

### 6.3.4 Топологическая сортировка

**Топологическая сортировка** ориентированного графа - такой порядок вершин, в
котором каждое ребро ведет слева направо. Иначе говоря, если есть ребро
`u → v`, то `u` стоит раньше `v`.

Применение - упорядочивание задач с зависимостями: порядок сборки модулей,
план курса, последовательность установки пакетов.

**Топологическая сортировка существует тогда и только тогда, когда граф
ацикличен.** Цикл `a → b → a` требовал бы, чтобы `a` шла и раньше, и позже `b`.
Ациклический ориентированный граф называют DAG.

Порядок не единственный: независимые вершины можно расставить как угодно.

#### Алгоритм

Запускаем DFS и в момент **закрытия** вершины (покраски в черный) добавляем ее в
список. По окончании обхода список **разворачиваем**.

```js
/**
 * Возвращает топологический порядок вершин ациклического графа.
 *
 * Вершина закрывается только после всех своих потомков, поэтому в порядке
 * закрытия она стоит позже них - это обратный топологический порядок. Отсюда
 * разворот результата.
 *
 * Время: O(|V| + |E|). Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности ациклического графа.
 * @param {number} n Количество вершин.
 * @returns {number[]} Вершины в топологическом порядке.
 */
function topologicalSort(adjacency, n) {
  const color = new Array(n + 1).fill(WHITE);
  const order = [];

  const visit = (v) => {
    color[v] = GRAY;

    for (const u of adjacency[v]) {
      if (color[u] === WHITE) {
        visit(u);
      }
    }

    color[v] = BLACK;
    order.push(v);
  };

  for (let v = 1; v <= n; v++) {
    if (color[v] === WHITE) {
      visit(v);
    }
  }

  return order.reverse();
}
```

**Разворот обязателен.** Порядок закрытия - это обратный топологический порядок,
и про это легко забыть: вершина `v` закрывается только после того, как закрыты
все достижимые из нее вершины, значит, в списке закрытия она оказывается
**позже** своих потомков, а нужно раньше.

Если результат накапливать в стеке и читать извлечением, разворот получается
сам собой - но при накоплении в массиве его нужно сделать явно.

#### Почему это работает

Нужно показать, что для любого ребра `u → v` вершина `u` закрывается позже `v`.
В момент, когда DFS рассматривает ребро `u → v`, вершина `v` имеет один из трех
цветов:

- **белая** - обход сразу уходит в нее, и `v` закроется раньше, чем `u`;
- **черная** - `v` уже закрыта, а `u` еще нет;
- **серая** - означало бы цикл, но граф ацикличен, поэтому этот случай
  невозможен.

В обоих возможных случаях `leave[v] < leave[u]`, что и требовалось.

#### Пример

```
   (f)   (e)──→(a)──→(b)      (c)──→(d)
                              │
                              ↓
                             (g)──→(h)

   Порядок закрытия:  d, h, g, c, b, a, e, f
   После разворота:   f, e, a, b, c, g, h, d
```

Проверка: каждое ребро исходного графа в итоговой строке ведет слева направо.

## 6.4 Связность неориентированного графа

Задача: разбить неориентированный граф на компоненты связности и для каждой
вершины указать, к какой компоненте она относится.

Решение прямо следует из свойства DFS: **обход из вершины `v` посещает ровно ее
компоненту связности**, потому что достижимость в неориентированном графе
симметрична.

Алгоритм:

1. завести массив `component`, заполненный нулями (0 - «компонента не
   назначена») и счетчик компонент;
2. идти по вершинам по порядку;
3. встретив вершину с нулевой компонентой, увеличить счетчик и запустить из нее
   DFS, записывая всем посещенным вершинам текущий номер компоненты.

```js
/**
 * Разбивает неориентированный граф на компоненты связности.
 *
 * Номер компоненты играет роль цвета: он одновременно помечает вершину
 * посещенной и указывает, к какой компоненте она относится.
 *
 * Время: O(|V| + |E|). Память: O(|V|).
 *
 * @param {number[][]} adjacency Списки смежности неориентированного графа.
 * @param {number} n Количество вершин.
 * @returns {{component: number[], count: number}} Номера компонент для каждой
 *   вершины, нумерация с единицы, и общее количество компонент.
 */
function findConnectedComponents(adjacency, n) {
  const component = new Array(n + 1).fill(0);
  let count = 0;

  for (let start = 1; start <= n; start++) {
    if (component[start] !== 0) {
      continue;
    }

    count++;

    // Обход итеративный: глубина рекурсии на длинной цепочке достигала бы |V|
    const stack = [start];
    component[start] = count;

    while (stack.length > 0) {
      const v = stack.pop();

      for (const u of adjacency[v]) {
        if (component[u] === 0) {
          component[u] = count;
          stack.push(u);
        }
      }
    }
  }

  return { component, count };
}
```

Обход выполняется за `O(|V| + |E|)` суммарно по всем запускам: каждая вершина и
каждое ребро обрабатываются один раз, независимо от числа компонент.

Граф связен, если `count === 1`.

**Для ориентированного графа этот алгоритм неприменим.** Из вершины `a` может
быть путь в `b`, а обратного пути нет; тогда результат зависит от того, с какой
вершины начать. Понятие расщепляется на слабую и сильную связность, и для
сильных компонент нужны отдельные алгоритмы - Косарайю или Тарьяна.
