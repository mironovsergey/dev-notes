# Поиск в массиве

[← К содержанию спринта](README.md)

Задача: определить, есть ли значение `target` в массиве `numbers`, и если есть
- вернуть его индекс. Решения принципиально различаются в зависимости от того,
упорядочен массив или нет.

---

## 1.6 Линейный поиск

Массив просматривается с начала, каждый элемент сравнивается с искомым.
Никаких требований к порядку элементов нет.

```js
/**
 * Возвращает индекс первого вхождения значения в массив.
 *
 * Время: O(n) в худшем случае, O(1) в лучшем. Память: O(1).
 *
 * @param {number[]} numbers Массив, в котором выполняется поиск.
 * @param {number} target Искомое значение.
 * @returns {number} Индекс первого вхождения либо -1, если значение отсутствует.
 */
function linearSearch(numbers, target) {
  for (let i = 0; i < numbers.length; i++) {
    if (numbers[i] === target) {
      return i;
    }
  }

  return -1;
}
```

### Разбор сложности

Тело цикла выполняет фиксированное число операций, поэтому стоимость поиска
определяется числом итераций:

- **лучший случай** - искомое значение стоит первым: одна итерация, `O(1)`;
- **худший случай** - значение отсутствует либо стоит последним: `n` итераций,
  `O(n)`;
- **средний случай** - при равновероятном положении значения в среднем `n / 2`
  итераций, что также `O(n)`.

Дополнительная память - единственная переменная-счетчик, `O(1)`.

### Когда применяется

Линейный поиск - единственный вариант для неупорядоченных данных. Он же
оказывается разумным выбором при малых `n`: константа у него минимальна, а
доступ к памяти последовательный, что хорошо согласуется с кэшем процессора.

Если поиск в одном и том же массиве выполняется многократно, линейный проход
каждый раз - ошибка. Массив либо [сортируют](../sprint-3/sorting.md#32-алгоритмы-сортировки)
один раз за `O(n log n)` и дальше применяют бинарный поиск, либо строят
[хеш-таблицу](../sprint-4/hash-tables.md#41-хеш-таблица-хеш-функция-свойства-хеш-функций)
и получают `O(1)` в среднем на запрос.

## 1.7 Бинарный поиск

Бинарный поиск применим к массиву, **упорядоченному по неубыванию**. Он
сравнивает искомое значение со средним элементом и по результату сравнения
отбрасывает половину диапазона: если средний элемент меньше искомого, вся
левая половина заведомо меньше и рассматривать ее не нужно.

Каждый шаг уменьшает диапазон вдвое, поэтому число шагов логарифмическое.

### Инвариант

Реализация ведется на полуинтервале `[left, right)`: левая граница включена,
правая исключена. Инвариант цикла - **если искомое значение присутствует в
массиве, оно лежит внутри `[left, right)`**.

Полуинтервал предпочтительнее отрезка `[left, right]`, потому что избавляет от
рассогласований на единицу: `right` изначально равен `numbers.length`, а длина
текущего диапазона всегда равна `right − left`. Цикл завершается, когда
диапазон пуст, то есть при `left === right`.

```js
/**
 * Возвращает индекс значения в отсортированном по неубыванию массиве.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {number[]} numbers Массив, отсортированный по неубыванию.
 * @param {number} target Искомое значение.
 * @returns {number} Индекс одного из вхождений либо -1, если значение отсутствует.
 */
function binarySearch(numbers, target) {
  // Инвариант: искомое значение, если оно есть, лежит в полуинтервале [left, right)
  let left = 0;
  let right = numbers.length;

  while (left < right) {
    const middle = left + Math.floor((right - left) / 2);

    if (numbers[middle] === target) {
      return middle;
    }

    if (numbers[middle] < target) {
      // Весь диапазон [left, middle] меньше искомого - отбрасывается
      left = middle + 1;
    } else {
      // Весь диапазон [middle, right) больше искомого - отбрасывается
      right = middle;
    }
  }

  return -1;
}
```

### Трассировка

Массив `[1, 3, 5, 7, 9, 11]`, искомое значение `9`:

| Шаг | `left` | `right` | `middle` | `numbers[middle]` | Действие |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 7 | `7 < 9` → `left = 4` |
| 2 | 4 | 6 | 5 | 11 | `11 > 9` → `right = 5` |
| 3 | 4 | 5 | 4 | 9 | найдено, возврат `4` |

Шесть элементов просмотрены за три сравнения вместо пяти у линейного поиска.

### Разбор сложности

После `k`-го шага длина диапазона не превышает `n / 2ᵏ`. Цикл завершается,
когда диапазон становится пустым, то есть при `n / 2ᵏ < 1`, откуда
`k > log₂ n`. Число итераций - `⌈log₂(n + 1)⌉`, сложность - `O(log n)`.

Практически это означает, что в массиве из миллиона элементов ответ находится
не более чем за 20 сравнений, а в массиве из миллиарда - не более чем за 30.
Разрыв с линейным поиском растет вместе с `n`: при `n = 100` выигрыш
пятнадцатикратный, при `n = 10⁶` - пятидесятитысячекратный.

Дополнительная память - три переменные, `O(1)`. Рекурсивная запись того же
алгоритма расходует `O(log n)` памяти на стек вызовов, поэтому итеративная
версия предпочтительнее.

### Вычисление середины

Выражение `left + Math.floor((right - left) / 2)` вместо более очевидного
`Math.floor((left + right) / 2)` - устоявшаяся идиома, защищающая от
переполнения при сложении двух больших индексов. В JavaScript переполнение
недостижимо: длина массива ограничена значением `2³² − 1`, а целые числа точны
до `2⁵³`. Но в языках с 32-битным типом индекса это реальная ошибка, поэтому
идиому имеет смысл использовать всегда.

Округление вниз обязательно: без него `middle` окажется дробным и обращение
`numbers[middle]` вернет `undefined`.

### Поиск левой границы

В задачах чаще требуется не факт наличия элемента, а **позиция**: куда
вставить значение, сколько элементов меньше заданного, где начинается серия
одинаковых значений. Обычный бинарный поиск при дубликатах возвращает
произвольное из вхождений и для этого не годится.

Нужная модификация называется поиском нижней границы. Она возвращает индекс
**первого** элемента, не меньшего `target`:

```js
/**
 * Возвращает индекс первого элемента, не меньшего заданного значения.
 *
 * Если все элементы меньше target, возвращается длина массива.
 * Время: O(log n). Память: O(1).
 *
 * @param {number[]} numbers Массив, отсортированный по неубыванию.
 * @param {number} target Искомое значение.
 * @returns {number} Индекс первого элемента, для которого numbers[i] >= target.
 */
function lowerBound(numbers, target) {
  let left = 0;
  let right = numbers.length;

  while (left < right) {
    const middle = left + Math.floor((right - left) / 2);

    if (numbers[middle] < target) {
      left = middle + 1;
    } else {
      // middle может оказаться ответом, поэтому он остается в диапазоне
      right = middle;
    }
  }

  return left;
}
```

Отличие от `binarySearch` только в отсутствии досрочного возврата: цикл
доводится до конца, и `left` останавливается точно на границе между
элементами, меньшими `target`, и остальными.

Что дает эта функция:

- проверка наличия - `lowerBound(numbers, target) < numbers.length &&
  numbers[lowerBound(numbers, target)] === target`;
- количество элементов, строго меньших `target`, - само значение `lowerBound`;
- количество вхождений `target` - `upperBound(target) − lowerBound(target)`,
  где `upperBound` получается заменой условия `<` на `<=`;
- позиция для вставки с сохранением порядка - снова `lowerBound`.

### Типичные ошибки

- **Массив не отсортирован.** Бинарный поиск не сообщает об ошибке, он просто
  возвращает неверный результат. Сортировка стоит `O(n log n)`, поэтому ради
  одного поиска сортировать бессмысленно - окупается от нескольких запросов.
- **Смешение границ.** Полуинтервал и отрезок требуют разных условий цикла
  (`left < right` против `left <= right`) и разных присваиваний. Смешивать их
  нельзя.
- **Зацикливание.** Если при `numbers[middle] < target` написать `left =
  middle` вместо `left = middle + 1`, диапазон длины 1 перестает сокращаться и
  цикл не завершится.

### Поиск по ответу

Бинарный поиск применим не только к массивам. Если для задачи существует
монотонный предикат - такой, что при малых значениях параметра он ложен, а
начиная с некоторого значения истинен всегда, - то границу переключения можно
найти тем же делением пополам, вычисляя предикат вместо чтения элемента.

Схема сохраняется полностью, меняется только источник данных для сравнения.
Этот прием называется бинарным поиском по ответу и превращает подбор
параметра за `O(n)` в подбор за `O(log n)` проверок.

Рекурсивная запись того же алгоритма и разбор того, почему на практике
предпочитают цикл, - в
[третьем спринте](../sprint-3/recursion.md#312-рекурсивный-бинарный-поиск).
