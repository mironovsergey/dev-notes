# Сложность алгоритмов

[← К содержанию спринта](README.md)

Один и тот же результат можно получить разными алгоритмами, и выбирать между
ними по времени работы на конкретной машине бессмысленно: замер зависит от
процессора, компилятора и загруженности системы. Поэтому алгоритмы сравнивают
по тому, **как быстро растет потребление ресурса при росте объема входных
данных**. Ресурсов два - память и процессорное время, им соответствуют
пространственная и временная сложность.

Размер входных данных обозначается `n`. Что именно считать размером, зависит от
задачи: для массива это количество элементов, для строки - количество символов,
для графа - количество вершин и ребер (тогда параметров два), для числа `n` в
задаче о факторизации - само значение `n`.

---

## 1.1 Пространственная сложность

**Пространственная сложность** - зависимость объема потребляемой памяти от
размера входных данных.

Учитывается **дополнительная** память: та, которую алгоритм выделяет сверх
самих входных данных. Вход обычно не включают в оценку, потому что его размер
задан условием и от алгоритма не зависит. Если алгоритму нужна собственная
копия входа, вот она уже считается.

В оценку входят три источника:

- переменные и структуры данных, созданные алгоритмом;
- стек вызовов при рекурсии - каждый незавершенный вызов хранит свои
  аргументы и локальные переменные;
- память, выделяемая библиотечными функциями (например, `split` создает новый
  массив).

### Константная память - `O(1)`

Алгоритм хранит фиксированное число значений, не зависящее от `n`.

```js
/**
 * Возвращает сумму элементов массива.
 *
 * Время: O(n). Память: O(1) - счетчик и аккумулятор не зависят от длины входа.
 *
 * @param {number[]} numbers Исходный массив.
 * @returns {number} Сумма всех элементов.
 */
function sum(numbers) {
  let total = 0;

  for (let i = 0; i < numbers.length; i++) {
    total += numbers[i];
  }

  return total;
}
```

Массив `numbers` в оценку не входит: он пришел извне, алгоритм его только
читает.

### Линейная память - `O(n)`

Алгоритм создает структуру, размер которой пропорционален входу.

```js
/**
 * Возвращает массив квадратов элементов исходного массива.
 *
 * Время: O(n). Память: O(n) - результирующий массив той же длины, что и вход.
 *
 * @param {number[]} numbers Исходный массив.
 * @returns {number[]} Массив квадратов.
 */
function squares(numbers) {
  const result = new Array(numbers.length);

  for (let i = 0; i < numbers.length; i++) {
    result[i] = numbers[i] * numbers[i];
  }

  return result;
}
```

### Квадратичная память - `O(n²)`

Алгоритм строит таблицу «каждый с каждым»: например, матрицу попарных
расстояний между `n` объектами. Такая таблица содержит `n²` ячеек, и уже при
`n = 10 000` это `10⁸` чисел - сотни мегабайт. Квадратичная память упирается в
лимит гораздо раньше, чем квадратичное время упирается в таймаут.

### Компромисс «время против памяти»

Память часто обменивается на скорость. Классический пример - [решето
Эратосфена](primes.md#182-решето-эратосфена): оно тратит `O(n)` памяти на
массив пометок и за счет этого находит все простые числа до `n` намного
быстрее, чем проверка каждого числа по отдельности, которой памяти почти не
нужно.

Обратное направление тоже работает: если памяти не хватает, часть уже
вычисленных значений можно не хранить, а пересчитывать заново.

## 1.2 Временная сложность

**Временная сложность** - зависимость количества выполняемых операций от
размера входных данных.

Считается не время в секундах, а число **элементарных операций**. Элементарной
считается операция, время выполнения которой не зависит от `n`: арифметическое
действие, сравнение, присваивание, обращение к элементу массива по индексу.
Каждая такая операция стоит `O(1)`.

Переход от секунд к операциям и делает оценку переносимой. Машина, которая
работает в десять раз быстрее, выполнит тот же алгоритм в десять раз быстрее -
но это постоянный множитель, он одинаков для всех алгоритмов и потому в оценке
не участвует. А вот разница между `n` и `n²` операциями от машины не зависит и
при росте `n` перекрывает любой постоянный множитель.

### Осторожно с «элементарностью»

Главный источник ошибок в оценке - вызовы, которые выглядят как одна операция,
но таковой не являются:

| Вызов | Реальная стоимость |
| --- | --- |
| `array.includes(x)`, `array.indexOf(x)` | `O(n)` |
| `array.push(x)` | `O(1)` амортизированно |
| `array.unshift(x)`, `array.shift()` | `O(n)` - сдвигаются все элементы |
| `array.slice()`, `array.concat()` | `O(n)` |
| `array.sort()` | `O(n log n)` |
| `string + string` | `O(n)` - строки неизменяемы, создается новая |
| `set.has(x)`, `map.get(x)` | `O(1)` в среднем |

Строка `if (array.includes(x))` внутри цикла по `n` элементам дает не `O(n)`, а
`O(n²)`.

### Пример разбора

```js
// visitors - массив номеров пассажиров: каждый пассажир проехал столько раз,
// сколько раз его номер встречается в массиве.
const visitors = [0, 2, 3, 2, 0, 4, 1, 1, 2];

/**
 * Возвращает номер пассажира, совершившего наибольшее число поездок.
 *
 * Время: O(n + maxId). Память: O(maxId).
 *
 * @param {number[]} visitors Номера пассажиров, каждый в диапазоне [0, maxId].
 * @param {number} maxId Максимально возможный номер пассажира.
 * @returns {number} Номер самого частого пассажира.
 */
function findMostFrequentVisitor(visitors, maxId) {
  // Счетчик поездок для каждого номера: индекс - номер, значение - количество
  const entriesByVisitor = new Array(maxId + 1).fill(0);
  let bestVisitor = 0;

  for (let i = 0; i < visitors.length; i++) {
    const visitor = visitors[i];
    entriesByVisitor[visitor] += 1;

    // Лидер обновляется сразу, поэтому второй проход по счетчикам не нужен
    if (entriesByVisitor[visitor] > entriesByVisitor[bestVisitor]) {
      bestVisitor = visitor;
    }
  }

  return bestVisitor;
}
```

Разбор по строкам:

- создание массива счетчиков - `maxId + 1` операций;
- цикл выполняется `n = visitors.length` раз;
- тело цикла - чтение по индексу, инкремент, сравнение, возможное
  присваивание - фиксированное число элементарных операций, то есть `O(1)`.

Итого `maxId + 1 + n · O(1)`, что дает `O(n + maxId)`.

Оценка зависит от **двух** параметров, и это не редкость. Если по условию
номера пассажиров ограничены небольшой константой, слагаемое `maxId`
отбрасывается и остается `O(n)`. Если же номера могут достигать `10⁹`, массив
счетчиков выделять нельзя - вместо него нужен `Map`, и сложность становится
`O(n)` по времени при `O(k)` памяти, где `k` - число различных номеров.

## 1.3 Как оценивать сложность

Оценка строится снизу вверх: стоимость элементарных операций складывается в
стоимость блоков, блоки - в стоимость функции.

### Правило суммы

Последовательные фрагменты кода складываются, и в сумме остается только
старшее слагаемое:

```js
// O(n) - первый проход
for (let i = 0; i < n; i++) { /* ... */ }

// O(n²) - второй проход
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) { /* ... */ }
}
```

`O(n) + O(n²) = O(n²)`. При больших `n` вклад линейной части пренебрежимо мал.

Слагаемые нельзя отбрасывать, если они зависят от **разных** параметров:
`O(n + m)` не сворачивается в `O(n)`, пока не известно, что `m ≤ n`.

### Правило произведения

Вложенные конструкции перемножаются:

```js
// Внешний цикл - n итераций, внутренний - m, тело - O(1)
for (let i = 0; i < n; i++) {
  for (let j = 0; j < m; j++) { /* ... */ }
}
```

Итого `O(n · m)`, при `m = n` - `O(n²)`.

### Отбрасывание констант

Постоянные множители не учитываются: `O(3n)` записывается как `O(n)`, `O(n/2)`
- тоже `O(n)`. Три прохода по массиву и один проход относятся к одному классу
сложности.

Это не значит, что константы не важны на практике - алгоритм с константой 100
может проигрывать алгоритму с константой 2. Но принадлежность к классу
сложности они не меняют, а при росте `n` разница классов перекрывает любую
константу.

### Треугольный цикл

Внутренний цикл, зависящий от счетчика внешнего, - по-прежнему `O(n²)`:

```js
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) { /* ... */ }
}
```

Тело выполняется `(n − 1) + (n − 2) + … + 1 = n(n − 1) / 2` раз. Константа
`1/2` отбрасывается, остается `O(n²)`.

### Цикл с умножением счетчика

```js
for (let i = 1; i < n; i *= 2) { /* ... */ }
```

Счетчик принимает значения `1, 2, 4, 8, …`, то есть `2⁰, 2¹, 2², …`. Цикл
останавливается, когда `2ᵏ ≥ n`, откуда `k = log₂ n`. Сложность - `O(log n)`.

То же верно и для деления: любой цикл, который на каждом шаге уменьшает
рабочий диапазон в постоянное число раз, логарифмический. На этом построен
[бинарный поиск](search.md#17-бинарный-поиск).

Основание логарифма в асимптотике не указывают: логарифмы по разным
основаниям отличаются постоянным множителем (`log₂ n = log₁₀ n / log₁₀ 2`), а
постоянные множители отбрасываются.

### Рекурсия

Сложность рекурсивного алгоритма - это число вызовов, умноженное на стоимость
одного вызова без учета рекурсивных обращений. Дополнительно учитывается
глубина рекурсии: она определяет пространственную сложность, потому что каждый
незавершенный вызов занимает кадр в стеке.

Рекурсивный бинарный поиск делает `log n` вызовов по `O(1)` работы в каждом:
`O(log n)` времени и `O(log n)` памяти на стек - в отличие от итеративной
версии, которой хватает `O(1)`.

### Амортизированная сложность

Иногда отдельная операция дорога, но дорогой она бывает редко, и **средняя**
стоимость по длинной последовательности операций оказывается низкой. Такая
оценка называется амортизированной.

Пример - `push` в [динамический массив](../sprint-2/arrays.md#212-реаллокация-в-динамических-массивах).
Обычно это запись в свободную ячейку,
`O(1)`. Когда место заканчивается, выделяется новый буфер вдвое большего
размера и все элементы копируются - `O(n)`. Но удвоение происходит тем реже,
чем больше массив, и суммарная стоимость `n` вставок составляет `O(n)`, то
есть `O(1)` на операцию амортизированно.

Амортизированная оценка отвечает на вопрос «сколько стоят `n` операций
подряд», а не «сколько стоит одна конкретная операция».

### Лучший, средний и худший случай

При одном и том же `n` алгоритм может отработать по-разному в зависимости от
самих данных. Рассмотрим [линейный поиск](search.md#16-линейный-поиск):

- **лучший случай** - элемент стоит первым, одна итерация, `O(1)`;
- **худший случай** - элемента нет вовсе, `n` итераций, `O(n)`;
- **средний случай** - при равновероятном расположении элемента `n / 2`
  итераций, что тоже `O(n)`.

По умолчанию под сложностью понимают **худший случай**: он дает гарантию, а
средний требует предположений о распределении входных данных и на
состязательных тестах не выполняется.

Разница между случаями бывает принципиальной. У
[быстрой сортировки](../sprint-3/sorting.md#325-быстрая-сортировка) средний
случай `O(n log n)`, а худший - `O(n²)`, и на практике ее выбирают именно из-за
среднего.

### Чему равен допустимый предел

Ориентир: современный процессор выполняет порядка `10⁸`–`10⁹` элементарных
операций в секунду. При типичном лимите в 1–2 секунды это дает ориентировочное
соответствие между ограничением на `n` из условия задачи и допустимой
сложностью:

| Ограничение на `n` | Допустимая сложность |
| --- | --- |
| `n ≤ 10⁶`–`10⁷` | `O(n)`, `O(n log n)` |
| `n ≤ 10⁴` | `O(n²)` |
| `n ≤ 500` | `O(n³)` |
| `n ≤ 25` | `O(2ⁿ)` |
| `n ≤ 10` | `O(n!)` |

Ограничения из условия - это подсказка о том, какой сложности решение
ожидается.

## 1.4 Типы временных сложностей

Классы перечислены в порядке возрастания скорости роста.

### 1.4.1 Константная - `O(1)`

Число операций не зависит от размера входа.

```js
/**
 * Возвращает первый элемент массива.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {number[]} numbers Исходный массив.
 * @returns {number|undefined} Первый элемент либо undefined для пустого массива.
 */
function first(numbers) {
  return numbers[0];
}
```

Сюда же относятся: обращение к элементу массива по индексу, арифметические
операции, вставка и поиск в
[хеш-таблице](../sprint-4/hash-tables.md#41-хеш-таблица-хеш-функция-свойства-хеш-функций)
(в среднем), добавление и удаление на
[вершине стека](../sprint-2/stack-and-queue.md#23-стек).

`O(1)` не означает «мгновенно» - оно означает «одинаково при любом `n`».
Алгоритм, всегда выполняющий миллион операций, тоже `O(1)`.

### 1.4.2 Логарифмическая - `O(log n)`

На каждом шаге объем оставшейся работы уменьшается в постоянное число раз.

```js
/**
 * Возвращает количество двоичных разрядов положительного числа.
 *
 * Время: O(log n). Память: O(1).
 *
 * @param {number} n Положительное целое число.
 * @returns {number} Количество разрядов в двоичной записи.
 */
function bitLength(n) {
  let length = 0;

  while (n > 0) {
    n = Math.floor(n / 2);
    length++;
  }

  return length;
}
```

Рост крайне медленный: удвоение `n` добавляет к работе **одну** итерацию.
`log₂` от миллиона - примерно 20, от миллиарда - примерно 30.

Представители: бинарный поиск, поиск в
[сбалансированном дереве](../sprint-5/balanced.md#54-сбалансированные-деревья-поиска),
вставка в [кучу](../sprint-5/priority-queue.md#552-очередь-с-приоритетом).

> Отдельно стоит запомнить промежуточный класс **`O(n log n)`** -
> линеарифмический. Он не входит в перечень выше, но встречается постоянно: это
> сложность [сортировки слиянием](../sprint-3/sorting.md#324-сортировка-слиянием),
> [быстрой сортировки](../sprint-3/sorting.md#325-быстрая-сортировка) в среднем и
> [пирамидальной сортировки](../sprint-5/heap.md#561-пирамидальная-сортировка).
> По скорости роста он лишь немного хуже линейного и радикально лучше
> квадратичного.

### 1.4.3 Линейная - `O(n)`

Каждый элемент входа обрабатывается фиксированное число раз.

```js
/**
 * Возвращает максимальный элемент непустого массива.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number[]} numbers Непустой массив чисел.
 * @returns {number} Максимальное значение.
 */
function max(numbers) {
  let result = numbers[0];

  for (let i = 1; i < numbers.length; i++) {
    if (numbers[i] > result) {
      result = numbers[i];
    }
  }

  return result;
}
```

Линейная сложность - нижняя граница для любой задачи, где нужно хотя бы
прочитать весь вход.

Представители: линейный поиск, подсчет суммы,
[сортировка подсчетом](../sprint-3/sorting.md#326-сортировка-подсчетом),
[решето Эратосфена](primes.md#182-решето-эратосфена) (с точностью до
`log log n`).

### 1.4.4 Полиномиальная - `O(nᵏ)`

Число операций - многочлен от `n` фиксированной степени `k ≥ 1`. Линейная
сложность формально тоже полиномиальная, но обычно под полиномиальными
понимают степени начиная с квадратичной.

**Квадратичная `O(n²)`** - два вложенных цикла по входу. Типична для
перебора всех пар элементов и для простых сортировок:

```js
/**
 * Проверяет, есть ли в массиве два одинаковых элемента.
 *
 * Время: O(n²). Память: O(1).
 *
 * @param {number[]} numbers Исходный массив.
 * @returns {boolean} true, если найдена хотя бы одна пара равных элементов.
 */
function hasDuplicates(numbers) {
  for (let i = 0; i < numbers.length; i++) {
    for (let j = i + 1; j < numbers.length; j++) {
      if (numbers[i] === numbers[j]) {
        return true;
      }
    }
  }

  return false;
}
```

**Кубическая `O(n³)`** - три вложенных цикла: перебор всех троек, наивное
умножение матриц, алгоритм Флойда - Уоршелла.

Полиномиальные алгоритмы считаются практически применимыми, но граница
проходит по величине `n`: `O(n²)` приемлемо при `n ≤ 10⁴` и безнадежно при
`n = 10⁶`.

### 1.4.5 Экспоненциальная - `O(2ⁿ)`

Число операций удваивается с добавлением одного элемента ко входу.

```js
/**
 * Возвращает все подмножества исходного множества.
 *
 * Время: O(n · 2ⁿ). Память: O(n · 2ⁿ).
 *
 * @param {number[]} items Элементы исходного множества.
 * @returns {number[][]} Все 2ⁿ подмножеств.
 */
function subsets(items) {
  const result = [[]];

  for (const item of items) {
    const currentLength = result.length;

    // Каждое уже построенное подмножество порождает еще одно - с новым элементом
    for (let i = 0; i < currentLength; i++) {
      result.push([...result[i], item]);
    }
  }

  return result;
}
```

`2⁶⁴` превышает `10¹⁹` - такой перебор не завершится за время жизни машины.
Экспоненциальные алгоритмы применимы только при малых `n` (порядка 20–30) и
служат отправной точкой: обычно от них уходят через динамическое
программирование или жадные стратегии.

Представители: перебор всех подмножеств,
[наивное решение задачи о рюкзаке](../sprint-7/knapsack.md#722-задача-о-рюкзаке),
[рекурсивное вычисление чисел Фибоначчи без запоминания](../sprint-7/dynamic.md#от-перебора-к-динамике).

### 1.4.6 Факториальная - `O(n!)`

Число операций равно числу перестановок входа. Самый быстрорастущий из
практически встречающихся классов: `10! ≈ 3,6 · 10⁶`, но уже
`20! ≈ 2,4 · 10¹⁸`.

Представители: перебор всех перестановок, решение задачи коммивояжера полным
перебором маршрутов.

Факториальный алгоритм пригоден только для `n ≤ 10`–`12` и почти всегда
означает, что задачу нужно решать иначе.

### Сравнение роста

Число операций при разных `n` (прочерк - величина, не имеющая физического
смысла):

| Сложность | `n = 10` | `n = 100` | `n = 1000` | `n = 10⁶` |
| --- | --- | --- | --- | --- |
| `O(1)` | 1 | 1 | 1 | 1 |
| `O(log n)` | 3 | 7 | 10 | 20 |
| `O(n)` | 10 | 100 | 1 000 | 10⁶ |
| `O(n log n)` | 33 | 664 | ~10⁴ | ~2 · 10⁷ |
| `O(n²)` | 100 | 10 000 | 10⁶ | 10¹² |
| `O(n³)` | 1 000 | 10⁶ | 10⁹ | 10¹⁸ |
| `O(2ⁿ)` | 1 024 | ~10³⁰ | - | - |
| `O(n!)` | ~3,6 · 10⁶ | ~10¹⁵⁸ | - | - |

Ключевое наблюдение: до `n = 10` разница между классами почти незаметна, а к
`n = 10⁶` она составляет уже десятки порядков. Асимптотика описывает поведение
именно при больших `n`.

## 1.5 Асимптотическая нотация

Асимптотическая нотация - формальный язык для записи скорости роста функций.
Она отвечает на вопрос «как ведет себя `f(n)` при `n → ∞`», игнорируя
постоянные множители и поведение на малых `n`.

Пусть `f(n)` - точное число операций алгоритма, а `g(n)` - простая функция
сравнения (`n`, `n²`, `log n` и подобные).

### 1.5.1 O-большое - верхняя граница

`f(n) = O(g(n))`, если существуют константы `c > 0` и `n₀ ≥ 0` такие, что

```
0 ≤ f(n) ≤ c · g(n)   для всех n ≥ n₀
```

Читается: начиная с некоторого размера входа `n₀`, функция `f` растет **не
быстрее**, чем `g`, с точностью до постоянного множителя.

Пример. Для `f(n) = 3n² + 5n + 7` возьмем `g(n) = n²`, `c = 15`, `n₀ = 1`:
при `n ≥ 1` верно `3n² + 5n + 7 ≤ 3n² + 5n² + 7n² = 15n²`. Значит,
`f(n) = O(n²)`.

`O` задает **верхнюю** оценку, поэтому та же функция удовлетворяет и
`f(n) = O(n³)`, и `f(n) = O(2ⁿ)`. Формально это корректные утверждения, просто
неинформативные. Отсюда типичная ошибка: сказать про линейный алгоритм, что он
`O(n²)`, - придраться не к чему, но оценка бесполезна. Подразумевается, что
называется **наименьшая известная** верхняя граница.

### 1.5.2 Θ-большое - точная граница

`f(n) = Θ(g(n))`, если существуют константы `c₁ > 0`, `c₂ > 0` и `n₀ ≥ 0`
такие, что

```
0 ≤ c₁ · g(n) ≤ f(n) ≤ c₂ · g(n)   для всех n ≥ n₀
```

Функция `f` зажата между двумя копиями `g` и растет **ровно так же**, как `g`.
Это самая точная из трех записей: `Θ(g(n))` означает одновременно
`O(g(n))` и `Ω(g(n))`.

Для `f(n) = 3n² + 5n + 7` верно `f(n) = Θ(n²)`, но неверно `f(n) = Θ(n³)`:
снизу `n³` уже не ограничивает `f`.

### 1.5.3 Ω-большое - нижняя граница

`f(n) = Ω(g(n))`, если существуют константы `c > 0` и `n₀ ≥ 0` такие, что

```
0 ≤ c · g(n) ≤ f(n)   для всех n ≥ n₀
```

Функция `f` растет **не медленнее**, чем `g`.

`Ω` применяют, когда нужно доказать, что задачу нельзя решить быстрее
определенного предела. Например, любая сортировка, основанная на сравнении
элементов, требует `Ω(n log n)` сравнений в худшем случае - это свойство самой
задачи, а не конкретного алгоритма.

### Почему на практике пишут O

Формально корректнее было бы говорить «бинарный поиск работает за `Θ(log n)`»,
но общепринято писать `O(log n)`. Причины две:

1. Практический интерес представляет гарантия сверху: важно, что алгоритм **не
   медленнее** заявленного.
2. У многих алгоритмов лучший и худший случаи различаются, и единой точной
   границы `Θ` для них не существует. У линейного поиска худший случай `O(n)`,
   лучший - `O(1)`; сказать «линейный поиск - `Θ(n)`» без уточнения «в худшем
   случае» нельзя.

Договоренность такова: если не оговорено иное, `O` относится к худшему случаю
и подразумевается наименьшей известной верхней границей.

### Сводка

| Запись | Смысл | Аналогия |
| --- | --- | --- |
| `f = O(g)` | `f` растет не быстрее `g` | `≤` |
| `f = Θ(g)` | `f` растет так же, как `g` | `=` |
| `f = Ω(g)` | `f` растет не медленнее `g` | `≥` |
