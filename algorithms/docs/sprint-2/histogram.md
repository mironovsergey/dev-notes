## 2.5 Задача про гистограмму

**Условие.** Дана гистограмма из `n` столбцов. Столбец с номером `i` имеет
высоту `heights[i]` и ширину 1, все столбцы стоят вплотную. Найти площадь
наибольшего прямоугольника, целиком помещающегося внутри гистограммы.

Прямоугольник не обязан совпадать со столбцом: он может накрывать несколько
соседних столбцов, но его высота тогда ограничена **самым низким** из них.

```
  heights = [2, 1, 5, 6, 2, 3]

  6            █
  5         █  █
  4         █  █
  3         █  █        █
  2   █     █  █  █     █
  1   █  █  █  █  █     █
      ─────────────────────
      2  1  5  6  2  3

  Наибольший прямоугольник - столбцы 2 и 3 высотой 5: площадь 5 × 2 = 10
```

Задача - тот случай, когда стек дает переход от квадратичного решения к
линейному, и потому разбирается сразу после стека.

### Наивное решение

Для каждой пары границ `(left, right)` высота прямоугольника равна минимуму на
этом отрезке. Перебираем левую границу и расширяем правую, попутно поддерживая
минимум:

```js
/**
 * Возвращает площадь наибольшего прямоугольника в гистограмме
 * перебором всех пар границ.
 *
 * Время: O(n²). Память: O(1).
 *
 * @param {number[]} heights Высоты столбцов.
 * @returns {number} Максимальная площадь.
 */
function largestRectangleNaive(heights) {
  let best = 0;

  for (let left = 0; left < heights.length; left++) {
    let minHeight = heights[left];

    for (let right = left; right < heights.length; right++) {
      minHeight = Math.min(minHeight, heights[right]);
      best = Math.max(best, minHeight * (right - left + 1));
    }
  }

  return best;
}
```

Решение верное, но при `n = 10⁵` требует `10¹⁰` операций - за лимит не
уложится.

### Переформулировка

Ключ к линейному решению - сменить точку зрения. Вместо перебора границ
переберем **высоты**: каждый прямоугольник максимальной площади можно считать
ограниченным сверху каким-то одним столбцом.

Зафиксируем столбец `i` и спросим: насколько широкий прямоугольник высоты
`heights[i]` можно построить? Он тянется влево и вправо, пока соседние столбцы
не ниже `heights[i]`. Значит, для каждого `i` нужно найти:

- `left(i)` - ближайший слева столбец **строго ниже** `heights[i]`;
- `right(i)` - ближайший справа столбец **строго ниже** `heights[i]`.

Тогда ширина равна `right(i) − left(i) − 1`, а площадь - `heights[i]` на эту
ширину. Ответ - максимум по всем `i`.

Задача свелась к поиску ближайшего меньшего элемента слева и справа. Именно ее
и решает стек за один проход.

### Монотонный стек

В стеке хранятся **индексы** столбцов, высоты которых строго возрастают снизу
вверх. Такой стек называют монотонным.

Обрабатывая столбец `i`, снимаем со стека все столбцы, которые не ниже
`heights[i]`: для каждого из них столбец `i` и есть ближайший справа меньший,
то есть его прямоугольник закончился и его площадь можно посчитать
окончательно. Левая граница при этом - новая вершина стека после снятия.

```js
/**
 * Возвращает площадь наибольшего прямоугольника в гистограмме.
 *
 * В стеке хранятся индексы столбцов с возрастающими высотами. Столбец
 * снимается со стека в тот момент, когда встречен столбец не выше него: тогда
 * границы прямоугольника, ограниченного сверху снятым столбцом, уже известны.
 *
 * Время: O(n). Память: O(n).
 *
 * @param {number[]} heights Высоты столбцов.
 * @returns {number} Максимальная площадь.
 */
function largestRectangle(heights) {
  const stack = [];
  let best = 0;

  // Дополнительная итерация с нулевой высотой опустошает стек в конце прохода
  for (let i = 0; i <= heights.length; i++) {
    const currentHeight = i === heights.length ? 0 : heights[i];

    while (stack.length > 0 && heights[stack[stack.length - 1]] >= currentHeight) {
      const height = heights[stack.pop()];
      // После снятия вершиной стал ближайший слева столбец меньшей высоты
      const left = stack.length === 0 ? -1 : stack[stack.length - 1];
      const width = i - left - 1;

      best = Math.max(best, height * width);
    }

    stack.push(i);
  }

  return best;
}
```

#### Два приема, без которых решение не работает

**Фиктивный столбец нулевой высоты.** Цикл идет до `i = n` включительно, и на
последней итерации высота считается нулевой. Без этого столбцы, оставшиеся в
стеке после прохода (возрастающая «лестница» в конце гистограммы), никогда не
были бы сняты и их площади не были бы учтены.

**Значение `-1` для пустого стека.** Если после снятия стек опустел, значит,
слева не было ни одного столбца меньшей высоты - прямоугольник тянется до
самого начала гистограммы. Формула `width = i - left - 1` при `left = -1` дает
ровно `i`, то есть всю длину от нуля до текущей позиции.

#### Трассировка для `[2, 1, 5, 6, 2, 3]`

| `i` | Высота | Действие | Стек (индексы) | `best` |
| --- | --- | --- | --- | --- |
| 0 | 2 | стек пуст, кладем 0 | `[0]` | 0 |
| 1 | 1 | `2 ≥ 1` → снимаем 0: высота 2, ширина 1 − (−1) − 1 = 1, площадь 2 | `[1]` | 2 |
| 2 | 5 | `1 < 5`, кладем 2 | `[1, 2]` | 2 |
| 3 | 6 | `5 < 6`, кладем 3 | `[1, 2, 3]` | 2 |
| 4 | 2 | `6 ≥ 2` → снимаем 3: высота 6, ширина 4 − 2 − 1 = 1, площадь 6 | `[1, 2]` | 6 |
| 4 | 2 | `5 ≥ 2` → снимаем 2: высота 5, ширина 4 − 1 − 1 = **2**, площадь **10** | `[1]` | **10** |
| 4 | 2 | `1 < 2`, кладем 4 | `[1, 4]` | 10 |
| 5 | 3 | `2 < 3`, кладем 5 | `[1, 4, 5]` | 10 |
| 6 | 0 | `3 ≥ 0` → снимаем 5: высота 3, ширина 6 − 4 − 1 = 1, площадь 3 | `[1, 4]` | 10 |
| 6 | 0 | `2 ≥ 0` → снимаем 4: высота 2, ширина 6 − 1 − 1 = 4, площадь 8 | `[1]` | 10 |
| 6 | 0 | `1 ≥ 0` → снимаем 1: высота 1, ширина 6 − (−1) − 1 = 6, площадь 6 | `[]` | 10 |

Ответ - 10, что совпадает с рисунком в условии.

#### Разбор сложности

Внешний цикл выполняется `n + 1` раз. Внутренний цикл `while` на первый взгляд
делает решение квадратичным, но это не так: **каждый индекс кладется на стек
ровно один раз и снимается не более одного раза**. Значит, суммарное число
итераций `while` по всему проходу не превышает `n`.

Итого `O(n)` времени при `O(n)` памяти на стек - в худшем случае, когда высоты
возрастают, на стеке оказываются все `n` индексов.

#### О сравнении `>=` и `>`

При равных высотах условие `>=` снимает столбец раньше, чем прямоугольник
достиг настоящей правой границы, и его площадь считается заниженной. На ответ
это не влияет: последний столбец из группы равных высот будет снят с полной
шириной и даст правильное значение. Замена на `>` тоже дает верный ответ, но
оставляет в стеке равные высоты, что усложняет рассуждение о границах.
