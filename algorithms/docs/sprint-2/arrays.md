## 2.1 Массивы

**Структура данных** - способ организации информации в памяти, допускающий
определенный набор операций. Выбор структуры данных определяется тем, какие
операции должны быть быстрыми: универсально хорошей структуры не существует.

**Массив** - набор однотипных элементов, расположенных в памяти подряд.

### Представление данных в памяти

Оперативная память - линейная последовательность байтов, каждый из которых
имеет свой адрес. Один байт хранит 8 бит, то есть 256 различных значений.

Значение занимает столько байтов, сколько требует его тип:

| Тип | Размер | Диапазон |
| --- | --- | --- |
| 32-битное целое | 4 байта | от −2 147 483 648 до 2 147 483 647 |
| 64-битное вещественное | 8 байт | примерно от 10⁻³⁰⁸ до 10³⁰⁸ |
| Адрес (указатель) | 8 байт | адресное пространство 64-битной машины |

Указатель занимает 8 байт независимо от размера объекта, на который он
указывает. Поэтому массив строк - это массив адресов: сами строки лежат в
других участках памяти, а подряд расположены только ссылки на них.

### Почему доступ по индексу выполняется за `O(1)`

Ключевое свойство массива - элементы лежат подряд и имеют одинаковый размер.
Значит, адрес любого элемента вычисляется арифметически:

```
адрес элемента i = адрес начала массива + i × размер элемента
```

Это одна операция умножения и одна сложения, независимо от `i` и от длины
массива. Отсюда `O(1)` на чтение и запись по индексу - и отсюда же
невозможность вставить элемент в середину, не сдвинув все, что за ним: иначе
формула перестанет работать.

> **Массивы в JavaScript.** Все сказанное описывает массив как машинную
> структуру. `Array` в JavaScript - объект, который может содержать значения
> разных типов и «дыры», поэтому в общем случае непрерывным блоком памяти он не
> является. Пока массив плотно заполнен значениями одного типа, движок хранит
> его непрерывно и доступ действительно `O(1)`; при появлении дыр или смешении
> типов он переключается на представление в виде
> [хеш-таблицы](../sprint-4/hash-tables.md#41-хеш-таблица-хеш-функция-свойства-хеш-функций),
> и константа заметно растет. Настоящий непрерывный массив в JavaScript дают типизированные
> массивы - `Int32Array`, `Float64Array` и подобные.

### Массив постоянного размера

Простейший вариант: размер задается при создании и не меняется. Доступны две
операции, обе за `O(1)`:

- чтение элемента по индексу;
- запись элемента по индексу.

Добавить элемент нельзя: за концом массива лежит чужая память.

### Динамический массив

Динамический массив снимает это ограничение. Он хранит буфер **с запасом** и
различает две величины:

- **емкость** (`capacity`) - сколько элементов помещается в выделенный буфер;
- **длина** (`length`) - сколько элементов фактически хранится.

Пока `length < capacity`, добавление в конец - это запись в свободную ячейку за
`O(1)`. Когда буфер заполнен, происходит [реаллокация](#212-реаллокация-в-динамических-массивах).

```js
const GROWTH_FACTOR = 2;

/**
 * Динамический массив поверх буфера фиксированного размера.
 *
 * Буфер эмулируется обычным массивом JavaScript: существенно лишь то, что его
 * размер задается при создании и не меняется, а расширение требует выделения
 * нового буфера и копирования содержимого.
 */
class DynamicArray {
  /**
   * @param {number} capacity Начальная емкость буфера.
   */
  constructor(capacity = 1) {
    this.buffer = new Array(capacity);
    this.capacity = capacity;
    this.length = 0;
  }

  /**
   * Возвращает элемент по индексу.
   *
   * Время: O(1).
   *
   * @param {number} index Индекс элемента.
   * @returns {*} Значение элемента.
   */
  get(index) {
    if (index < 0 || index >= this.length) {
      throw new RangeError('Индекс за пределами массива');
    }

    return this.buffer[index];
  }

  /**
   * Добавляет элемент в конец массива.
   *
   * Время: O(1) амортизированно, O(n) в момент реаллокации.
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   */
  push(value) {
    if (this.length === this.capacity) {
      this.reallocate(this.capacity * GROWTH_FACTOR);
    }

    this.buffer[this.length] = value;
    this.length++;
  }

  /**
   * Вставляет элемент по индексу, сдвигая хвост вправо.
   *
   * Время: O(n).
   *
   * @param {number} index Позиция вставки, от 0 до length включительно.
   * @param {*} value Вставляемое значение.
   * @returns {void}
   */
  insert(index, value) {
    if (index < 0 || index > this.length) {
      throw new RangeError('Индекс за пределами массива');
    }

    if (this.length === this.capacity) {
      this.reallocate(this.capacity * GROWTH_FACTOR);
    }

    // Сдвиг выполняется справа налево, иначе элементы затрут друг друга
    for (let i = this.length; i > index; i--) {
      this.buffer[i] = this.buffer[i - 1];
    }

    this.buffer[index] = value;
    this.length++;
  }

  /**
   * Удаляет элемент по индексу, сдвигая хвост влево.
   *
   * Время: O(n).
   *
   * @param {number} index Индекс удаляемого элемента.
   * @returns {*} Удаленное значение.
   */
  remove(index) {
    if (index < 0 || index >= this.length) {
      throw new RangeError('Индекс за пределами массива');
    }

    const removed = this.buffer[index];

    for (let i = index; i < this.length - 1; i++) {
      this.buffer[i] = this.buffer[i + 1];
    }

    this.length--;
    // Освобождение ссылки: иначе удаленный объект останется достижимым
    this.buffer[this.length] = undefined;

    return removed;
  }

  /**
   * Выделяет буфер заданного размера и переносит в него содержимое.
   *
   * Время: O(n). Память: O(newCapacity).
   *
   * @param {number} newCapacity емкость нового буфера.
   * @returns {void}
   */
  reallocate(newCapacity) {
    const newBuffer = new Array(newCapacity);

    for (let i = 0; i < this.length; i++) {
      newBuffer[i] = this.buffer[i];
    }

    this.buffer = newBuffer;
    this.capacity = newCapacity;
  }
}
```

### 2.1.1 Вставки и удаления в динамических массивах

Стоимость операции определяется тем, сколько элементов приходится сдвигать.

```
Вставка в конец - сдвигать нечего:

  [ a | b | c |   |   ]  →  [ a | b | c | d |   ]
                ↑                          ↑
             свободно                   записали

Вставка в начало - сдвигаются все n элементов:

  [ a | b | c |   |   ]  →  [ d | a | b | c |   ]
    └───┴───┴──→ вправо
```

| Операция | Сложность | Причина |
| --- | --- | --- |
| Чтение и запись по индексу | `O(1)` | Адрес вычисляется арифметически |
| Вставка в конец | `O(1)` амортизированно | Сдвиг не нужен, изредка реаллокация |
| Вставка в начало | `O(n)` | Сдвигаются все элементы |
| Вставка в середину (позиция `i`) | `O(n − i)`, в худшем случае `O(n)` | Сдвигается хвост |
| Удаление с конца | `O(1)` | Сдвиг не нужен |
| Удаление из начала | `O(n)` | Сдвигаются все элементы |
| Удаление из середины | `O(n − i)`, в худшем случае `O(n)` | Сдвигается хвост |
| Поиск значения | `O(n)` | Линейный просмотр |

Общий вывод: динамический массив дешев с конца и дорог с начала. Если задача
требует частых операций в начале последовательности, массив - неподходящая
структура; нужны [связный список](linked-lists.md#22-связные-списки) или
[дек на кольцевом буфере](stack-and-queue.md#242-очередь-на-кольцевом-буфере).

Соответствие встроенным методам JavaScript:

| Метод | Сложность |
| --- | --- |
| `push`, `pop` | `O(1)` амортизированно |
| `unshift`, `shift` | `O(n)` |
| `splice` | `O(n)` |
| `indexOf`, `includes` | `O(n)` |
| `concat`, `slice` | `O(n)` |

Типичная ошибка - накапливать результат через `unshift` в цикле: `n` вызовов
по `O(n)` дают `O(n²)`. Правильный прием - накопить через `push` и один раз
развернуть массив.

### 2.1.2 Реаллокация в динамических массивах

**Реаллокация** - выделение нового участка памяти большего размера,
копирование в него содержимого и освобождение старого участка.

```
Буфер заполнен:        [ a | b | c | d ]           capacity = 4

Выделяем новый буфер:  [   |   |   |   |   |   |   |   ]   capacity = 8

Копируем содержимое:   [ a | b | c | d |   |   |   |   ]
```

Реаллокация стоит `O(n)`: копируется весь массив. Вопрос в том, насколько
увеличивать буфер.

#### Почему емкость умножают, а не увеличивают на константу

**Увеличение на константу `k`.** Реаллокация происходит каждые `k` вставок,
то есть `n / k` раз. При `i`-й реаллокации копируется `i · k` элементов, и
суммарный объем копирования равен

```
k + 2k + 3k + … + n  ≈  n² / (2k)
```

Это `O(n²)` на `n` вставок, то есть `O(n)` на одну вставку. Неприемлемо.

**Умножение на константу `q > 1`** (обычно 2, иногда 1,5). Реаллокации
происходят при размерах `1, q, q², …`, и суммарный объем копирования равен

```
1 + q + q² + … + n  =  (q·n − 1) / (q − 1)  <  n · q / (q − 1)
```

Это `O(n)` на `n` вставок, то есть **`O(1)` на одну вставку амортизированно**.
При `q = 2` суммарное копирование не превышает `2n`.

Формально это и есть [амортизированная
сложность](../sprint-1/complexity.md#амортизированная-сложность): отдельная
вставка может стоить `O(n)`, но средняя стоимость по длинной серии вставок -
`O(1)`.

Выбор `q` - компромисс: чем больше `q`, тем реже копирование, но тем больше
неиспользуемой памяти. При `q = 2` в худшем случае простаивает половина
буфера.

#### Сжатие при удалении

Симметричный вопрос: сокращать ли буфер, когда элементов стало мало.

Наивное правило «сжимать вдвое, как только заполнено меньше половины» плохо:
на границе чередование `push` и `pop` вызывает реаллокацию на каждой операции,
и амортизированная оценка разрушается. Такое поведение называется
дребезгом.

Рабочее правило - сжимать вдвое при заполнении **меньше четверти**. Тогда
после сжатия буфер заполнен наполовину, и до следующей реаллокации в любую
сторону нужно не менее `n / 2` операций, что сохраняет `O(1)`
амортизированно.
