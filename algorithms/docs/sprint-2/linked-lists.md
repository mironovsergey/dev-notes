## 2.2 Связные списки

**Связный список** - структура данных, в которой элементы не лежат в памяти
подряд, а связаны ссылками: каждый узел хранит значение и ссылку на соседний
узел.

Это прямая противоположность массиву. Массив покупает быстрый доступ по индексу
ценой дорогих вставок; список покупает дешевые вставки ценой отсутствия
индексации.

```
Массив: элементы подряд, адрес вычисляется

  [ a | b | c | d ]

Список: узлы где угодно, связаны ссылками

  ┌───┬──┐   ┌───┬──┐   ┌───┬──┐   ┌───┬──────┐
  │ a │ ●─┼──→│ b │ ●─┼──→│ c │ ●─┼──→│ d │ null │
  └───┴──┘   └───┴──┘   └───┴──┘   └───┴──────┘
    ↑
   head
```

Ключевое следствие: **добраться до `i`-го элемента можно только пройдя по
ссылкам от головы**, то есть за `O(i)`. Никакой арифметики адресов здесь нет.

### 2.2.1 Односвязный список

Узел хранит значение и ссылку на следующий узел. Последний узел ссылается на
`null`.

```js
class Node {
  /**
   * @param {*} value Значение узла.
   * @param {Node|null} next Ссылка на следующий узел.
   */
  constructor(value = null, next = null) {
    this.value = value;
    this.next = next;
  }
}
```

Список задается ссылкой на голову - первый узел. Пустой список - это `null`.

#### Обход

```js
/**
 * Печатает значения всех узлов списка, по одному в строке.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {Node|null} head Голова списка.
 * @returns {void}
 */
function printList(head) {
  let node = head;

  while (node !== null) {
    process.stdout.write(`${node.value}\n`);
    node = node.next;
  }
}
```

#### Доступ по индексу

```js
/**
 * Возвращает узел с заданным индексом.
 *
 * Время: O(index). Память: O(1).
 *
 * @param {Node|null} head Голова списка.
 * @param {number} index Индекс узла, нумерация с нуля.
 * @returns {Node|null} Узел либо null, если индекс за пределами списка.
 */
function getNodeByIndex(head, index) {
  let node = head;
  let remaining = index;

  while (node !== null && remaining > 0) {
    node = node.next;
    remaining--;
  }

  return node;
}
```

Проверка `node !== null` обязательна: без нее индекс, выходящий за пределы
списка, приводит к обращению к полю `null`.

#### Вставка

Вставка **после известного узла** - это две записи ссылок, `O(1)`:

```
До:    ┌───┬──┐        ┌───┬──┐
       │ a │ ●─┼───────→│ c │ ●─┼→
       └───┴──┘        └───┴──┘

После: ┌───┬──┐   ┌───┬──┐   ┌───┬──┐
       │ a │ ●─┼──→│ b │ ●─┼──→│ c │ ●─┼→
       └───┴──┘   └───┴──┘   └───┴──┘
                    новый
```

```js
/**
 * Вставляет новый узел сразу после заданного.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {Node} node Узел, после которого выполняется вставка.
 * @param {*} value Значение нового узла.
 * @returns {Node} Созданный узел.
 */
function insertAfter(node, value) {
  const newNode = new Node(value, node.next);
  node.next = newNode;

  return newNode;
}

/**
 * Вставляет новый узел по индексу и возвращает голову обновленного списка.
 *
 * Время: O(index). Память: O(1).
 *
 * @param {Node|null} head Голова списка.
 * @param {number} index Позиция вставки, нумерация с нуля.
 * @param {*} value Значение нового узла.
 * @returns {Node} Голова обновленного списка.
 */
function insertByIndex(head, index, value) {
  // Вставка в начало меняет голову списка, поэтому обрабатывается отдельно
  if (index === 0) {
    return new Node(value, head);
  }

  const previous = getNodeByIndex(head, index - 1);

  if (previous === null) {
    throw new RangeError('Индекс за пределами списка');
  }

  insertAfter(previous, value);

  return head;
}
```

Обратите внимание на закономерность: любая операция, способная затронуть первый
узел, должна возвращать новую голову. Это неудобство устраняется фиктивным
головным узлом либо оборачиванием списка в класс с полем `head`.

#### Удаление

Здесь проявляется главный недостаток односвязного списка. Чтобы исключить узел
из цепочки, нужно изменить ссылку **предыдущего** узла, а перейти к нему по
ссылкам невозможно - они ведут только вперед. Поэтому удаление известного узла
стоит `O(n)`: предшественника приходится искать заново.

```js
/**
 * Удаляет узел по индексу и возвращает голову обновленного списка.
 *
 * Время: O(index). Память: O(1).
 *
 * @param {Node} head Голова непустого списка.
 * @param {number} index Индекс удаляемого узла, нумерация с нуля.
 * @returns {Node|null} Голова обновленного списка.
 */
function removeByIndex(head, index) {
  if (index === 0) {
    return head.next;
  }

  const previous = getNodeByIndex(head, index - 1);

  if (previous === null || previous.next === null) {
    throw new RangeError('Индекс за пределами списка');
  }

  previous.next = previous.next.next;

  return head;
}
```

#### Поиск

```js
/**
 * Возвращает индекс первого вхождения значения в список.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {Node|null} head Голова списка.
 * @param {*} value Искомое значение.
 * @returns {number} Индекс первого вхождения либо -1, если значение отсутствует.
 */
function indexOf(head, value) {
  let node = head;
  let index = 0;

  while (node !== null) {
    if (node.value === value) {
      return index;
    }

    node = node.next;
    index++;
  }

  return -1;
}
```

#### Хвостовая ссылка

Добавление в конец односвязного списка стоит `O(n)`: нужно дойти до последнего
узла. Если хранить рядом с головой еще и ссылку на хвост, добавление в конец
становится `O(1)`. Именно так строится
[очередь на связном списке](stack-and-queue.md#243-очередь-на-связном-списке).

Удаление с конца ссылка на хвост не ускоряет: предпоследний узел все равно
приходится искать с начала.

### 2.2.2 Двусвязный список

Каждый узел хранит ссылки на оба соседних узла.

```js
class DoublyNode {
  /**
   * @param {*} value Значение узла.
   * @param {DoublyNode|null} prev Ссылка на предыдущий узел.
   * @param {DoublyNode|null} next Ссылка на следующий узел.
   */
  constructor(value = null, prev = null, next = null) {
    this.value = value;
    this.prev = prev;
    this.next = next;
  }
}
```

```
        ┌───┬──┐ ←──── ┌───┬──┐ ←──── ┌───┬──┐
  null ←┼─● │ a │ ●───→│ b │ ● │ ●───→│ c │ ●─┼→ null
        └───┴──┘       └───┴──┘       └───┴──┘
          ↑                             ↑
        head                          tail
```

Что это дает:

- **движение в обе стороны** - список можно обходить с конца;
- **удаление известного узла за `O(1)`** - предшественник доступен напрямую;
- **вставка перед известным узлом за `O(1)`**.

```js
/**
 * Исключает узел из двусвязного списка.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {DoublyNode} node Удаляемый узел.
 * @returns {void}
 */
function removeNode(node) {
  if (node.prev !== null) {
    node.prev.next = node.next;
  }

  if (node.next !== null) {
    node.next.prev = node.prev;
  }

  node.prev = null;
  node.next = null;
}
```

Проверки на `null` обрабатывают удаление головы и хвоста. Если список
оборачивается в класс, там же обновляются поля `head` и `tail`.

Цена - дополнительная ссылка в каждом узле: примерно на треть больше памяти по
сравнению с односвязным списком при хранении небольших значений.

#### Разворот списка

Разворот двусвязного списка сводится к обмену ссылок `prev` и `next` в каждом
узле:

```js
/**
 * Разворачивает двусвязный список.
 *
 * У каждого узла ссылки prev и next меняются местами; новой головой становится
 * бывший хвост.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {DoublyNode|null} head Голова исходного списка.
 * @returns {DoublyNode|null} Голова развернутого списка.
 */
function reverse(head) {
  let current = head;
  let previous = null;

  while (current !== null) {
    // Ссылку на следующий узел нужно сохранить до перезаписи
    const next = current.next;

    current.next = previous;
    current.prev = next;

    previous = current;
    current = next;
  }

  return previous;
}
```

### Список против массива

| Операция | Массив | Односвязный список | Двусвязный список |
| --- | --- | --- | --- |
| Доступ по индексу | `O(1)` | `O(n)` | `O(n)` |
| Вставка в начало | `O(n)` | `O(1)` | `O(1)` |
| Вставка в конец | `O(1)` амортиз. | `O(n)`, с хвостом `O(1)` | `O(1)` |
| Вставка после известного узла | `O(n)` | `O(1)` | `O(1)` |
| Удаление известного узла | `O(n)` | `O(n)` | `O(1)` |
| Поиск значения | `O(n)` | `O(n)` | `O(n)` |
| Память на элемент | значение | значение + 1 ссылка | значение + 2 ссылки |

Таблица не рассказывает всей правды. У массива есть преимущество, которое в
асимптотике не видно: элементы лежат подряд, поэтому процессор подгружает их в
кэш целыми блоками. Обход списка прыгает по произвольным адресам, и каждый
переход - потенциальный промах кэша. На практике обход массива из миллиона
элементов может оказаться на порядок быстрее обхода списка той же длины, хотя
обе операции - `O(n)`.

Поэтому связный список выбирают не «когда много вставок», а когда вставки и
удаления выполняются **по уже известным узлам**, без поиска. Иначе `O(n)` на
поиск съедает всю выгоду.
