# Стек, очередь и дек

[← К содержанию спринта](README.md)

Стек и очередь - структуры с намеренно **ограниченным** интерфейсом. Они не
дают доступа по индексу и не позволяют вставить элемент в середину: работать
можно только с концами. Ограничение и есть их ценность - оно гарантирует, что
все операции выполняются за `O(1)`, и делает порядок обработки элементов частью
контракта структуры.

---

## 2.3 Стек

**Стек** работает по принципу LIFO (last in, first out) - «последним вошел,
первым вышел». Добавление и извлечение происходят с одного конца, называемого
вершиной.

```
        push(d)              pop() → d
           ↓                    ↑
        ┌─────┐              ┌─────┐
        │  d  │              │  d  │
        ├─────┤              ├─────┤
        │  c  │              │  c  │  ← вершина
        ├─────┤              ├─────┤
        │  b  │              │  b  │
        ├─────┤              ├─────┤
        │  a  │              │  a  │  ← дно
        └─────┘              └─────┘
```

### Интерфейс

| Операция | Смысл | Сложность |
| --- | --- | --- |
| `push(value)` | Положить элемент на вершину | `O(1)` амортизированно |
| `pop()` | Снять элемент с вершины и вернуть его | `O(1)` |
| `peek()` | Посмотреть вершину, не снимая | `O(1)` |
| `size()` | Количество элементов | `O(1)` |
| `isEmpty()` | Пуст ли стек | `O(1)` |

### Реализация на динамическом массиве

Вершиной служит конец массива - единственное место, где вставка и удаление
стоят `O(1)`.

```js
class Stack {
  constructor() {
    this.items = [];
  }

  /**
   * Кладет элемент на вершину стека.
   *
   * Время: O(1) амортизированно.
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   */
  push(value) {
    this.items.push(value);
  }

  /**
   * Снимает элемент с вершины стека.
   *
   * Время: O(1).
   *
   * @returns {*} Снятое значение либо undefined, если стек пуст.
   */
  pop() {
    return this.items.pop();
  }

  /**
   * Возвращает элемент на вершине, не снимая его.
   *
   * Время: O(1).
   *
   * @returns {*} Значение на вершине либо undefined, если стек пуст.
   */
  peek() {
    return this.items[this.items.length - 1];
  }

  /**
   * Возвращает количество элементов в стеке.
   *
   * Время: O(1).
   *
   * @returns {number} Количество элементов.
   */
  size() {
    return this.items.length;
  }

  /**
   * Проверяет, пуст ли стек.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если стек пуст.
   */
  isEmpty() {
    return this.items.length === 0;
  }
}
```

Обратите внимание на поведение при пустом стеке: `pop` и `peek` возвращают
`undefined`. Это допустимо, но опасно, если `undefined` - легальное значение
элемента. Альтернатива - бросать исключение. Главное, чтобы решение было
принято осознанно и одинаково во всем коде.

Стек так же естественно строится на односвязном списке: вершина - это голова,
`push` и `pop` сводятся к вставке и удалению в начале, обе операции `O(1)`.
Массив выигрывает за счет локальности в памяти, список - за счет отсутствия
реаллокаций.

### Применение: стек вызовов

Стек вызовов - область памяти, в которой исполняющая среда хранит состояние
незавершенных вызовов функций. При вызове на стек кладется **кадр** (frame),
содержащий:

- аргументы функции;
- ее локальные переменные;
- адрес возврата - инструкцию, на которую нужно перейти после завершения.

При возврате кадр снимается, и выполнение продолжается с сохраненного адреса.
Порядок строго LIFO: последний вызванный завершается первым.

```js
function printHoroscope(name) {
  console.log(`${name}! Сегодня подходящий день для изучения рекурсии.`);
}

function sayHello(name) {
  console.log(`Привет, ${name}.`);
  printHoroscope(name.toUpperCase());
  console.log(`Пока, ${name}, хорошего дня!`);
}

sayHello('Гоша');
```

В момент работы `printHoroscope` на стеке лежат три кадра: глобальный,
`sayHello` и `printHoroscope`.

Практическое следствие - **глубина рекурсии ограничена размером стека**.
Рекурсивное вычисление факториала создает `n` вложенных кадров, то есть требует
`O(n)` памяти, тогда как итеративное обходится `O(1)`:

```js
/**
 * Вычисляет факториал рекурсивно.
 *
 * Время: O(n). Память: O(n) на кадры стека вызовов.
 *
 * @param {number} n Неотрицательное целое число.
 * @returns {number} Значение n!.
 */
function factorialRecursive(n) {
  if (n <= 1) {
    return 1;
  }

  return n * factorialRecursive(n - 1);
}

/**
 * Вычисляет факториал итеративно.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number} n Неотрицательное целое число.
 * @returns {number} Значение n!.
 */
function factorialIterative(n) {
  let result = 1;

  for (let i = 2; i <= n; i++) {
    result *= i;
  }

  return result;
}
```

При слишком большой глубине стек исчерпывается, и выполнение прерывается
ошибкой - в Node.js это `RangeError: Maximum call stack size exceeded`.
Порядок допустимой глубины - около десяти тысяч кадров для простой функции;
точное значение зависит от среды и от размера кадра, поэтому опираться на него
нельзя.

Отсюда правило: если глубина рекурсии зависит от размера входных данных и может
достигать сотен тысяч, рекурсию нужно разворачивать в цикл с явным стеком.
Подробнее рекурсия разбирается в [третьем спринте](../sprint-3/README.md).

### Применение: скобочная последовательность

Классическая задача, в которой стек - точный инструмент: проверить, что
скобки расставлены правильно.

Идея: открывающая скобка кладется на стек, закрывающая должна совпасть по типу
с вершиной. LIFO-порядок в точности соответствует правилу вложенности -
закрывается всегда последняя незакрытая скобка.

```js
const CLOSING_TO_OPENING = new Map([
  [')', '('],
  [']', '['],
  ['}', '{'],
]);

/**
 * Проверяет правильность скобочной последовательности.
 *
 * Время: O(n). Память: O(n) в худшем случае - все скобки открывающие.
 *
 * @param {string} line Строка, возможно содержащая скобки трех видов.
 * @returns {boolean} true, если скобки расставлены правильно.
 */
function isBalanced(line) {
  const stack = [];

  for (const char of line) {
    if (char === '(' || char === '[' || char === '{') {
      stack.push(char);
    } else if (CLOSING_TO_OPENING.has(char)) {
      // Несовпадение типа и извлечение из пустого стека обрабатываются
      // одинаково: pop вернет undefined, который ничему не равен
      if (stack.pop() !== CLOSING_TO_OPENING.get(char)) {
        return false;
      }
    }
  }

  // Непустой стек означает незакрытые скобки
  return stack.length === 0;
}
```

Вычисление выражений в обратной польской нотации устроено по тому же принципу:
операнды накапливаются на стеке, оператор снимает нужное их количество и кладет
обратно результат.

### Применение: максимум в стеке за `O(1)`

Задача: научить стек отвечать на запрос «каков максимум среди всех элементов»
за `O(1)`. Прямолинейный ответ - просматривать все элементы - стоит `O(n)` на
запрос и превращает серию из `n` команд в `O(n²)`.

Прием: хранить **второй стек**, синхронный основному, в котором на позиции `i`
лежит максимум среди первых `i + 1` элементов. При добавлении новый максимум
вычисляется за одно сравнение, при удалении оба стека снимают вершину вместе.

```js
class StackMax {
  constructor() {
    this.items = [];
    // maxima[i] - максимум среди items[0..i]
    this.maxima = [];
  }

  /**
   * Кладет элемент на вершину стека.
   *
   * Время: O(1) амортизированно.
   *
   * @param {number} value Добавляемое число.
   * @returns {void}
   */
  push(value) {
    const previousMax = this.maxima[this.maxima.length - 1];

    this.items.push(value);
    this.maxima.push(this.maxima.length === 0 ? value : Math.max(value, previousMax));
  }

  /**
   * Снимает элемент с вершины стека.
   *
   * Время: O(1).
   *
   * @returns {number|undefined} Снятое число либо undefined, если стек пуст.
   */
  pop() {
    this.maxima.pop();

    return this.items.pop();
  }

  /**
   * Возвращает максимум среди элементов стека.
   *
   * Время: O(1).
   *
   * @returns {number|null} Максимум либо null, если стек пуст.
   */
  getMax() {
    if (this.maxima.length === 0) {
      return null;
    }

    return this.maxima[this.maxima.length - 1];
  }
}
```

Плата - `O(n)` дополнительной памяти. Это типичный размен памяти на время:
дублирование данных превращает `O(n)` на запрос в `O(1)`.

## 2.4 Очередь и дек

**Очередь** работает по принципу FIFO (first in, first out) - «первым вошел,
первым вышел». Добавление происходит в один конец (хвост), извлечение - из
другого (голова).

```
   push(d) →  ┌───┬───┬───┬───┐  → pop() → a
              │ d │ c │ b │ a │
              └───┴───┴───┴───┘
              хвост        голова
```

| Операция | Смысл | Сложность (цель) |
| --- | --- | --- |
| `push(value)` | Добавить элемент в хвост | `O(1)` |
| `pop()` | Извлечь элемент из головы | `O(1)` |
| `peek()` | Посмотреть голову, не извлекая | `O(1)` |
| `size()` | Количество элементов | `O(1)` |
| `isEmpty()` | Пуста ли очередь | `O(1)` |

**Дек** (deque, double-ended queue) - «очередь с двумя концами»: добавлять и
извлекать можно с любой стороны.

| Операция | Смысл |
| --- | --- |
| `pushBack(value)` | Добавить в конец |
| `popBack()` | Извлечь с конца |
| `pushFront(value)` | Добавить в начало |
| `popFront()` | Извлечь из начала |

Дек обобщает и стек, и очередь: используя только `pushBack` и `popBack`,
получаем стек; используя `pushBack` и `popFront` - очередь.

Ниже - четыре способа реализовать очередь. Они различаются не интерфейсом, а
сложностью операций, ограничениями на размер и расходом памяти.

---

### 2.4.1 Очередь на динамическом массиве

**Наивный вариант.** Добавляем в конец массива, извлекаем с позиции 0 со
сдвигом всех остальных элементов влево.

```js
push(value) {
  this.items.push(value);        // O(1)
}

pop() {
  return this.items.shift();     // O(n) - сдвигаются все элементы
}
```

Извлечение стоит `O(n)`, и серия из `n` извлечений - `O(n²)`. Для очереди, чья
цель - `O(1)` на операцию, это неприемлемо.

**Вариант с указателем на голову.** Ничего не сдвигаем: вместо этого храним
индекс головы и продвигаем его при извлечении.

```js
class ArrayQueue {
  constructor() {
    this.items = [];
    this.head = 0;
  }

  /**
   * Добавляет элемент в хвост очереди.
   *
   * Время: O(1) амортизированно.
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   */
  push(value) {
    this.items.push(value);
  }

  /**
   * Извлекает элемент из головы очереди.
   *
   * Время: O(1).
   *
   * @returns {*} Извлеченное значение либо null, если очередь пуста.
   */
  pop() {
    if (this.isEmpty()) {
      return null;
    }

    const value = this.items[this.head];

    // Освобождение ссылки: извлеченный объект не должен удерживаться в памяти
    this.items[this.head] = null;
    this.head++;

    return value;
  }

  /**
   * Возвращает количество элементов в очереди.
   *
   * Время: O(1).
   *
   * @returns {number} Количество элементов.
   */
  size() {
    return this.items.length - this.head;
  }

  /**
   * Проверяет, пуста ли очередь.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если очередь пуста.
   */
  isEmpty() {
    return this.size() === 0;
  }
}
```

Обе операции стали `O(1)`, но появилась новая проблема: **обработанная часть
массива не освобождается**. После миллиона добавлений и миллиона извлечений
очередь пуста, а буфер по-прежнему занимает миллион ячеек.

Лечится уплотнением: когда `head` превышает половину длины массива, обрезаем
обработанный префикс. Уплотнение стоит `O(n)`, но происходит не чаще одного
раза на `n / 2` извлечений, поэтому `O(1)` амортизированно сохраняется. Именно
эта проблема и решается радикально в следующем варианте.

### 2.4.2 Очередь на кольцевом буфере

Идея: считать массив замкнутым в кольцо. Индекс, дошедший до конца буфера,
переходит в его начало - за это отвечает взятие остатка по модулю емкости.
Освободившиеся в начале ячейки переиспользуются, и сдвигать ничего не нужно.

```
        буфер емкости 8, в очереди элементы c, d, e

           0     1     2     3     4     5     6     7
        ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
        │  ·  │  ·  │  ·  │  c  │  d  │  e  │  ·  │  ·  │
        └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
                             ↑                 ↑
                           head              tail
                     (откуда извлекать)  (куда добавлять)

        после трех добавлений tail «оборачивается» через конец:

        ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
        │  h  │  ·  │  ·  │  c  │  d  │  e  │  f  │  g  │
        └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
                 ↑           ↑
               tail        head
```

Голова указывает на элемент, находящийся в очереди дольше всех; хвост - на
первую свободную ячейку.

#### Почему нужен явный счетчик элементов

Если хранить только `head` и `tail`, состояния «очередь пуста» и «очередь
полна» неразличимы: в обоих `head === tail`. Есть два решения:

1. хранить длину очереди отдельным полем;
2. всегда оставлять одну ячейку пустой, тогда «полна» - это
   `(tail + 1) % capacity === head`, ценой одной неиспользуемой ячейки.

Ниже используется первый способ - он нагляднее и не теряет ячейку.

```js
class RingQueue {
  /**
   * @param {number} capacity Максимальное количество элементов.
   */
  constructor(capacity) {
    this.buffer = new Array(capacity).fill(null);
    this.capacity = capacity;
    // Индекс, из которого извлекается элемент
    this.head = 0;
    // Индекс первой свободной ячейки
    this.tail = 0;
    this.length = 0;
  }

  /**
   * Проверяет, пуста ли очередь.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если очередь пуста.
   */
  isEmpty() {
    return this.length === 0;
  }

  /**
   * Проверяет, заполнена ли очередь.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если свободных ячеек не осталось.
   */
  isFull() {
    return this.length === this.capacity;
  }

  /**
   * Добавляет элемент в хвост очереди.
   *
   * Время: O(1).
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   * @throws {RangeError} Если очередь заполнена.
   */
  push(value) {
    if (this.isFull()) {
      throw new RangeError('Очередь переполнена');
    }

    this.buffer[this.tail] = value;
    this.tail = (this.tail + 1) % this.capacity;
    this.length++;
  }

  /**
   * Извлекает элемент из головы очереди.
   *
   * Время: O(1).
   *
   * @returns {*} Извлеченное значение.
   * @throws {RangeError} Если очередь пуста.
   */
  pop() {
    if (this.isEmpty()) {
      throw new RangeError('Очередь пуста');
    }

    const value = this.buffer[this.head];

    this.buffer[this.head] = null;
    this.head = (this.head + 1) % this.capacity;
    this.length--;

    return value;
  }

  /**
   * Возвращает элемент в голове очереди, не извлекая его.
   *
   * Время: O(1).
   *
   * @returns {*} Значение в голове.
   * @throws {RangeError} Если очередь пуста.
   */
  peek() {
    if (this.isEmpty()) {
      throw new RangeError('Очередь пуста');
    }

    return this.buffer[this.head];
  }
}
```

#### Трассировка для емкости 8

| Команда | Буфер | `head` | `tail` | `length` |
| --- | --- | --- | --- | --- |
| - | `[·,·,·,·,·,·,·,·]` | 0 | 0 | 0 |
| `push(1)` | `[1,·,·,·,·,·,·,·]` | 0 | 1 | 1 |
| `push(-1)`, `push(0)`, `push(11)` | `[1,-1,0,11,·,·,·,·]` | 0 | 4 | 4 |
| `pop()` → `1` | `[·,-1,0,11,·,·,·,·]` | 1 | 4 | 3 |
| `pop()` → `-1`, `pop()` → `0` | `[·,·,·,11,·,·,·,·]` | 3 | 4 | 1 |
| `push(-8)`, `push(7)`, `push(3)`, `push(16)` | `[·,·,·,11,-8,7,3,16]` | 3 | 0 | 5 |
| `push(12)` | `[12,·,·,11,-8,7,3,16]` | 3 | 1 | 6 |

Последняя строка показывает суть кольца: хвост дошел до конца буфера и
продолжил запись с нулевой ячейки, освобожденной ранее.

#### Дек на кольцевом буфере

Дек получается добавлением симметричных операций. Движение влево записывается
как `(index - 1 + capacity) % capacity` - слагаемое `capacity` нужно потому,
что в JavaScript остаток от деления отрицательного числа отрицателен:
`(0 - 1) % 8` дает `-1`, а не `7`.

```js
/**
 * Добавляет элемент в начало дека.
 *
 * Время: O(1).
 *
 * @param {*} value Добавляемое значение.
 * @returns {void}
 * @throws {RangeError} Если дек заполнен.
 */
pushFront(value) {
  if (this.isFull()) {
    throw new RangeError('Дек переполнен');
  }

  this.head = (this.head - 1 + this.capacity) % this.capacity;
  this.buffer[this.head] = value;
  this.length++;
}

/**
 * Извлекает элемент с конца дека.
 *
 * Время: O(1).
 *
 * @returns {*} Извлеченное значение.
 * @throws {RangeError} Если дек пуст.
 */
popBack() {
  if (this.isEmpty()) {
    throw new RangeError('Дек пуст');
  }

  // tail указывает на свободную ячейку, поэтому сначала шаг назад
  this.tail = (this.tail - 1 + this.capacity) % this.capacity;

  const value = this.buffer[this.tail];

  this.buffer[this.tail] = null;
  this.length--;

  return value;
}
```

**Достоинство:** все операции строго `O(1)`, без амортизации и без
реаллокаций. **Недостаток:** емкость фиксирована. Снять ограничение можно
реаллокацией с удвоением, но копирование кольца сложнее копирования массива -
элементы приходится переносить в правильном порядке, разворачивая кольцо.

### 2.4.3 Очередь на связном списке

Ограничение на размер снимается заменой буфера на связный список: узлы
выделяются по мере необходимости.

Добавление - вставка в хвост, извлечение - удаление головы. Обе операции
затрагивают концы списка, где вставка и удаление стоят `O(1)`, при условии, что
ссылка на хвост хранится явно.

```js
class Node {
  /**
   * @param {*} value Значение узла.
   * @param {Node|null} next Ссылка на следующий узел.
   */
  constructor(value, next = null) {
    this.value = value;
    this.next = next;
  }
}

class LinkedQueue {
  constructor() {
    this.head = null;
    this.tail = null;
    this.length = 0;
  }

  /**
   * Проверяет, пуста ли очередь.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если очередь пуста.
   */
  isEmpty() {
    return this.length === 0;
  }

  /**
   * Добавляет элемент в хвост очереди.
   *
   * Время: O(1).
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   */
  push(value) {
    const node = new Node(value);

    if (this.isEmpty()) {
      this.head = node;
    } else {
      this.tail.next = node;
    }

    this.tail = node;
    this.length++;
  }

  /**
   * Извлекает элемент из головы очереди.
   *
   * Время: O(1).
   *
   * @returns {*} Извлеченное значение.
   * @throws {RangeError} Если очередь пуста.
   */
  pop() {
    if (this.isEmpty()) {
      throw new RangeError('Очередь пуста');
    }

    const node = this.head;

    this.head = node.next;
    this.length--;

    // Из очереди извлекли последний элемент - хвост тоже нужно сбросить
    if (this.head === null) {
      this.tail = null;
    }

    return node.value;
  }
}
```

Сбрасывать `tail` при опустошении обязательно: иначе он продолжит ссылаться на
уже извлеченный узел, и следующее добавление присоединит новый элемент к
выброшенной цепочке.

**Достоинство:** размер не ограничен, все операции `O(1)` без амортизации.
**Недостатки:**

- на каждый элемент расходуется дополнительная память под узел и ссылку;
- узлы разбросаны по памяти, поэтому обход медленнее, чем у варианта на
  массиве, - сказываются промахи кэша;
- выделение узла на каждое добавление нагружает сборщик мусора.

### 2.4.4 Очередь на двух стеках

Очередь можно построить, имея только стековые операции. Прием выглядит
искусственным, но показывает нетривиальный амортизационный анализ.

Правила:

1. добавляем всегда во входной стек;
2. извлекаем всегда из выходного;
3. если выходной стек пуст, **перекладываем** в него все содержимое входного.

Перекладывание разворачивает порядок: элемент, лежавший на дне входного стека
(добавленный раньше всех), оказывается на вершине выходного - то есть
извлекается первым, как и требует FIFO.

```
Добавили a, b, c:          Извлекаем - выходной пуст, перекладываем:

  вход   выход              вход   выход
  ┌───┐                            ┌───┐
  │ c │                            │ a │ ← вершина, извлечется первым
  ├───┤                            ├───┤
  │ b │                            │ b │
  ├───┤                            ├───┤
  │ a │                            │ c │
  └───┘                            └───┘
```

```js
class TwoStackQueue {
  constructor() {
    this.inbox = [];
    this.outbox = [];
  }

  /**
   * Возвращает количество элементов в очереди.
   *
   * Время: O(1).
   *
   * @returns {number} Количество элементов.
   */
  size() {
    return this.inbox.length + this.outbox.length;
  }

  /**
   * Проверяет, пуста ли очередь.
   *
   * Время: O(1).
   *
   * @returns {boolean} true, если очередь пуста.
   */
  isEmpty() {
    return this.size() === 0;
  }

  /**
   * Добавляет элемент в хвост очереди.
   *
   * Время: O(1).
   *
   * @param {*} value Добавляемое значение.
   * @returns {void}
   */
  push(value) {
    this.inbox.push(value);
  }

  /**
   * Извлекает элемент из головы очереди.
   *
   * Время: O(1) амортизированно, O(n) в худшем случае.
   *
   * @returns {*} Извлеченное значение.
   * @throws {RangeError} Если очередь пуста.
   */
  pop() {
    if (this.isEmpty()) {
      throw new RangeError('Очередь пуста');
    }

    // Перекладывание выполняется только когда выходной стек опустел,
    // поэтому порядок уже переложенных элементов не нарушается
    if (this.outbox.length === 0) {
      while (this.inbox.length > 0) {
        this.outbox.push(this.inbox.pop());
      }
    }

    return this.outbox.pop();
  }
}
```

#### Разбор сложности

Отдельное извлечение может стоить `O(n)`: если во входном стеке накопилось `n`
элементов, все они перекладываются за один вызов `pop`.

Тем не менее амортизированная стоимость - `O(1)`. Проследим за судьбой одного
элемента: за все время жизни в очереди он участвует ровно в трех операциях -
попадает во входной стек, один раз перекладывается в выходной, извлекается из
выходного. Каждая из них стоит `O(1)`, значит, на элемент приходится `O(1)`
работы, а на `n` операций - `O(n)`.

Существенно, что перекладывание происходит **только при пустом выходном
стеке**. Уже переложенный элемент во входной стек не возвращается, поэтому
второй раз он не перекладывается.

### Сравнение реализаций

| Реализация | `push` | `pop` | Размер | Память |
| --- | --- | --- | --- | --- |
| Массив со сдвигом | `O(1)` | `O(n)` | не ограничен | компактно |
| Массив с указателем головы | `O(1)` амортиз. | `O(1)` | не ограничен | растет без уплотнения |
| Кольцевой буфер | `O(1)` | `O(1)` | **фиксирован** | компактно, емкость занята всегда |
| Связный список | `O(1)` | `O(1)` | не ограничен | накладные расходы на узлы |
| Два стека | `O(1)` | `O(1)` амортиз. | не ограничен | два массива |

Практический выбор: кольцевой буфер, если верхняя граница размера известна
заранее (так устроены буферы ввода-вывода и очереди задач фиксированной
емкости); связный список или массив с уплотнением, если не известна.
