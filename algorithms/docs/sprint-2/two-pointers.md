## 2.6 Метод двух указателей

**Метод двух указателей** - прием, при котором по данным движутся два индекса,
и каждый из них проходит их не более одного раза. Это превращает вложенный
перебор пар за `O(n²)` в один проход за `O(n)` при `O(1)` дополнительной
памяти.

Прием не универсален. Он работает тогда, когда из проверки одной пары можно
сделать вывод сразу о **множестве** других пар и отбросить их не рассматривая.
Обычно такой вывод дает монотонность: отсортированность массива или то, что
целевая функция меняется предсказуемо при сдвиге указателя.

Различают три основные схемы.

---

### Схема 1. Указатели навстречу друг другу

Один указатель стоит в начале, другой в конце, и они сближаются.

**Задача.** В массиве, отсортированном по неубыванию, найти пару элементов с
заданной суммой.

Наивное решение перебирает все пары за `O(n²)`. Но в отсортированном массиве
сумма крайних элементов уже дает информацию обо всей строке или столбце
таблицы пар:

- если `numbers[left] + numbers[right] < target`, то сумма мала, и увеличить
  ее можно только сдвигом левого указателя вправо - с любым меньшим правым
  элементом сумма будет еще меньше, поэтому вся эта группа пар отбрасывается;
- если сумма больше `target`, симметрично сдвигаем правый указатель влево.

```js
/**
 * Находит в отсортированном массиве два элемента с заданной суммой.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number[]} numbers Массив, отсортированный по неубыванию.
 * @param {number} target Искомая сумма.
 * @returns {number[]|null} Индексы двух элементов либо null, если пары нет.
 */
function twoSumSorted(numbers, target) {
  let left = 0;
  let right = numbers.length - 1;

  while (left < right) {
    const sum = numbers[left] + numbers[right];

    if (sum === target) {
      return [left, right];
    }

    if (sum < target) {
      left++;
    } else {
      right--;
    }
  }

  return null;
}
```

Каждая итерация сдвигает ровно один указатель, а суммарно они могут сделать не
более `n` шагов - отсюда `O(n)`.

По той же схеме устроена [проверка палиндрома](../sprint-1/search.md#16-линейный-поиск):
указатели идут с концов строки навстречу и сравнивают символы.

### Схема 2. Скользящее окно

Оба указателя движутся в одну сторону и задают границы отрезка - «окна».
Правый указатель расширяет окно, левый сжимает, когда нарушено условие.

**Задача.** Найти длину самого длинного подотрезка с суммой не больше `limit`
(все числа неотрицательные).

Неотрицательность и обеспечивает монотонность: расширение окна вправо сумму
только увеличивает, сжатие слева - только уменьшает. Поэтому, если окно стало
недопустимым, левую границу достаточно двигать вперед, и назад она уже никогда
не вернется.

```js
/**
 * Возвращает длину самого длинного подотрезка с суммой не больше limit.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number[]} numbers Массив неотрицательных чисел.
 * @param {number} limit Верхняя граница суммы подотрезка.
 * @returns {number} Длина наибольшего подходящего подотрезка.
 */
function longestSubarrayWithSumAtMost(numbers, limit) {
  let left = 0;
  let sum = 0;
  let best = 0;

  for (let right = 0; right < numbers.length; right++) {
    sum += numbers[right];

    // Окно стало недопустимым - сжимаем его слева
    while (sum > limit && left <= right) {
      sum -= numbers[left];
      left++;
    }

    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

Сложность `O(n)`, хотя внутри цикла есть `while`: указатель `left` только
растет и за весь проход сделает не более `n` шагов. Это то же рассуждение, что
и при разборе [монотонного стека](histogram.md#разбор-сложности).

Частный случай скользящего окна - **окно постоянной ширины**. Тогда `while` не
нужен, левая граница сдвигается синхронно с правой, а сумма пересчитывается
за `O(1)`: прибавляем вошедший элемент, вычитаем вышедший.

```js
/**
 * Возвращает скользящие средние по окну заданной ширины.
 *
 * Сумма окна пересчитывается за O(1) на шаг: прибавляется вошедший элемент
 * и вычитается вышедший, вместо суммирования всего окна заново.
 *
 * Время: O(n). Память: O(n) на результат.
 *
 * @param {number[]} numbers Исходный массив.
 * @param {number} width Ширина окна, 1 <= width <= numbers.length.
 * @returns {number[]} Средние значения для каждого положения окна.
 */
function movingAverage(numbers, width) {
  const result = [];
  let sum = 0;

  for (let i = 0; i < numbers.length; i++) {
    sum += numbers[i];

    if (i >= width) {
      sum -= numbers[i - width];
    }

    if (i >= width - 1) {
      result.push(sum / width);
    }
  }

  return result;
}
```

Наивный пересчет суммы окна на каждом шаге дал бы `O(n · width)`.

### Схема 3. Указатели по двум последовательностям

По каждой из двух последовательностей движется свой указатель. Классический
пример - слияние двух отсортированных массивов, шаг сортировки слиянием.

```js
/**
 * Сливает два отсортированных массива в один отсортированный.
 *
 * Время: O(n + m). Память: O(n + m) на результат.
 *
 * @param {number[]} first Первый массив, отсортированный по неубыванию.
 * @param {number[]} second Второй массив, отсортированный по неубыванию.
 * @returns {number[]} Отсортированный массив из всех элементов.
 */
function merge(first, second) {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < first.length && j < second.length) {
    // Нестрогое сравнение сохраняет относительный порядок равных элементов
    if (first[i] <= second[j]) {
      result.push(first[i]);
      i++;
    } else {
      result.push(second[j]);
      j++;
    }
  }

  // Один из массивов исчерпан; хвост второго дописывается как есть
  while (i < first.length) {
    result.push(first[i]);
    i++;
  }

  while (j < second.length) {
    result.push(second[j]);
    j++;
  }

  return result;
}
```

К этой же схеме относится проверка того, что одна строка является
подпоследовательностью другой: указатель по образцу продвигается только при
совпадении, указатель по тексту - всегда.

### Когда метод неприменим

Проверка сводится к одному вопросу: **можно ли, отвергнув текущую пару,
отбросить вместе с ней целую группу других?** Если нет, сдвиг указателя теряет
кандидатов, и ответ будет неверным.

Показательный пример - та же задача о паре с заданной суммой, но на
**неотсортированном** массиве. Сравнение суммы с целью больше ничего не
говорит о том, какой указатель двигать: слева и справа могут стоять числа
любой величины. Здесь двух указателей недостаточно, и задача решается либо
предварительной [сортировкой](../sprint-3/sorting.md#32-алгоритмы-сортировки) за
`O(n log n)`, либо [хеш-таблицей](../sprint-4/hash-tables.md#41-хеш-таблица-хеш-функция-свойства-хеш-функций)
за `O(n)` времени и `O(n)` памяти.

Скользящее окно точно так же ломается, если в массиве появляются отрицательные
числа: расширение окна перестает монотонно увеличивать сумму, и сжатие слева
уже не гарантирует возврат в допустимое состояние.

---

### Сводка

| Схема | Движение указателей | Условие применимости | Типичные задачи |
| --- | --- | --- | --- |
| Навстречу | с концов к середине | отсортированность или симметрия | пара с заданной суммой, палиндром |
| Скользящее окно | оба вперед | монотонность целевой величины | подотрезок с ограничением, скользящее среднее |
| По двум последовательностям | по своему массиву | обе упорядочены либо сопоставляются по порядку | слияние, подпоследовательность |

Во всех трех случаях время `O(n)`, дополнительная память `O(1)` - не считая
места под результат.
