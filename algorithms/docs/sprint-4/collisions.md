## 4.3 Коллизии

**Коллизия** - попадание двух разных ключей в одну корзину. Коллизии
неустранимы: ключей больше, чем корзин, поэтому вопрос не в том, случатся ли
они, а в том, что таблица будет делать, когда они случатся.

Существуют два подхода: хранить столкнувшиеся элементы **вне** массива корзин
(метод цепочек) или размещать их **в других корзинах** того же массива (метод
открытой адресации).

Ключевая величина для обоих - **коэффициент заполнения**:

```
α = N / M        N - число элементов, M - число корзин
```

### 4.3.1 Метод цепочек

Каждая корзина хранит ссылку на голову
[связного списка](../sprint-2/linked-lists.md#221-односвязный-список) всех
элементов, попавших в нее.

```
   корзины              цепочки

  0 ┌─────┐
    │  ●──┼──► [k=7, v=a] ──► [k=21, v=b] ──► null
  1 ├─────┤
    │ null│
  2 ├─────┤
    │  ●──┼──► [k=9, v=c] ──► null
  3 └─────┘
```

**Добавление ключа `k`:**

1. вычислить `x = h(k)`;
2. получить номер корзины `i = x mod M`;
3. пройти по цепочке `H[i]`: если ключ найден - обновить значение;
4. иначе вставить новый узел в начало цепочки.

**Поиск и удаление** повторяют первые три шага, отличаясь лишь действием на
найденном узле.

```js
class Node {
  /**
   * @param {*} key Ключ.
   * @param {*} value Значение.
   * @param {Node|null} next Следующий узел цепочки.
   */
  constructor(key, value, next = null) {
    this.key = key;
    this.value = value;
    this.next = next;
  }
}

class ChainedHashTable {
  /**
   * @param {number} bucketsCount Число корзин; рекомендуется простое число.
   */
  constructor(bucketsCount) {
    this.buckets = new Array(bucketsCount).fill(null);
    this.bucketsCount = bucketsCount;
    this.size = 0;
  }

  /**
   * Возвращает номер корзины для целочисленного ключа.
   *
   * Время: O(1).
   *
   * @param {number} key Ключ.
   * @returns {number} Номер корзины.
   */
  bucketOf(key) {
    return ((key % this.bucketsCount) + this.bucketsCount) % this.bucketsCount;
  }

  /**
   * Записывает значение по ключу, заменяя прежнее.
   *
   * Время: O(1 + α) в среднем, O(n) в худшем случае.
   *
   * @param {number} key Ключ.
   * @param {*} value Значение.
   * @returns {void}
   */
  put(key, value) {
    const index = this.bucketOf(key);

    for (let node = this.buckets[index]; node !== null; node = node.next) {
      if (node.key === key) {
        node.value = value;
        return;
      }
    }

    // Вставка в голову цепочки: O(1), порядок внутри корзины не важен
    this.buckets[index] = new Node(key, value, this.buckets[index]);
    this.size++;
  }

  /**
   * Возвращает значение по ключу.
   *
   * Время: O(1 + α) в среднем.
   *
   * @param {number} key Ключ.
   * @returns {*} Значение либо undefined, если ключа нет.
   */
  get(key) {
    const index = this.bucketOf(key);

    for (let node = this.buckets[index]; node !== null; node = node.next) {
      if (node.key === key) {
        return node.value;
      }
    }

    return undefined;
  }

  /**
   * Удаляет ключ из таблицы.
   *
   * Время: O(1 + α) в среднем.
   *
   * @param {number} key Ключ.
   * @returns {*} Удаленное значение либо undefined, если ключа нет.
   */
  delete(key) {
    const index = this.bucketOf(key);
    let previous = null;

    for (let node = this.buckets[index]; node !== null; node = node.next) {
      if (node.key === key) {
        if (previous === null) {
          this.buckets[index] = node.next;
        } else {
          previous.next = node.next;
        }

        this.size--;

        return node.value;
      }

      previous = node;
    }

    return undefined;
  }
}
```

**Сложность.** Вычисление хеша - `O(1)`, проход по цепочке - пропорционален ее
длине. При равномерной хеш-функции средняя длина цепочки равна `α`, поэтому
средняя стоимость операции составляет `O(1 + α)`. Слагаемое `1` учитывает
вычисление хеша, которое выполняется всегда, даже если корзина пуста.

Худший случай - `O(n)`: все ключи попали в одну корзину, и таблица выродилась в
связный список.

**Недостатки.** Каждый элемент требует отдельного узла, то есть выделения
памяти и хранения ссылки. Узлы разбросаны по памяти, поэтому проход по цепочке
страдает от промахов кэша - та же
[проблема, что и у связных списков](../sprint-2/linked-lists.md#список-против-массива).

Метод цепочек допускает `α > 1`: цепочки просто становятся длиннее.

### 4.3.2 Метод открытой адресации

Все элементы хранятся **в самом массиве корзин**. Если нужная корзина занята,
элемент записывается в другую, найденную по фиксированному правилу. Правило
обхода корзин называется **стратегией пробирования**.

Последовательность проб для ключа `k` - это `i₀, i₁, i₂, …`, где `iⱼ`
вычисляется по `h(k)` и номеру попытки `j`.

| Стратегия | Формула | Свойства |
| --- | --- | --- |
| Линейное пробирование | `(h(k) + j) mod M` | Просто, отличная локальность кэша, но образует кластеры |
| Квадратичное пробирование | `(h(k) + c₁j + c₂j²) mod M` | Кластеры меньше, но обходятся не все корзины |
| Двойное хеширование | `(h₁(k) + j · h₂(k)) mod M` | Лучшее распределение, шаг зависит от ключа |

**Кластеризация** - главная беда линейного пробирования. Занятые ячейки
слипаются в непрерывные участки, и чем длиннее участок, тем выше вероятность,
что следующий ключ попадет в него и удлинит еще сильнее. Среднее число проб
растет лавинообразно при приближении `α` к единице.

При двойном хешировании `h₂(k)` обязана быть взаимно простой с `M`, иначе
пробы зациклятся, не обойдя всех корзин. Проще всего это обеспечить, взяв `M`
простым и `h₂(k)` в диапазоне `1 … M − 1`.

#### Проблема удаления

Наивное удаление ломает таблицу, и это самая частая ошибка в реализациях.

Пусть ключи `A` и `B` дали один и тот же начальный индекс, и `B` при вставке
был вытеснен на следующую позицию:

```
индекс:    3      4      5
         [ A ]  [ B ]  [   ]

Удаляем A наивно, освобождая ячейку:

         [   ]  [ B ]  [   ]

Ищем B: начинаем с индекса 3, видим пустую ячейку - поиск
останавливается, и B объявляется отсутствующим, хотя он на месте.
```

Поиск обязан прекращаться на пустой ячейке - иначе при отсутствии ключа
пришлось бы просматривать всю таблицу. Значит, освобождать ячейку в середине
цепочки проб нельзя.

Решение - **надгробие** (tombstone): специальная пометка «здесь был элемент».
Поиск через надгробие проходит дальше, а вставка может занять его место.

```js
// Надгробие: ячейка освобождена, но цепочку проб не разрывает
const TOMBSTONE = Symbol('tombstone');

class OpenAddressingHashTable {
  /**
   * @param {number} bucketsCount Число корзин.
   */
  constructor(bucketsCount) {
    this.keys = new Array(bucketsCount).fill(undefined);
    this.values = new Array(bucketsCount).fill(undefined);
    this.bucketsCount = bucketsCount;
    this.size = 0;
  }

  /**
   * Возвращает индекс j-й пробы для ключа при линейном пробировании.
   *
   * Время: O(1).
   *
   * @param {number} key Ключ.
   * @param {number} attempt Номер попытки, начиная с нуля.
   * @returns {number} Номер корзины.
   */
  probe(key, attempt) {
    const start = ((key % this.bucketsCount) + this.bucketsCount) % this.bucketsCount;

    return (start + attempt) % this.bucketsCount;
  }

  /**
   * Записывает значение по ключу, заменяя прежнее.
   *
   * Время: O(1) в среднем при небольшом α.
   *
   * @param {number} key Ключ.
   * @param {*} value Значение.
   * @returns {void}
   * @throws {RangeError} Если свободных корзин не осталось.
   */
  put(key, value) {
    let firstTombstone = -1;

    for (let attempt = 0; attempt < this.bucketsCount; attempt++) {
      const index = this.probe(key, attempt);
      const slot = this.keys[index];

      if (slot === key) {
        this.values[index] = value;
        return;
      }

      // Надгробие запоминается, но поиск продолжается: такой же ключ
      // может лежать дальше по цепочке проб
      if (slot === TOMBSTONE) {
        if (firstTombstone === -1) {
          firstTombstone = index;
        }

        continue;
      }

      if (slot === undefined) {
        const target = firstTombstone === -1 ? index : firstTombstone;

        this.keys[target] = key;
        this.values[target] = value;
        this.size++;

        return;
      }
    }

    throw new RangeError('Таблица заполнена');
  }

  /**
   * Возвращает значение по ключу.
   *
   * Время: O(1) в среднем при небольшом α.
   *
   * @param {number} key Ключ.
   * @returns {*} Значение либо undefined, если ключа нет.
   */
  get(key) {
    for (let attempt = 0; attempt < this.bucketsCount; attempt++) {
      const index = this.probe(key, attempt);
      const slot = this.keys[index];

      // Только пустая ячейка останавливает поиск; надгробие - нет
      if (slot === undefined) {
        return undefined;
      }

      if (slot === key) {
        return this.values[index];
      }
    }

    return undefined;
  }

  /**
   * Удаляет ключ из таблицы, оставляя надгробие.
   *
   * Время: O(1) в среднем при небольшом α.
   *
   * @param {number} key Ключ.
   * @returns {*} Удаленное значение либо undefined, если ключа нет.
   */
  delete(key) {
    for (let attempt = 0; attempt < this.bucketsCount; attempt++) {
      const index = this.probe(key, attempt);
      const slot = this.keys[index];

      if (slot === undefined) {
        return undefined;
      }

      if (slot === key) {
        const value = this.values[index];

        this.keys[index] = TOMBSTONE;
        this.values[index] = undefined;
        this.size--;

        return value;
      }
    }

    return undefined;
  }
}
```

Надгробия накапливаются и постепенно удлиняют цепочки проб, поэтому таблицу с
открытой адресацией периодически перестраивают, даже если число элементов не
изменилось.

#### Сравнение методов

| | Цепочки | Открытая адресация |
| --- | --- | --- |
| Допустимый `α` | любой, в том числе `> 1` | строго `< 1`, на практике `≤ 0,7` |
| Память | указатель на элемент | только сам массив, без указателей |
| Локальность кэша | плохая | **хорошая** |
| Удаление | простое | требует надгробий |
| Деградация при росте `α` | плавная | резкая |

Открытая адресация быстрее при небольшом заполнении за счет того, что данные
лежат подряд. Цепочки надежнее и проще, поэтому именно их обычно выбирают в
учебных реализациях и в задачах, где важна предсказуемость.

## 4.4 Рехеширование

Размер таблицы должен соответствовать числу хранимых элементов. Слишком много
корзин - впустую расходуется память; слишком мало - цепочки удлиняются, и
операции замедляются.

Поскольку заранее число элементов неизвестно, таблица меняет размер на ходу -
как [динамический массив](../sprint-2/arrays.md#212-реаллокация-в-динамических-массивах).
Этот процесс называется **рехешированием**.

Оптимальный коэффициент заполнения для метода цепочек - примерно `1`: средняя
длина цепочки равна единице, то есть большинство операций обходятся одним
сравнением.

### 4.4.1 Изменение размера хеш-таблицы

**Шаг 1. Выбрать новый размер.** Число корзин вычисляется как `n / α₀`, где `n`
- число элементов, `α₀` - целевой коэффициент заполнения. Результат нужно
округлить до простого числа.

Искать простое число каждый раз накладно, поэтому хранят готовый список
размеров, в котором каждое следующее примерно вдвое больше предыдущего и все
числа простые:

```
7, 17, 31, 67, 127, 257, 509, 1021, 2053, 4099, 8191, …
```

Рост в постоянное число раз обязателен по той же причине, что и у динамического
массива: только он дает `O(1)` амортизированно.

**Шаг 2. Выделить новый массив корзин.** Старый в расчетах не участвует.

**Шаг 3. Перенести все элементы.** Номер корзины пересчитывается как
`h(k) mod M'` с новым `M'`. Сами хеши `h(k)` не меняются - функция
детерминирована и от размера таблицы не зависит. Если хеши сохранены рядом с
элементами, повторно вычислять их не нужно, и это главная экономия при
перестройке таблицы со строковыми ключами.

**Сложность.** Одно рехеширование стоит `O(n)`. Но при удвоении размера оно
происходит тем реже, чем больше таблица, и амортизированная стоимость на
операцию составляет `O(1)`.

Поскольку `α` удерживается в фиксированных пределах, `O(1 + α)` превращается
просто в `O(1)`. Отсюда стандартная формулировка: операции хеш-таблицы
выполняются за `O(1)` **в среднем амортизированно** - три оговорки, каждая из
которых существенна. «В среднем» - потому что худший случай `O(n)`;
«амортизированно» - потому что отдельная вставка может вызвать перестройку.

### 4.4.2 Идеальная хеш-функция

**Идеальная хеш-функция** отображает заданное конечное множество ключей в целые
числа **без коллизий**.

Применима, только если множество ключей известно заранее и конечно: шахматные
фигуры, регионы страны, дни недели, коды команд протокола.

Свойства такой таблицы:

- **рехеширование не нужно** - коллизий нет по построению, и размер выбирается
  сразу;
- **сжатие по модулю не нужно** - число ячеек берут равным максимальному
  значению хеша, и хеш используется прямо как индекс;
- **ключ можно не хранить** - хеш однозначно определяет ключ, поэтому в ячейке
  достаточно значения.

Если функция вдобавок **минимальна**, то есть отображает `n` ключей ровно в
`n` подряд идущих чисел, таблица не содержит ни одной пустой ячейки.

Простейший пример уже встречался: массив счетчиков в
[сортировке подсчетом](../sprint-3/sorting.md#326-сортировка-подсчетом) - это
хеш-таблица с идеальной хеш-функцией `h(k) = k − minValue`.
