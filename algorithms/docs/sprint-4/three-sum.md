## 4.7 Задача 3-sum

**Условие.** Дан массив чисел `x` и число `A`. Найти все тройки элементов, сумма
которых равна `A`. Тройки, отличающиеся лишь порядком, считаются одинаковой
тройкой и не должны дублироваться.

Задача показательна тем, что хеш-множество снижает степень перебора на единицу -
прием, применимый далеко за пределами этой конкретной задачи.

### Наивное решение

Три вложенных цикла перебирают все тройки индексов:

```js
/**
 * Возвращает все тройки элементов с заданной суммой.
 *
 * Время: O(n³). Память: O(размера ответа).
 *
 * @param {number[]} numbers Исходный массив.
 * @param {number} target Искомая сумма.
 * @returns {number[][]} Тройки элементов.
 */
function threeSumNaive(numbers, target) {
  const triples = [];

  for (let i = 0; i < numbers.length; i++) {
    for (let j = i + 1; j < numbers.length; j++) {
      for (let k = j + 1; k < numbers.length; k++) {
        if (numbers[i] + numbers[j] + numbers[k] === target) {
          triples.push([numbers[i], numbers[j], numbers[k]]);
        }
      }
    }
  }

  return triples;
}
```

Условие `j > i` и `k > j` исключает повторное рассмотрение одной и той же
тройки индексов. Но одинаковые **значения** на разных позициях по-прежнему
порождают дубликаты в ответе.

### Ловушка: множество массивов не дедуплицирует

Естественная попытка убрать дубликаты - складывать отсортированные тройки в
`Set`. Она не работает:

```js
const triples = new Set();

triples.add([1, 2, 3]);
triples.add([1, 2, 3]);

triples.size; // 2, а не 1
```

`Set` и `Map` сравнивают элементы по правилу `SameValueZero`, а для объектов
это сравнение **по ссылке**. Два массива с одинаковым содержимым - разные
объекты, поэтому оба попадают в множество.

Рабочий прием - приводить тройку к строке и использовать ее как ключ:

```js
const key = sortedTriple.join(',');
```

Разделитель обязателен: без него `[1, 23]` и `[12, 3]` дадут одинаковую строку
`«123»`. Для отрицательных чисел запятая тоже подходит, так как минус остается
частью числа.

### Решение за `O(n²)`

Идея: перебирать не три элемента, а два, а третий **искать в хеш-множестве** за
`O(1)`.

Массив предварительно сортируется. Это дает два преимущества: тройка сразу
получается упорядоченной, и ее строковое представление становится каноническим,
так что одинаковые по составу тройки склеиваются автоматически.

Множество `seen` содержит элементы, стоящие **левее** текущего `i`. Благодаря
этому каждая тройка `(seen, i, j)` рассматривается ровно в одном порядке
индексов.

```js
/**
 * Возвращает все различные тройки элементов с заданной суммой.
 *
 * Перебираются две позиции из трех, третий элемент ищется в хеш-множестве
 * ранее просмотренных значений за O(1). Массив сортируется заранее, поэтому
 * каждая найденная тройка сразу упорядочена, и ее строковое представление
 * годится как канонический ключ для устранения дубликатов.
 *
 * Время: O(n²) в среднем. Память: O(n + размер ответа).
 *
 * @param {number[]} numbers Исходный массив; не изменяется.
 * @param {number} target Искомая сумма.
 * @returns {number[][]} Тройки элементов в неубывающем порядке, без повторов.
 */
function threeSum(numbers, target) {
  const sorted = [...numbers].sort((a, b) => a - b);
  const triples = new Map();
  const seen = new Set();

  for (let i = 0; i < sorted.length; i++) {
    for (let j = i + 1; j < sorted.length; j++) {
      const missing = target - sorted[i] - sorted[j];

      if (seen.has(missing)) {
        const triple = [missing, sorted[i], sorted[j]];

        // Ключом служит строка, а не сам массив: Set и Map сравнивают
        // объекты по ссылке и одинаковые по содержимому тройки не склеили бы
        triples.set(triple.join(','), triple);
      }
    }

    // Элемент добавляется после обработки, поэтому seen всегда содержит
    // строго предшествующие элементы
    seen.add(sorted[i]);
  }

  return [...triples.values()];
}
```

Внешний и внутренний циклы дают `O(n²)`, проверка в множестве - `O(1)` в
среднем. Сортировка стоит `O(n log n)` и в итоговую оценку не входит.

### Вариант без хеш-таблицы

Ту же сложность дает метод
[двух указателей](../sprint-2/two-pointers.md#схема-1-указатели-навстречу-друг-другу).
Первый элемент тройки перебирается внешним циклом, а оставшиеся два ищутся
двумя указателями, идущими навстречу по отсортированному хвосту.

| | Через хеш-множество | Через два указателя |
| --- | --- | --- |
| Время | `O(n²)` в среднем | `O(n²)` **в худшем случае** |
| Дополнительная память | `O(n)` | `O(1)` |
| Устойчивость к неудачному хешу | нет | да |

Вариант с двумя указателями предпочтительнее: он дает гарантию вместо среднего
и не расходует дополнительной памяти. Вариант с множеством ценен как образец
общего приема - **свести перебор `k` элементов к перебору `k − 1` и поиску
последнего за `O(1)`**.

Тот же прием в другой форме встречается в
[динамическом программировании](../sprint-7/dynamic.md#два-условия-применимости):
там перебор тоже сокращается за счет того, что часть работы уже вычислена и
сохранена.
