## 4.1 Хеш-таблица, хеш-функция, свойства хеш-функций

### Задача, которую решает хеш-таблица

**Отображение** (map, словарь, ассоциативный массив) - структура данных,
хранящая пары «ключ - значение» и позволяющая по ключу получить значение.
Каждому ключу соответствует ровно одно значение.

Прямолинейная реализация - массив пар с линейным поиском:

```js
class Pair {
  constructor(key, value) {
    this.key = key;
    this.value = value;
  }
}

class NaiveMap {
  constructor() {
    this.pairs = [];
  }

  /**
   * Возвращает значение по ключу.
   *
   * Время: O(n) - просматриваются все пары.
   *
   * @param {*} key Искомый ключ.
   * @returns {*} Значение либо undefined, если ключа нет.
   */
  get(key) {
    for (const pair of this.pairs) {
      if (pair.key === key) {
        return pair.value;
      }
    }

    return undefined;
  }

  /**
   * Записывает значение по ключу, заменяя прежнее.
   *
   * Время: O(n).
   *
   * @param {*} key Ключ.
   * @param {*} value Значение.
   * @returns {void}
   */
  set(key, value) {
    for (const pair of this.pairs) {
      if (pair.key === key) {
        pair.value = value;
        return;
      }
    }

    this.pairs.push(new Pair(key, value));
  }
}
```

Обе операции стоят `O(n)`, потому что положение пары в массиве никак не связано
с ключом и его приходится искать перебором.

> Отсутствующий ключ здесь дает `undefined`, а не `null`. Разница существенна:
> `null` - допустимое хранимое значение, и возвращать его как признак
> отсутствия значит не уметь отличить «ключа нет» от «по ключу лежит `null`».
> Строгий вариант - отдельный метод `has`.

### Идея хеш-таблицы

Массив дает доступ по индексу за `O(1)`. Значит, если научиться **вычислять
индекс прямо из ключа**, поиск станет константным.

Именно это и делает хеш-таблица. Она хранит массив ячеек, называемых
**корзинами**, а положение пары определяется функцией от ключа.

```
        ключ                                   массив корзин
      "москва" ──► хеш-функция ──► 4728 ──► 4728 mod 7 = 3 ──► ┌───┐ 0
                                                                ├───┤ 1
                                                                ├───┤ 2
                                                                ├───┤ 3 ← сюда
                                                                ├───┤ 4
                                                                ├───┤ 5
                                                                └───┘ 6
```

**Хеш-функция** - функция, преобразующая данные произвольного вида в целое
число. Результат называется **хешем**.

**Коллизия** - ситуация, когда хеш-функция возвращает одно и то же значение для
разных ключей.

Коллизии неизбежны. Множество возможных ключей практически всегда больше
множества возможных значений хеша, а корзин тем более конечное число, - по
принципу Дирихле какие-то ключи обязаны попасть в одну корзину. Поэтому
хеш-таблица немыслима без [стратегии разрешения
коллизий](collisions.md#43-коллизии).

### Свойства хеш-функций

1. **Детерминированность.** Для одного и того же ключа функция всегда
   возвращает одно значение. Без этого найти ранее записанные данные
   невозможно.
2. **Эффективность.** Хеш должен вычисляться быстро. Стоимость операции в
   таблице складывается из вычисления хеша и работы внутри корзины; медленная
   хеш-функция обесценивает всю конструкцию.
3. **Ограниченность.** Номер корзины обязан попадать в диапазон `[0, M)`, где
   `M` - число корзин. Обычно хеш-функция возвращает произвольное целое, а
   сжатие в диапазон выполняется отдельным шагом.
4. **Равномерность.** Ключи должны распределяться по корзинам равномерно.
   Именно равномерность превращает `O(n)` в `O(1)`: если все ключи попадут в
   одну корзину, хеш-таблица выродится в тот самый линейный список.
5. **Лавинность.** Малое изменение ключа должно сильно менять хеш.
6. **Необратимость.** По значению хеша нельзя восстановить ключ.

Последние два свойства **не требуются** для хеш-таблиц. Лавинность и
необратимость нужны криптографическим хеш-функциям - там, где хеш защищает
данные: при хранении паролей, проверке целостности файлов, электронной подписи.

Разница практическая. Криптографические функции (`SHA-256` и подобные)
намеренно сделаны медленными и для хеш-таблицы не подходят: они нарушают
свойство эффективности. Для таблиц берут быстрые некриптографические функции,
от которых требуются только первые четыре свойства.

Есть, однако, случай, когда лавинность нужна и таблице. Если ключи приходят
извне, злоумышленник, зная хеш-функцию, может подобрать набор ключей с
одинаковым хешем и обрушить все операции до `O(n)`. Это называется атакой по
хеш-коллизиям, и защищаются от нее рандомизацией: в хеш подмешивают случайное
число, выбираемое при запуске программы.

## 4.2 Выбор размера хеш-таблицы и вычисление номера корзины

### 4.2.1 Выбор числа корзин

Число корзин `M` определяет и расход памяти, и вероятность коллизий. При методе
деления `M` следует брать **простым**.

Причина в том, что остаток по составному модулю теряет часть информации о
ключе. Пусть `M` и типичный шаг между ключами имеют общий делитель `d`. Тогда
все такие ключи попадут лишь в `M / d` корзин из `M`, а остальные останутся
пустыми.

Конкретно: пусть `M = 100`, а ключи - стоимости товаров, кратные 10.

```
ключи:   10, 20, 30, 40, …, 990
корзины: 10, 20, 30, 40, …, 90, 0   - заняты только 10 корзин из 100
```

Девяносто корзин не используются, а средняя длина цепочки в десять раз больше
расчетной. При `M = 101` (простое) те же ключи распределяются по всем корзинам.

Простое `M` не имеет общих делителей ни с каким шагом, кроме кратных самому
`M`, поэтому регулярность в данных не может «сложиться» с модулем.

Отдельно плох выбор `M = 2ᵏ`: остаток от деления на степень двойки - это просто
`k` младших битов ключа, а старшие биты отбрасываются полностью. Если ключи
различаются в основном старшими разрядами, все они попадут в одну корзину.

### 4.2.2 Вычисление номера корзины методом деления

Самый простой способ: номер корзины - остаток от деления хеша на число корзин.

```
bucket(k) = h(k) mod M
```

Любое целое `k` представимо как `k = j · M + r`, где `r ∈ [0, M)`. Число `r` и
есть остаток. Диапазон его значений - ровно `0 … M − 1`, то есть в точности
множество допустимых номеров корзин.

В JavaScript оператор `%` возвращает остаток **со знаком делимого**:
`-13 % 5 === -3`. Отрицательный индекс корзине не соответствует, поэтому
результат нужно приводить к неотрицательному:

```js
/**
 * Возвращает неотрицательный остаток от деления.
 *
 * Оператор % в JavaScript возвращает остаток со знаком делимого, поэтому
 * для отрицательных ключей его результат нельзя использовать как индекс.
 *
 * Время: O(1).
 *
 * @param {number} n Делимое.
 * @param {number} m Делитель, m > 0.
 * @returns {number} Остаток в диапазоне [0, m).
 */
function positiveModulo(n, m) {
  return ((n % m) + m) % m;
}

positiveModulo(-13, 5); // 2
```

### 4.2.3 Вычисление номера корзины по хешу

Полезно разделять два шага, которые легко перепутать:

1. **хеширование** - превращение ключа произвольного вида в целое число `h(k)`;
2. **сжатие** - превращение этого числа в номер корзины из `[0, M)`.

За первый шаг отвечает хеш-функция, за второй - таблица. Хеш-функция ничего не
знает о `M`.

Разделение принципиально по трем причинам.

**Хеш не зависит от размера таблицы.** При
[рехешировании](collisions.md#441-изменение-размера-хеш-таблицы) меняется `M`,
но не `h(k)`. Значит, вычисленные хеши можно сохранить рядом с элементами и при
перестройке таблицы не пересчитывать заново - а для длинных строк это самая
дорогая часть работы.

**Хеш-функцию можно менять независимо от таблицы.** Требования к ней
формулируются как «дай хорошо перемешанное число», без оглядки на текущее число
корзин.

**Сжатие может быть разным.** Метод деления и метод умножения - это два
способа выполнить именно второй шаг.

Типичная ошибка - использовать в качестве номера корзины младшие биты хеша
(`h(k) & (M − 1)` при `M = 2ᵏ`). Если хеш-функция плохо перемешивает младшие
разряды, вся информация из старших разрядов теряется. С методом деления по
простому модулю в результат вносят вклад все разряды хеша.

### 4.2.4 Вычисление номера корзины методом умножения

Альтернатива делению. Хеш умножается на константу `A ∈ (0, 1)`, берется дробная
часть произведения, и она растягивается на диапазон `[0, M)`:

```
bucket(k) = ⌊ M · { h(k) · A } ⌋        где { x } - дробная часть x
```

Главное достоинство - **`M` может быть любым**, в том числе степенью двойки.
Качество распределения обеспечивается константой `A`, а не модулем, поэтому
искать простые числа не нужно. При `M = 2ᵏ` умножение на `M` сводится к сдвигу,
и весь расчет выполняется без деления, что заметно быстрее.

Дональд Кнут рекомендует брать `A`, равное дробной части золотого сечения:

```
A = (√5 − 1) / 2 ≈ 0,6180339887
```

Это значение хорошо перемешивает последовательные ключи: соседние `k`
отображаются в далеко отстоящие точки отрезка `[0, 1)`.

```js
// Дробная часть золотого сечения: рекомендованный Кнутом множитель
const KNUTH_MULTIPLIER = (Math.sqrt(5) - 1) / 2;

/**
 * Возвращает номер корзины методом умножения.
 *
 * В отличие от метода деления, не предъявляет требований к числу корзин:
 * M может быть любым, включая степень двойки.
 *
 * Время: O(1).
 *
 * @param {number} hash Хеш ключа, неотрицательное целое число.
 * @param {number} bucketsCount Число корзин M.
 * @returns {number} Номер корзины в диапазоне [0, M).
 */
function multiplicativeBucket(hash, bucketsCount) {
  const product = hash * KNUTH_MULTIPLIER;
  const fraction = product - Math.floor(product);

  return Math.floor(bucketsCount * fraction);
}
```

Ограничение метода в JavaScript: числа хранятся как 64-битные вещественные, и
точность мантиссы - 53 бита. При очень больших хешах дробная часть произведения
вычисляется неточно, и распределение портится. Метод деления такой проблемы не
имеет.
