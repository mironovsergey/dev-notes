## 4.6 Поисковый индекс

**Поисковый индекс** - отображение, которое каждому объекту ставит в
соответствие его расположение.

Задача: есть `n` документов, приходят запросы из нескольких слов, для каждого
запроса нужно быстро найти наиболее подходящие документы.

### Почему прямой перебор не работает

Наивное решение просматривает при каждом запросе все документы. При `n = 10⁴`
документах и `m = 10⁴` запросах это `10⁸` просмотров текстов - заведомо за
пределами лимита.

Ключевое наблюдение: документы не меняются, а запросы приходят многократно.
Значит, разумно один раз выполнить дорогой предподсчет, чтобы каждый запрос
обрабатывался дешево. Это тот же размен, что и у
[префиксных хешей](string-hashing.md#хеши-подстрок-за-o1).

### Обратный индекс

**Прямой индекс** отвечает на вопрос «какие слова есть в документе» - это сам
документ. **Обратный индекс** (inverted index) отвечает на обратный вопрос: «в
каких документах встречается слово».

```
документы:
  0: «мама мыла раму»
  1: «мама варила суп»
  2: «раму мыла соседка»

обратный индекс:
  «мама»    → { 0: 1, 1: 1 }
  «мыла»    → { 0: 1, 2: 1 }
  «раму»    → { 0: 1, 2: 1 }
  «варила»  → { 1: 1 }
  «суп»     → { 1: 1 }
  «соседка» → { 2: 1 }
```

Значение - не просто список документов, а отображение «номер документа →
количество вхождений». Счетчик нужен для оценки релевантности.

```js
/**
 * Строит обратный индекс: слово → отображение «номер документа → число вхождений».
 *
 * Время: O(S), где S - суммарное число слов во всех документах.
 * Память: O(S).
 *
 * @param {string[]} documents Документы, по одному в строке.
 * @returns {Map<string, Map<number, number>>} Обратный индекс.
 */
function buildIndex(documents) {
  const index = new Map();

  for (let documentId = 0; documentId < documents.length; documentId++) {
    for (const word of documents[documentId].split(/\s+/)) {
      let occurrences = index.get(word);

      if (occurrences === undefined) {
        occurrences = new Map();
        index.set(word, occurrences);
      }

      occurrences.set(documentId, (occurrences.get(documentId) ?? 0) + 1);
    }
  }

  return index;
}
```

### Релевантность

Релевантность документа для запроса - сумма числа вхождений каждого
**уникального** слова запроса в этот документ.

Уникальность существенна: если слово встречается в запросе дважды, его вклад
все равно учитывается один раз. Дедупликация выполняется множеством.

```js
/**
 * Возвращает релевантность документов для запроса.
 *
 * В результат попадают только документы, содержащие хотя бы одно слово
 * запроса. Это принципиально: заводить счетчик для каждого из n документов
 * означало бы O(n) работы на запрос независимо от того, сколько документов
 * реально подходит.
 *
 * Время: O(размер ответа по индексу). Память: O(числа подходящих документов).
 *
 * @param {string} query Поисковый запрос.
 * @param {Map<string, Map<number, number>>} index Обратный индекс.
 * @returns {Map<number, number>} Отображение «номер документа → релевантность».
 */
function relevance(query, index) {
  const scores = new Map();

  for (const word of new Set(query.split(/\s+/))) {
    const occurrences = index.get(word);

    if (occurrences === undefined) {
      continue;
    }

    for (const [documentId, count] of occurrences) {
      scores.set(documentId, (scores.get(documentId) ?? 0) + count);
    }
  }

  return scores;
}
```

### Главная ловушка

Естественная, но неверная реализация - завести массив релевантностей длины `n`
и обнулить его перед каждым запросом:

```js
// Так делать нельзя
const scores = new Array(documents.length).fill(0);
```

Такой массив стоит `O(n)` **на каждый запрос**, даже если запрос состоит из
одного редкого слова, встречающегося в двух документах. При `n = 10⁴` и
`m = 10⁴` это `10⁸` операций только на создание и обнуление массивов, не считая
последующего просмотра.

Отображение вместо массива устраняет зависимость от общего числа документов:
работа пропорциональна числу документов, реально содержащих слова запроса.
Именно на это намекает условие задачи, спрашивая, что будет, если слова запроса
встречаются в малом числе документов.

### Ранжирование

Документы упорядочиваются по убыванию релевантности, а при равной релевантности
- по возрастанию номера. Второй критерий обязателен: без него порядок документов
с одинаковым весом не определен, и ответ становится неоднозначным.

```js
/**
 * Возвращает номера наиболее релевантных документов.
 *
 * @param {Map<number, number>} scores Релевантности документов.
 * @param {number} limit Максимальное количество документов в ответе.
 * @returns {number[]} Номера документов, нумерация с единицы.
 */
function topDocuments(scores, limit) {
  return [...scores.entries()]
    .sort((a, b) => b[1] - a[1] || a[0] - b[0])
    .slice(0, limit)
    .map(([documentId]) => documentId + 1);
}
```

Полная сортировка избыточна, когда нужны лишь первые несколько документов: тот
же результат дает частичный выбор за `O(k log limit)`, где `k` - число
подходящих документов. На практике `k` обычно мало, и разница несущественна.
