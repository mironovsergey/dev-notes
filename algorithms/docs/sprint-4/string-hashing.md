## 4.5 Построение хеш-функций для строк, полиномиальное хеширование

Хеш-функция для целого ключа очевидна - сам ключ. Для строки нужно свернуть
последовательность символов в одно число, причем так, чтобы разные строки почти
всегда давали разные числа.

Наивные варианты не годятся. Сумма кодов символов дает одинаковый хеш всем
анаграммам: `«abc»` и `«cba»` неразличимы. Длина строки не различает даже
`«aaa»` и `«zzz»`. Нужна функция, учитывающая и сами символы, и их **порядок**.

### Формула

**Полиномиальное хеширование** трактует строку как запись числа в системе
счисления с основанием `q`, где цифры - коды символов:

```
h(s) = (s₁·qⁿ⁻¹ + s₂·qⁿ⁻² + … + sₙ₋₁·q + sₙ) mod R
```

Здесь `sᵢ` - код `i`-го символа, `n` - длина строки, `q` и `R` - выбранные
константы.

Позиция символа задает степень `q`, поэтому перестановка символов меняет хеш -
именно этого не хватало сумме кодов.

Взятие по модулю `R` обязательно: без него значение растет экспоненциально с
длиной строки и мгновенно выходит за пределы точности чисел.

### Метод Горнера

Вычислять степени `q` по отдельности не нужно. Многочлен переписывается так,
что на каждом шаге выполняются одно умножение и одно сложение:

```
h(s) = ((…((s₁·q + s₂)·q + s₃)·q + … )·q + sₙ) mod R
```

Проверка на строке `«abc»` при `q = 31`: коды символов `97, 98, 99`.

```
прямая формула:  97·31² + 98·31 + 99 = 93217 + 3038 + 99 = 96354
метод Горнера:   (97·31 + 98)·31 + 99 = 3105·31 + 99 = 96255 + 99 = 96354
```

Обратите внимание, что первый шаг - это `s₁·q + s₂`, а **не** `(s₁ + s₂)·q`:
второй вариант дает `(97 + 98)·31 + 99 = 6144` и с формулой не совпадает.

```js
/**
 * Возвращает полиномиальный хеш строки, вычисленный методом Горнера.
 *
 * Взятие остатка на каждом шаге удерживает промежуточные значения в пределах
 * [0, m), поэтому переполнения не происходит независимо от длины строки.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {string} s Хешируемая строка.
 * @param {number} q Основание, по которому считается хеш.
 * @param {number} m Модуль.
 * @returns {number} Хеш строки в диапазоне [0, m).
 */
function polynomialHash(s, q, m) {
  let hash = 0;

  for (let i = 0; i < s.length; i++) {
    hash = (hash * q + s.charCodeAt(i)) % m;
  }

  return hash;
}
```

Пустая строка дает хеш `0` - цикл не выполняется ни разу.

### Выбор констант

**Основание `q`** должно быть больше размера алфавита, иначе разные символы
начнут смешиваться при переносе разрядов. Для строчных латинских букв подходит
любое `q ≥ 27`; на практике берут простое число вроде `31`, `53` или `257`.

**Модуль `R`** берут большим простым числом. Чем он больше, тем реже коллизии:
при случайных строках вероятность совпадения хешей двух конкретных строк
примерно `1 / R`.

### Ограничение точности в JavaScript

Все числа в JavaScript - 64-битные вещественные, целые представляются точно
лишь до `2⁵³ ≈ 9 · 10¹⁵`. Это накладывает ограничение на произведения.

В `polynomialHash` перемножаются `hash < m` и `q`, поэтому требуется
`m · q < 2⁵³`. При `q ≤ 1000` это допускает `m` примерно до `9 · 10¹²` -
запас большой.

Но как только перемножаются **два остатка** по модулю `m`, ограничение
становится `m² < 2⁵³`, то есть `m < 9,4 · 10⁷`. Именно это и происходит при
вычислении хеша подстроки ниже. Превышение не дает ошибки - результат просто
молча теряет младшие разряды, и хеши перестают совпадать там, где должны.

Обойти ограничение можно типом `BigInt`, но он на порядок медленнее, поэтому в
задачах на время предпочитают удерживать модуль в безопасных пределах.

### Хеши подстрок за `O(1)`

Полиномиальный хеш обладает свойством, ради которого его в основном и
применяют: зная хеши всех **префиксов** строки, хеш любой подстроки можно
получить за константное время.

Пусть `H[i]` - хеш префикса длины `i`. Тогда

```
h(s[l..r]) = (H[r] − H[l−1] · q^(r−l+1)) mod m
```

Смысл прост: `H[r]` содержит вклад префикса `s[1..l−1]`, сдвинутый на
`r − l + 1` позиций влево, - его и нужно вычесть.

```js
/**
 * Вычисляет хеши всех префиксов строки и степени основания.
 *
 * Время: O(n). Память: O(n).
 *
 * @param {string} s Исходная строка.
 * @param {number} q Основание, по которому считается хеш.
 * @param {number} m Модуль; должен удовлетворять m² < 2^53.
 * @returns {{hashes: number[], powers: number[]}} Массивы длины n + 1:
 *   hashes[i] - хеш префикса длины i, powers[i] - q^i по модулю m.
 */
function calculatePrefixHashes(s, q, m) {
  const hashes = new Array(s.length + 1).fill(0);
  const powers = new Array(s.length + 1).fill(1);

  for (let i = 1; i <= s.length; i++) {
    powers[i] = (powers[i - 1] * q) % m;
    hashes[i] = (hashes[i - 1] * q + s.charCodeAt(i - 1)) % m;
  }

  return { hashes, powers };
}

/**
 * Возвращает хеш подстроки по предвычисленным хешам префиксов.
 *
 * Время: O(1). Память: O(1).
 *
 * @param {number[]} hashes Хеши префиксов из calculatePrefixHashes.
 * @param {number[]} powers Степени основания из calculatePrefixHashes.
 * @param {number} l Индекс начала подстроки, нумерация с единицы.
 * @param {number} r Индекс конца подстроки включительно, нумерация с единицы.
 * @param {number} m Модуль.
 * @returns {number} Хеш подстроки в диапазоне [0, m).
 */
function calculateSubstringHash(hashes, powers, l, r, m) {
  const difference = (hashes[r] - hashes[l - 1] * powers[r - l + 1]) % m;

  // Разность может оказаться отрицательной: остаток в JavaScript
  // берет знак делимого
  return (difference + m) % m;
}
```

Предподсчет стоит `O(n)`, каждый последующий запрос - `O(1)`. Именно это
превращает наивное сравнение подстрок за `O(n)` в константное и лежит в основе
алгоритма Рабина - Карпа - вероятностной альтернативы
[алгоритму Кнута - Морриса - Пратта](../sprint-8/prefix-function.md#85-эффективный-поиск-шаблона-в-строке).

На тех же префиксных хешах строится
[быстрое сравнение строк](../sprint-8/string-compare.md#87-быстрое-сравнение-двух-строк)
из восьмого спринта.

### Коллизии и их подбор

Равенство хешей **не гарантирует** равенства строк. Программа, сравнивающая
строки только по хешам, ошибается на коллизиях, и такие коллизии можно
целенаправленно подобрать.

Лобовой перебор здесь неэффективен: чтобы подобрать строку под **заданный** хеш,
нужно в среднем `m` попыток. При `m ≈ 1,2 · 10⁸` это десятки секунд.

Правильный прием - **парадокс дней рождения**. Вместо подбора под фиксированный
хеш генерируются случайные строки, их хеши складываются в словарь, и поиск
прекращается на первом повторе. Достаточно примерно `√(π·m / 2)` строк - при
том же `m` это около **14 000** попыток вместо `1,2 · 10⁸`, то есть в четыре
порядка меньше.

```js
/**
 * Находит две различные строки с одинаковым полиномиальным хешем.
 *
 * Используется парадокс дней рождения: коллизия среди случайных строк
 * находится примерно за √m попыток, тогда как подбор под заранее заданный хеш
 * потребовал бы порядка m попыток.
 *
 * Время: O(√m) в среднем. Память: O(√m).
 *
 * @param {number} q Основание, по которому считается хеш.
 * @param {number} m Модуль.
 * @param {number} length Длина генерируемых строк.
 * @returns {[string, string]} Две различные строки с равными хешами.
 */
function findCollision(q, m, length) {
  const seen = new Map();

  for (;;) {
    const candidate = randomString(length);

    if (seen.has(candidate)) {
      continue;
    }

    const hash = polynomialHash(candidate, q, m);
    const previous = seen.get(hash);

    if (previous !== undefined && previous !== candidate) {
      return [previous, candidate];
    }

    seen.set(hash, candidate);
  }
}
```

Практический вывод: хеш годится как **быстрый фильтр**, отсекающий заведомо
разные строки, но при совпадении хешей строки нужно сравнивать посимвольно.
Исключение - задачи, где вероятностной гарантии достаточно; тогда защищаются
двойным хешированием по двум разным модулям, что снижает вероятность коллизии
до `1 / (m₁·m₂)`.
