## 3.1 Рекурсия

**Рекурсия** - прием, при котором функция для решения задачи вызывает саму себя
на меньших входных данных.

Рекурсия применима, когда задача обладает свойством самоподобия: ее решение
выражается через решения таких же задач меньшего размера. Обход дерева
каталогов, разбор вложенных структур, деление отрезка пополам, перебор
вариантов - все это устроено рекурсивно по своей природе.

### Рекурсия против явного стека

Любой рекурсивный алгоритм можно переписать циклом с явной структурой данных, и
наоборот. Разница только в том, кто хранит состояние незавершенных шагов:
[стек вызовов](../sprint-2/stack-and-queue.md#применение-стек-вызовов) или ваш
собственный контейнер.

Поиск файла в дереве каталогов с явной очередью:

```js
const fs = require('fs');
const path = require('path');

/**
 * Ищет файл с заданным именем в каталоге и его подкаталогах.
 *
 * Обход в ширину: очередь хранит еще не просмотренные пути.
 *
 * @param {string} folder Каталог, с которого начинается поиск.
 * @param {string} fileToFind Имя искомого файла.
 * @returns {string|null} Полный путь к файлу либо null, если файл не найден.
 */
function findFileWithQueue(folder, fileToFind) {
  const queue = [folder];

  while (queue.length > 0) {
    const item = queue.shift();

    if (fs.statSync(item).isDirectory()) {
      for (const entry of fs.readdirSync(item)) {
        queue.push(path.join(item, entry));
      }
    } else if (path.basename(item) === fileToFind) {
      return item;
    }
  }

  return null;
}
```

Тот же поиск рекурсией:

```js
/**
 * Ищет файл с заданным именем в каталоге и его подкаталогах.
 *
 * Обход в глубину: состояние незавершенных шагов хранит стек вызовов.
 *
 * @param {string} folder Каталог, с которого начинается поиск.
 * @param {string} fileToFind Имя искомого файла.
 * @returns {string|null} Полный путь к файлу либо null, если файл не найден.
 */
function findFileRecursive(folder, fileToFind) {
  for (const entry of fs.readdirSync(folder)) {
    const entryPath = path.join(folder, entry);

    if (fs.statSync(entryPath).isDirectory()) {
      const found = findFileRecursive(entryPath, fileToFind);

      // Результат нужно передать вверх по цепочке вызовов явно
      if (found !== null) {
        return found;
      }
    } else if (entry === fileToFind) {
      return entryPath;
    }
  }

  return null;
}
```

Рекурсивная версия короче и ближе к структуре задачи. Взамен она расходует стек
вызовов и не дает управлять порядком обхода так же гибко, как явная очередь: с
очередью получается обход в ширину, с рекурсией - в глубину.

### Прямой и обратный ход

У рекурсии два хода. **Прямой** - углубление вызовов; **обратный** -
возвращение из них. Действия, записанные до рекурсивного вызова, выполняются на
прямом ходу, записанные после - на обратном, в обратном порядке.

```js
/**
 * Печатает порядок сборки матрешки из n вложенных фигур.
 *
 * @param {number} size Размер текущей фигуры.
 * @param {number} depth Количество оставшихся вложений.
 * @returns {void}
 */
function buildMatryoshka(size, depth) {
  if (depth < 1) {
    return;
  }

  console.log(`Создаем низ матрешки размера ${size}.`);
  buildMatryoshka(size - 1, depth - 1);
  console.log(`Создаем верх матрешки размера ${size}.`);
}

buildMatryoshka(4, 3);
// Создаем низ матрешки размера 4.   ← прямой ход
// Создаем низ матрешки размера 3.
// Создаем низ матрешки размера 2.
// Создаем верх матрешки размера 2.  ← обратный ход
// Создаем верх матрешки размера 3.
// Создаем верх матрешки размера 4.
```

Низы печатаются в порядке убывания размера, верхи - в порядке возрастания.
Симметрия и есть наглядное проявление стека: последний начатый вызов
завершается первым.

Это различие принципиально при проектировании алгоритмов. В
[сортировке слиянием](sorting.md#324-сортировка-слиянием) вся полезная работа
происходит на обратном ходу, в [быстрой сортировке](sorting.md#325-быстрая-сортировка)
- на прямом.

### Цена рекурсии

Каждый незавершенный вызов занимает кадр в стеке, поэтому **глубина рекурсии
равна дополнительной памяти**: рекурсия глубины `d` стоит `O(d)` памяти сверх
самого алгоритма.

Практический предел - порядка десяти тысяч кадров. Поэтому рекурсия глубины
`O(log n)` безопасна при любом разумном `n`, а рекурсия глубины `O(n)` при
`n = 10⁵` гарантированно завершится ошибкой
`RangeError: Maximum call stack size exceeded`.

Второй источник затрат - повторные вычисления. Прямолинейная рекурсия для чисел
Фибоначчи

```js
function fibonacci(n) {
  if (n <= 1) {
    return n;
  }

  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

пересчитывает одни и те же значения экспоненциальное число раз и работает за
[`O(2ⁿ)`](../sprint-1/complexity.md#145-экспоненциальная---o2ⁿ): уже при
`n = 50` это неприемлемо. Лечится запоминанием вычисленных значений - этот
прием разбирается в [седьмом спринте](../sprint-7/README.md).

### 3.1.1 Рекурсивный и базовый случаи

Корректная рекурсия состоит из двух обязательных частей:

- **базовый случай** - вариант, который решается напрямую, без рекурсивного
  вызова; он останавливает углубление и запускает обратный ход;
- **рекурсивный случай** - сведение задачи к такой же задаче меньшего размера.

```js
/**
 * Возвращает двоичную запись целого числа.
 *
 * Время: O(log n). Память: O(log n) на кадры стека вызовов.
 *
 * @param {number} n Целое число.
 * @returns {string} Двоичное представление числа.
 */
function asBinaryString(n) {
  if (n < 0) {
    return `-${asBinaryString(-n)}`;
  }

  // Базовый случай: числа 0 и 1 записываются сами собой
  if (n === 0 || n === 1) {
    return `${n}`;
  }

  // Рекурсивный случай: старшие разряды получаются из n / 2,
  // младший разряд - это остаток от деления на 2
  return asBinaryString(Math.floor(n / 2)) + `${n % 2}`;
}
```

Разряды приписываются на обратном ходу: сначала рекурсия доходит до старшего
разряда, а затем на подъеме дописывает младшие.

#### Три условия корректности

Чтобы рекурсия завершилась и дала верный ответ, должны выполняться все три
условия:

1. **Базовый случай существует и достижим.** Отсутствие базы - бесконечная
   рекурсия и переполнение стека.
2. **Рекурсивный вызов уменьшает задачу.** Каждый шаг обязан приближать вход к
   базовому случаю. Вызов `f(n)` внутри `f(n)` или `f(n - 0)` не приближает.
3. **База покрывает все терминальные варианты.** Если база проверяет `n === 1`,
   а рекурсия может привести к `n === 0`, углубление проскочит базу и уйдет в
   отрицательные значения.

Третье условие нарушается чаще всего. В `asBinaryString` база проверяет и `0`, и
`1` именно поэтому: проверки только `n === 1` не хватило бы для нулевого
аргумента.

#### Соответствие индукции

Рекурсия - это математическая индукция, записанная кодом. Базовый случай
соответствует базе индукции, рекурсивный - индукционному переходу. Поэтому
доказательство корректности строится так же: проверить базу и убедиться, что
шаг сохраняет требуемое свойство при условии, что оно верно для меньших входов.

При написании рекурсивной функции полезно **предположить, что она уже работает
правильно** для меньших входов, и написать только один шаг. Попытка
мысленно раскрутить всю цепочку вызовов почти всегда приводит к путанице.

### 3.1.2 Рекурсивный бинарный поиск

[Бинарный поиск](../sprint-1/search.md#17-бинарный-поиск) - естественно
рекурсивный алгоритм: сравнение со средним элементом сводит задачу к такой же
задаче на вдвое меньшем диапазоне.

Реализация ведется на полуинтервале `[left, right)` - той же конвенции, что и в
итеративной версии первого спринта. Базовый случай - пустой диапазон.

```js
/**
 * Возвращает индекс значения в отсортированном по неубыванию массиве.
 *
 * Время: O(log n). Память: O(log n) на кадры стека вызовов.
 *
 * @param {number[]} numbers Массив, отсортированный по неубыванию.
 * @param {number} target Искомое значение.
 * @param {number} left Левая граница диапазона поиска, включительно.
 * @param {number} right Правая граница диапазона поиска, исключительно.
 * @returns {number} Индекс одного из вхождений либо -1, если значение отсутствует.
 */
function binarySearchRecursive(
  numbers,
  target,
  left = 0,
  right = numbers.length,
) {
  // Базовый случай: диапазон пуст, значения в массиве нет
  if (left >= right) {
    return -1;
  }

  const middle = left + Math.floor((right - left) / 2);

  if (numbers[middle] === target) {
    return middle;
  }

  if (numbers[middle] < target) {
    return binarySearchRecursive(numbers, target, middle + 1, right);
  }

  return binarySearchRecursive(numbers, target, left, middle);
}
```

Каждый вызов делает `O(1)` работы и порождает **один** рекурсивный вызов, а
глубина равна числу делений пополам - `O(log n)`. Отсюда `O(log n)` времени.

#### Хвостовая рекурсия и почему на практике пишут цикл

Рекурсивный вызов здесь - последнее действие функции, ее результат
возвращается без изменений. Такая рекурсия называется **хвостовой**, и ее
можно механически превратить в цикл: вместо нового вызова достаточно
переприсвоить параметры и повторить тело.

Некоторые языки выполняют это преобразование сами. **JavaScript этого не
делает** - оптимизация хвостовых вызовов описана в стандарте, но в
распространенных движках не реализована. Поэтому рекурсивная версия реально
расходует `O(log n)` памяти на стек, тогда как итеративной хватает `O(1)`.

Для бинарного поиска разница невелика: при `n = 10⁹` глубина всего 30 кадров.
Но правило общее - **если рекурсия хвостовая, цикл предпочтительнее**: та же
логика, меньше расход памяти, нет риска переполнения стека.

Рекурсия оправдана там, где вызовов **несколько** и их результаты нужно
объединять: [обход дерева](../sprint-5/traversal.md#53-обход-дерева),
[сортировка слиянием](sorting.md#324-сортировка-слиянием), перебор вариантов.
Свести такую рекурсию к циклу без явного стека уже не получится.

### 3.1.3 Рекурсивный перебор вариантов

Задача перебора: построить все объекты, удовлетворяющие условию. Рекурсия
строит их **по одному элементу за шаг**, а разные варианты выбора на каждом шаге
порождают ветвление.

Пример: напечатать все последовательности длины `n` из нулей и единиц.

```js
/**
 * Печатает все последовательности заданной длины из нулей и единиц
 * в лексикографическом порядке.
 *
 * Время: O(n · 2ⁿ). Память: O(n) на кадры стека вызовов.
 *
 * @param {number} remaining Количество еще не выбранных символов.
 * @param {string} prefix Уже построенная часть последовательности.
 * @returns {void}
 */
function generateBinary(remaining, prefix = '') {
  if (remaining === 0) {
    console.log(prefix);
    return;
  }

  generateBinary(remaining - 1, `${prefix}0`);
  generateBinary(remaining - 1, `${prefix}1`);
}

generateBinary(3);
// 000  001  010  011  100  101  110  111
```

Перебор удобно представлять деревом решений: каждый уровень - очередная
позиция, каждое ребро - вариант выбора, каждый лист - готовый ответ.

```
                      ""
              ┌────────┴────────┐
              0                 1
         ┌────┴────┐       ┌────┴────┐
        00        01      10        11
       ┌─┴─┐     ┌─┴─┐   ┌─┴─┐     ┌─┴─┐
     000  001  010 011 100 101   110 111
```

Порядок обхода дерева в глубину слева направо и дает лексикографический
порядок результатов - при условии, что варианты на каждом шаге перебираются по
возрастанию. Дополнительно сортировать результат не нужно.

#### Общая схема

Перебор с возвратом (backtracking) всегда имеет одну и ту же структуру:

```
если решение построено полностью:
    записать его и вернуться
иначе:
    для каждого допустимого варианта на текущем шаге:
        сделать выбор
        рекурсивный вызов для следующего шага
        отменить выбор
```

Отмена выбора нужна, когда состояние изменяется на месте - например, при
использовании общего массива. В примере выше ее нет: `prefix` - неизменяемая
строка, и каждая ветвь получает собственную копию. Это проще, но расходует
`O(n)` памяти на каждый уровень.

#### Отсечение

Число листьев дерева перебора растет экспоненциально, и уменьшить его
асимптотически нельзя, если требуется вывести все варианты: их просто столько.
Но можно **не строить заведомо тупиковые ветви**.

Пример: сгенерировать все правильные скобочные последовательности из `n` пар
скобок. Наивный подход - перебрать все `2²ⁿ` строк и отфильтровать правильные.
Отсечение позволяет строить только правильные:

```js
/**
 * Возвращает все правильные скобочные последовательности из n пар скобок
 * в лексикографическом порядке.
 *
 * Ветви, из которых правильную последовательность получить уже нельзя,
 * не строятся: открывающих скобок не может быть больше n, а закрывающих -
 * больше, чем уже открытых.
 *
 * @param {number} n Количество пар скобок.
 * @returns {string[]} Все правильные последовательности длины 2n.
 */
function generateBrackets(n) {
  const result = [];

  const backtrack = (prefix, open, close) => {
    if (prefix.length === 2 * n) {
      result.push(prefix);
      return;
    }

    if (open < n) {
      backtrack(`${prefix}(`, open + 1, close);
    }

    if (close < open) {
      backtrack(`${prefix})`, open, close + 1);
    }
  };

  backtrack('', 0, 0);

  return result;
}
```

Два условия - `open < n` и `close < open` - и есть отсечение. Без них дерево
имело бы `2²ⁿ` листьев, с ними их ровно столько, сколько правильных
последовательностей: `Cₙ` - `n`-е число Каталана, что примерно в `n^1,5` раз
меньше.

Скобка `(` перебирается раньше `)`, потому что в таблице символов она идет
раньше, - благодаря этому результат сразу получается лексикографически
упорядоченным.
