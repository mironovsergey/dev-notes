## 3.2 Алгоритмы сортировки

**Сортировка** - перестановка элементов последовательности в порядке
неубывания заданного признака.

Сортировка редко является самоцелью. Ее ценность в том, что упорядоченные
данные допускают приемы, невозможные на неупорядоченных:
[бинарный поиск](../sprint-1/search.md#17-бинарный-поиск),
[метод двух указателей](../sprint-2/two-pointers.md#26-метод-двух-указателей),
поиск дубликатов за один проход. Поэтому сортировка за `O(n log n)` часто
окупается даже ради одной последующей операции.

### Ключ сортировки

Признак, по которому сравниваются элементы, называется **ключом сортировки**.
Задать порядок можно двумя способами.

**Функция ключа** `key(item)` применяется к каждому элементу, и сравниваются
уже полученные значения:

```js
// Длины слов «ноль», «один», «два», …
const DIGIT_LENGTHS = [4, 4, 3, 3, 6, 4, 5, 4, 6, 6];

/**
 * Сортирует массив вставками по значению функции ключа.
 *
 * Время: O(n²) сравнений. Память: O(1).
 *
 * @param {number[]} items Сортируемый массив; изменяется на месте.
 * @param {(item: number) => number} key Функция вычисления ключа.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию ключа.
 */
function insertionSortByKey(items, key) {
  for (let i = 1; i < items.length; i++) {
    const current = items[i];
    const currentKey = key(current);
    let j = i - 1;

    while (j >= 0 && key(items[j]) > currentKey) {
      items[j + 1] = items[j];
      j--;
    }

    items[j + 1] = current;
  }

  return items;
}

insertionSortByKey([3, 7, 9, 2, 3], (card) => DIGIT_LENGTHS[card]);
// [3, 2, 3, 7, 9] - «три», «два», «три», «семь», «девять»
// Длины 3, 3, 3, 4, 6. Три карты с равным ключом сохранили исходный
// относительный порядок - сортировка вставками устойчива
```

**Компаратор** `compare(a, b)` сравнивает два элемента напрямую. В JavaScript
принято соглашение о числовом результате: отрицательное значение означает, что
`a` идет раньше `b`, положительное - позже, ноль - порядок безразличен. Именно
такой компаратор принимает встроенный `Array.prototype.sort`.

Функция ключа удобнее, когда порядок определяется одним вычислимым признаком;
компаратор - когда правило сравнения сложное или многоступенчатое.

### Ловушка: составной ключ в JavaScript

Многоступенчатый порядок часто пытаются задать массивом-ключом: сравнить по
первому признаку, при равенстве - по второму. Прием стандартный, но **в
JavaScript в лоб он не работает**.

```js
const keyForCard = (card) => [-DIGIT_LENGTHS[card], card];

// Так делать нельзя
[2, 3, 4, 7, 8].sort((a, b) => (keyForCard(a) < keyForCard(b) ? -1 : 1));
// [2, 3, 7, 4, 8] - неверно
```

Причина в том, что оператор `<` не сравнивает массивы поэлементно. Он приводит
операнды к примитивам, то есть к строкам, и сравнивает их **лексикографически
посимвольно**:

```js
keyForCard(4) < keyForCard(2);
// [-6, 4] < [-3, 2]  →  '-6,4' < '-3,2'  →  false
// хотя поэлементно -6 < -3, то есть должно быть true
```

Символ `'6'` больше символа `'3'`, и знак минуса при этом никак не
учитывается. Корректный способ - сравнивать признаки по очереди явно:

```js
[2, 3, 4, 7, 8].sort(
  (a, b) => DIGIT_LENGTHS[b] - DIGIT_LENGTHS[a] || a - b,
);
// [4, 8, 7, 2, 3] - верно
```

Оператор `||` здесь работает как переход ко второму признаку: если разность
первых ключей равна нулю, вычисляется следующее выражение.

Отдельно стоит запомнить, что `Array.prototype.sort` **без компаратора**
сортирует как строки, поэтому `[10, 9, 1].sort()` дает `[1, 10, 9]`. Для чисел
компаратор обязателен всегда.

### Устойчивость

Сортировка **устойчива** (stable), если элементы с равными ключами сохраняют
исходный относительный порядок. Иначе она неустойчива.

```
Исходный массив (ключ - число, буква - метка элемента):

    2a   2b   1c

Устойчивая сортировка:     1c   2a   2b     ← 2a по-прежнему раньше 2b
Неустойчивая сортировка:   1c   2b   2a     ← порядок равных нарушен
```

Свойство важно при **многоключевой сортировке**. Чтобы упорядочить таблицу
сначала по одному столбцу, а внутри групп - по другому, достаточно устойчиво
отсортировать ее сначала по второму признаку, затем по первому. С неустойчивой
сортировкой такой прием неприменим - второй проход разрушит результат первого.

### Нижняя граница для сортировок сравнением

Алгоритм, который получает информацию о порядке **только через сравнения
элементов**, не может работать быстрее чем за `Ω(n log n)` в худшем случае.

Доказательство короткое. Работу такого алгоритма можно изобразить деревом
решений: узел - сравнение, две ветви - два его исхода, лист - итоговая
перестановка. Различных перестановок `n` элементов существует `n!`, и каждая
должна быть достижима, значит, у дерева не меньше `n!` листьев. Двоичное дерево
с `n!` листьями имеет высоту не менее `log₂(n!)`, а по формуле Стирлинга
`log₂(n!) = Θ(n log n)`. Высота дерева - это число сравнений в худшем случае,
что и требовалось.

Отсюда два вывода: сортировки слиянием и
[пирамидальная](../sprint-5/heap.md#561-пирамидальная-сортировка) **оптимальны**
по порядку, а обойти границу можно только отказавшись от сравнений - так
работает [сортировка подсчетом](#326-сортировка-подсчетом).

### 3.2.1 Сортировка пузырьком

Соседние элементы сравниваются попарно, и стоящие в неправильном порядке
меняются местами. За один проход наибольший элемент «всплывает» в конец, поэтому
следующий проход можно выполнять на один элемент короче.

```
[5, 2, 4, 6, 1, 3]   первый проход
 ↑  ↑                5 > 2 → обмен
[2, 5, 4, 6, 1, 3]
    ↑  ↑             5 > 4 → обмен
[2, 4, 5, 6, 1, 3]
       ↑  ↑          5 < 6 → без обмена
[2, 4, 5, 6, 1, 3]
          ↑  ↑       6 > 1 → обмен
[2, 4, 5, 1, 6, 3]
             ↑  ↑    6 > 3 → обмен
[2, 4, 5, 1, 3, 6]   6 на своем месте, дальше он не участвует
```

```js
/**
 * Сортирует массив пузырьком по неубыванию.
 *
 * Флаг swapped останавливает работу, как только очередной проход прошел без
 * единого обмена: это означает, что массив уже упорядочен. Без флага лучший
 * случай был бы не O(n), а O(n²).
 *
 * Время: O(n²) в среднем и худшем случае, O(n) в лучшем. Память: O(1).
 *
 * @param {number[]} numbers Сортируемый массив; изменяется на месте.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function bubbleSort(numbers) {
  for (let i = 0; i < numbers.length - 1; i++) {
    let swapped = false;

    // Последние i элементов уже заняли свои места
    for (let j = 0; j < numbers.length - 1 - i; j++) {
      if (numbers[j] > numbers[j + 1]) {
        [numbers[j], numbers[j + 1]] = [numbers[j + 1], numbers[j]];
        swapped = true;
      }
    }

    if (!swapped) {
      break;
    }
  }

  return numbers;
}
```

| | |
| --- | --- |
| Лучший случай | `O(n)` - массив уже отсортирован, один проход без обменов |
| Средний и худший | `O(n²)` |
| Память | `O(1)` |
| Устойчивость | **устойчива** - обмен происходит только при строгом `>` |

Практической ценности алгоритм не имеет: при той же асимптотике он проигрывает
сортировке вставками по числу операций. Его учат как простейший пример.

### 3.2.2 Сортировка вставками

Массив делится на упорядоченный префикс и необработанный хвост. Очередной
элемент вставляется в префикс на свое место, а элементы больше него сдвигаются
вправо.

Так человек раскладывает карты в руке.

```
[5 | 2, 4, 6, 1, 3]   префикс из одного элемента упорядочен по определению
[2, 5 | 4, 6, 1, 3]   вставили 2 перед 5
[2, 4, 5 | 6, 1, 3]   вставили 4 между 2 и 5
[2, 4, 5, 6 | 1, 3]   6 больше всех, остался на месте
[1, 2, 4, 5, 6 | 3]   вставили 1 в начало
[1, 2, 3, 4, 5, 6]    вставили 3 между 2 и 4
```

```js
/**
 * Сортирует массив вставками по неубыванию.
 *
 * Время: O(n²) в среднем и худшем случае, O(n) в лучшем. Память: O(1).
 *
 * @param {number[]} numbers Сортируемый массив; изменяется на месте.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function insertionSort(numbers) {
  for (let i = 1; i < numbers.length; i++) {
    const current = numbers[i];
    let j = i - 1;

    // Сдвигаем вправо все, что строго больше вставляемого элемента
    while (j >= 0 && numbers[j] > current) {
      numbers[j + 1] = numbers[j];
      j--;
    }

    numbers[j + 1] = current;
  }

  return numbers;
}
```

| | |
| --- | --- |
| Лучший случай | `O(n)` - массив уже отсортирован, `while` не выполняется ни разу |
| Средний и худший | `O(n²)` |
| Память | `O(1)` |
| Устойчивость | **устойчива** - сдвиг только при строгом `>`, равные не переставляются |

В отличие от пузырьковой, эта сортировка полезна на практике. У нее очень малая
константа, она работает на месте и **особенно быстра на почти отсортированных
данных**: стоимость составляет `O(n + k)`, где `k` - число инверсий. По этой
причине промышленные реализации `sort` переключаются на нее для коротких
подмассивов внутри быстрой сортировки или сортировки слиянием.

Еще одно ее свойство - она **онлайновая**: элементы можно вставлять по мере
поступления, не имея всего массива заранее.

### 3.2.3 Сортировка выбором

На каждом шаге в необработанной части ищется минимум и меняется местами с ее
первым элементом.

```
[5, 2, 4, 6, 1, 3]   минимум 1 → обмен с позицией 0
[1 | 2, 4, 6, 5, 3]  минимум 2 → уже на месте
[1, 2 | 4, 6, 5, 3]  минимум 3 → обмен с позицией 2
[1, 2, 3 | 6, 5, 4]  минимум 4 → обмен с позицией 3
[1, 2, 3, 4 | 5, 6]  минимум 5 → уже на месте
[1, 2, 3, 4, 5, 6]
```

```js
/**
 * Сортирует массив выбором по неубыванию.
 *
 * Время: O(n²) во всех случаях. Память: O(1).
 * Количество обменов - не более n - 1, что минимально среди всех сортировок.
 *
 * @param {number[]} numbers Сортируемый массив; изменяется на месте.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function selectionSort(numbers) {
  for (let i = 0; i < numbers.length - 1; i++) {
    let minIndex = i;

    for (let j = i + 1; j < numbers.length; j++) {
      if (numbers[j] < numbers[minIndex]) {
        minIndex = j;
      }
    }

    if (minIndex !== i) {
      [numbers[i], numbers[minIndex]] = [numbers[minIndex], numbers[i]];
    }
  }

  return numbers;
}
```

| | |
| --- | --- |
| Лучший, средний, худший | `O(n²)` - внутренний цикл выполняется всегда полностью |
| Память | `O(1)` |
| Устойчивость | **неустойчива** |

Досрочного выхода здесь быть не может: чтобы найти минимум, нужно просмотреть
весь остаток независимо от того, упорядочен он или нет.

Неустойчивость легко увидеть на примере. Пусть ключи равны, а буквы - метки
элементов:

```
[2a, 2b, 1c]  →  минимум 1c, обмен с позицией 0  →  [1c, 2b, 2a]
```

Элемент `2a` перепрыгнул через `2b`, хотя ключи равны. Один обмен переносит
элемент через произвольное расстояние - именно поэтому устойчивость теряется.

Единственное достоинство алгоритма - **минимальное число обменов**: не более
`n − 1`. Это имеет значение, когда перемещение элемента стоит несопоставимо
дороже сравнения, например при сортировке очень крупных записей.

### 3.2.4 Сортировка слиянием

Алгоритм построен по принципу «разделяй и властвуй»:

1. разделить массив пополам;
2. рекурсивно отсортировать обе половины;
3. слить две отсортированные половины в одну отсортированную.

Вся работа выполняется на обратном ходу рекурсии - при слиянии.

```
Разделение (прямой ход):        Слияние (обратный ход):

    [5, 2, 4, 6, 1, 3]              [1, 2, 3, 4, 5, 6]
      ↙          ↘                    ↖          ↗
  [5, 2, 4]   [6, 1, 3]           [2, 4, 5]   [1, 3, 6]
    ↙  ↘        ↙  ↘                ↖  ↗        ↖  ↗
  [5] [2, 4]  [6] [1, 3]          [5] [2, 4]  [6] [1, 3]
       ↙ ↘         ↙ ↘                 ↖ ↗         ↖ ↗
      [2] [4]     [1] [3]             [2] [4]     [1] [3]
```

Слияние - это [метод двух указателей](../sprint-2/two-pointers.md#схема-3-указатели-по-двум-последовательностям):
по указателю на каждую половину, на каждом шаге забирается меньший из двух
текущих элементов.

```js
/**
 * Сливает два отсортированных массива в один отсортированный.
 *
 * Время: O(n + m). Память: O(n + m) на результат.
 *
 * @param {number[]} left Первый массив, отсортированный по неубыванию.
 * @param {number[]} right Второй массив, отсортированный по неубыванию.
 * @returns {number[]} Отсортированный массив из всех элементов.
 */
function merge(left, right) {
  const result = new Array(left.length + right.length);
  let i = 0;
  let j = 0;
  let k = 0;

  while (i < left.length && j < right.length) {
    // Нестрогое сравнение обеспечивает устойчивость: при равенстве
    // первым забирается элемент из левой половины, то есть более ранний
    if (left[i] <= right[j]) {
      result[k] = left[i];
      i++;
    } else {
      result[k] = right[j];
      j++;
    }

    k++;
  }

  // Один из массивов исчерпан; хвост второго уже упорядочен
  while (i < left.length) {
    result[k] = left[i];
    i++;
    k++;
  }

  while (j < right.length) {
    result[k] = right[j];
    j++;
    k++;
  }

  return result;
}

/**
 * Сортирует массив слиянием по неубыванию.
 *
 * Время: O(n log n) во всех случаях. Память: O(n).
 *
 * @param {number[]} numbers Сортируемый массив; не изменяется.
 * @returns {number[]} Новый отсортированный массив.
 */
function mergeSort(numbers) {
  // База покрывает и пустой массив, и массив из одного элемента:
  // проверки length === 1 не хватило бы, на пустом входе рекурсия
  // делила бы [] на [] и [] бесконечно
  if (numbers.length <= 1) {
    return numbers;
  }

  const middle = Math.floor(numbers.length / 2);

  return merge(
    mergeSort(numbers.slice(0, middle)),
    mergeSort(numbers.slice(middle)),
  );
}
```

| | |
| --- | --- |
| Лучший, средний, худший | `O(n log n)` - глубина рекурсии `log n`, на каждом уровне `O(n)` работы |
| Память | `O(n)` |
| Устойчивость | **устойчива** - благодаря `<=` в слиянии |

#### Почему `O(n log n)`

Массив делится пополам, пока не останутся отрезки длины 1, - это `log₂ n`
уровней. На каждом уровне суммарная длина всех сливаемых отрезков равна `n`, а
слияние линейно по длине. Итого `n` операций на уровень, умноженные на `log₂ n`
уровней.

#### Почему `O(n)` памяти, а не `O(n log n)`

На каждом уровне рекурсии выделяется вспомогательный массив под результат
слияния - казалось бы, суммарно `O(n log n)`. Но эта память нужна лишь на
время слияния: как только результат передан наверх, вспомогательные массивы
нижних уровней освобождаются. Одновременно живыми оказываются только массивы
вдоль одного пути от корня к листу, а их суммарный размер равен
`n + n/2 + n/4 + … < 2n`, то есть `O(n)`.

Именно `O(n)` дополнительной памяти - главный недостаток алгоритма по сравнению
с быстрой сортировкой. Для связного списка его нет: слияние списков выполняется
переприсваиванием ссылок, без копирования, за `O(1)` дополнительной памяти.

### 3.2.5 Быстрая сортировка

Тоже «разделяй и властвуй», но с обратным распределением работы: основное
происходит на прямом ходу, а обратный ход не делает ничего.

1. выбрать **опорный элемент** (pivot);
2. переупорядочить массив так, чтобы слева от границы оказались элементы, не
   превосходящие опорного, справа - не меньшие;
3. рекурсивно отсортировать обе части.

После разделения элементы не пересекают границу, поэтому склеивать части не
нужно - в отличие от слияния.

```
[5, 2, 4, 6, 1, 3]   опорный элемент 4 (средний)

разделение:  [3, 2, 1] [4, 6, 5]
              ≤ 4       ≥ 4

рекурсия:    [1, 2, 3] [4, 5, 6]

результат:   [1, 2, 3, 4, 5, 6]
```

Разделение выполняется **на месте** двумя указателями, идущими навстречу:
левый останавливается на элементе, не меньшем опорного, правый - на элементе,
не большем; найденную пару меняют местами.

```js
/**
 * Переупорядочивает отрезок массива относительно опорного элемента.
 *
 * После вызова все элементы отрезка левее возвращенного индекса не превосходят
 * опорного, а все правее и он сам - не меньше опорного.
 *
 * Время: O(right - left). Память: O(1).
 *
 * @param {number[]} numbers Массив; изменяется на месте.
 * @param {number} left Левая граница отрезка, включительно.
 * @param {number} right Правая граница отрезка, включительно.
 * @returns {number} Индекс начала правой части.
 */
function partition(numbers, left, right) {
  const pivot = numbers[left + Math.floor((right - left) / 2)];
  let i = left;
  let j = right;

  while (i <= j) {
    while (numbers[i] < pivot) {
      i++;
    }

    while (numbers[j] > pivot) {
      j--;
    }

    if (i <= j) {
      [numbers[i], numbers[j]] = [numbers[j], numbers[i]];
      i++;
      j--;
    }
  }

  return i;
}

/**
 * Сортирует массив быстрой сортировкой по неубыванию, на месте.
 *
 * Время: O(n log n) в среднем, O(n²) в худшем случае.
 * Память: O(log n) в среднем на кадры стека вызовов.
 *
 * @param {number[]} numbers Сортируемый массив; изменяется на месте.
 * @param {number} left Левая граница сортируемого отрезка, включительно.
 * @param {number} right Правая граница сортируемого отрезка, включительно.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function quickSort(numbers, left = 0, right = numbers.length - 1) {
  if (left >= right) {
    return numbers;
  }

  const index = partition(numbers, left, right);

  quickSort(numbers, left, index - 1);
  quickSort(numbers, index, right);

  return numbers;
}
```

| | |
| --- | --- |
| Лучший и средний | `O(n log n)` |
| Худший | `O(n²)` - опорный элемент каждый раз оказывается крайним |
| Память | `O(log n)` в среднем, `O(n)` в худшем случае - стек вызовов |
| Устойчивость | **неустойчива** - обмен переносит элемент через произвольное расстояние |

#### Выбор опорного элемента

Именно он определяет, будет алгоритм быстрым или квадратичным.

- **Крайний элемент** (`numbers[left]`) - худший выбор: на уже отсортированном
  массиве разделение каждый раз дает части размера 0 и `n − 1`, глубина
  рекурсии становится `O(n)`, а время - `O(n²)`. Обидно, что вырожденным
  оказывается самый частый на практике вход.
- **Средний элемент** - простая и разумная защита именно от отсортированных
  входов; используется в коде выше.
- **Случайный элемент** - дает `O(n log n)` в среднем для **любого** входа, так
  как убирает зависимость от порядка данных.
- **Медиана трех** (первого, среднего и последнего) - стандартный компромисс в
  промышленных реализациях.

Полностью исключить `O(n²)` выбором опорного элемента нельзя, можно лишь
сделать вырожденный случай маловероятным.

#### Глубина рекурсии

При неудачных разделениях глубина достигает `O(n)`, и на больших массивах это
приводит к переполнению стека. Прием, дающий гарантию `O(log n)`, -
рекурсивно обрабатывать только **меньшую** часть, а для большей продолжать
цикл в том же вызове. Тогда размер задачи на каждом уровне рекурсии
уменьшается минимум вдвое.

#### Сравнение со слиянием

| | Слиянием | Быстрая |
| --- | --- | --- |
| Худший случай | `O(n log n)` | `O(n²)` |
| Дополнительная память | `O(n)` | `O(log n)` |
| Устойчивость | да | нет |
| Скорость на практике | медленнее | **быстрее** |

Быстрая сортировка обычно выигрывает по времени, несмотря на худшую
асимптотику в вырожденном случае: она работает на месте и обращается к памяти
последовательно, что хорошо согласуется с кэшем процессора. Сортировку слиянием
выбирают, когда нужна гарантия `O(n log n)` или устойчивость.

### 3.2.6 Сортировка подсчетом

Единственный алгоритм в этом списке, который **не сравнивает элементы между
собой**, а потому не подчиняется границе `Ω(n log n)`.

Идея: если ключи - целые числа из известного диапазона, можно просто посчитать,
сколько раз встречается каждое значение, и восстановить массив по счетчикам.

```
[2, 5, 3, 2, 3, 3]   диапазон значений от 2 до 5

счетчики:   значение  2  3  4  5
            сколько   2  3  0  1

восстановление:  2, 2, 3, 3, 3, 5
```

```js
/**
 * Сортирует массив целых чисел подсчетом по неубыванию.
 *
 * Время: O(n + k), где k - размер диапазона значений. Память: O(k).
 *
 * @param {number[]} numbers Сортируемый массив; изменяется на месте.
 * @param {number} minValue Минимальное возможное значение элемента.
 * @param {number} maxValue Максимальное возможное значение элемента.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function countingSort(numbers, minValue, maxValue) {
  const counts = new Array(maxValue - minValue + 1).fill(0);

  for (const value of numbers) {
    counts[value - minValue]++;
  }

  let index = 0;

  for (let offset = 0; offset < counts.length; offset++) {
    for (let repeat = 0; repeat < counts[offset]; repeat++) {
      numbers[index] = offset + minValue;
      index++;
    }
  }

  return numbers;
}
```

Смещение на `minValue` обязательно: без него отрицательные значения дадут
отрицательный индекс, а диапазон вроде `[1000000, 1000010]` потребует массива
на миллион ячеек вместо одиннадцати.

| | |
| --- | --- |
| Время | `O(n + k)`, где `k = maxValue − minValue + 1` |
| Память | `O(k)` |
| Ограничение | ключи - целые числа из известного ограниченного диапазона |

Алгоритм линеен, только когда `k = O(n)`. При `n = 100` и значениях до `10⁹`
он безнадежно проигрывает любой сортировке сравнением: размер массива
счетчиков определяется диапазоном, а не количеством элементов.

#### Устойчивая версия

Приведенная реализация не сохраняет элементы - она записывает значения заново.
Для чисел это неотличимо от сортировки, но как только у элемента появляются
дополнительные поля, такой подход неприменим: восстановить запись по одному
лишь ключу невозможно.

Устойчивая версия использует **префиксные суммы** счетчиков, которые дают
каждой группе ключей ее диапазон позиций в результате:

```js
/**
 * Устойчиво сортирует элементы подсчетом по целочисленному ключу.
 *
 * Время: O(n + k). Память: O(n + k).
 *
 * @param {*[]} items Сортируемые элементы; не изменяются.
 * @param {(item: *) => number} key Функция целочисленного ключа.
 * @param {number} minKey Минимальное возможное значение ключа.
 * @param {number} maxKey Максимальное возможное значение ключа.
 * @returns {*[]} Новый массив, отсортированный по неубыванию ключа.
 */
function countingSortStable(items, key, minKey, maxKey) {
  const counts = new Array(maxKey - minKey + 1).fill(0);

  for (const item of items) {
    counts[key(item) - minKey]++;
  }

  // После накопления префиксных сумм counts[i] равно позиции,
  // следующей за последним местом группы ключей i
  for (let i = 1; i < counts.length; i++) {
    counts[i] += counts[i - 1];
  }

  const result = new Array(items.length);

  // Проход с конца и есть то, что делает сортировку устойчивой:
  // равные элементы раскладываются справа налево и сохраняют исходный порядок
  for (let i = items.length - 1; i >= 0; i--) {
    const bucket = key(items[i]) - minKey;

    counts[bucket]--;
    result[counts[bucket]] = items[i];
  }

  return result;
}
```

Устойчивость здесь не украшение: именно она позволяет использовать сортировку
подсчетом как шаг поразрядной сортировки, где числа упорядочиваются разряд за
разрядом.

#### Частный случай: три значения за один проход

Когда различных значений всего три, массив можно упорядочить за **один** проход
и `O(1)` памяти - сортировке подсчетом требуется два прохода. Прием известен
как разбиение голландского флага и использует три указателя.

```js
/**
 * Сортирует массив, содержащий только значения 0, 1 и 2, за один проход.
 *
 * Инвариант: элементы левее low равны 0, на отрезке [low, mid) равны 1,
 * правее high равны 2; отрезок [mid, high] еще не просмотрен.
 *
 * Время: O(n). Память: O(1).
 *
 * @param {number[]} values Массив из значений 0, 1 и 2; изменяется на месте.
 * @returns {number[]} Тот же массив, отсортированный по неубыванию.
 */
function sortThreeValues(values) {
  let low = 0;
  let mid = 0;
  let high = values.length - 1;

  while (mid <= high) {
    if (values[mid] === 0) {
      [values[low], values[mid]] = [values[mid], values[low]];
      low++;
      mid++;
    } else if (values[mid] === 1) {
      mid++;
    } else {
      [values[mid], values[high]] = [values[high], values[mid]];
      high--;
      // mid не увеличивается: пришедший справа элемент еще не просмотрен
    }
  }

  return values;
}
```

Строка, где `mid` намеренно не сдвигается, - единственное неочевидное место:
элемент, полученный обменом с правого конца, еще не рассматривался, и его нужно
обработать на следующей итерации.

| Алгоритм | Лучший | Средний | Худший | Память | Устойчивость |
| --- | --- | --- | --- | --- | --- |
| Пузырьком | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | да |
| Вставками | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | да |
| Выбором | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | нет |
| Слиянием | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | да |
| Быстрая | `O(n log n)` | `O(n log n)` | `O(n²)` | `O(log n)` | нет |
| Подсчетом | `O(n + k)` | `O(n + k)` | `O(n + k)` | `O(k)` | да |

### Как выбирать

- **По умолчанию** - встроенная `sort` языка. В современных движках это
  гибридный алгоритм, сочетающий сортировку слиянием и вставками; он устойчив
  и дает `O(n log n)`. Собственную сортировку пишут ради учебы или ради
  требования задачи.
- **Ключи - целые числа из узкого диапазона** - подсчетом, `O(n)`.
- **Нужна гарантия `O(n log n)` или устойчивость** - слиянием.
- **Память ограничена, нужна максимальная скорость** - быстрая.
- **Массив мал или почти отсортирован** - вставками.
- **Данные поступают потоком** - вставками: она онлайновая.
