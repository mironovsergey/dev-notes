# 02 · Функциональные компоненты и хуки

Та же «Лавка», но состояние разложено по хукам. Классом остался ровно один
компонент - граница ошибок: хука, заменяющего `getDerivedStateFromError` и
`componentDidCatch`, в React нет. Разметка, стили и поведение совпадают с
вариантом 01, поэтому разницу видно построчно.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Пользовательский хук с загрузкой данных: статус, ошибка, повтор; отмена запроса в функции очистки | `hooks/use-catalog.ts` |
| Пользовательский хук состояния корзины: чистые апдейтеры, возврат прежнего объекта вместо «пустого» изменения | `hooks/use-cart.ts` |
| Пользовательский хук подписки на событие документа с отпиской в очистке | `hooks/use-escape-key.ts` |
| `useMemo` для производных данных: фильтрация каталога, строки корзины, итоги | `catalog.tsx`, `app.tsx` |
| `useCallback` для обработчиков, уходящих в компоненты под `memo` | `hooks/use-cart.ts`, `app.tsx`, `cart-line.tsx` |
| `memo` вместо `PureComponent` | `product-card.tsx`, `products.tsx`, `stepper.tsx` |
| `useRef` как изменяемая ячейка (запрос завершился после размонтирования) и как ссылка на DOM (фокус в окне) | `promo-form.tsx`, `checkout-modal.tsx` |
| `ref` обычным пропом функционального компонента - без `forwardRef` (React 19) | `text-field.tsx` |
| `useId` для связи `label` и `input` | `text-field.tsx` |
| Пропсы нативного элемента через `ComponentProps<'input'>` вместо ручного перечисления | `text-field.tsx` |
| Обобщенный компонент: `Select<Value>` связывает список вариантов, значение и обработчик | `select.tsx` |
| Портал: узел создается ленивым инициализатором `useState`, эффект только добавляет и убирает его | `modal.tsx` |
| Управляемая форма оформления заказа вместо неуправляемой из варианта 01 | `checkout-modal.tsx` |
| Обертка с `children` вместо HOC `withLoading` | `load-state.tsx` |

## Чем отличается от варианта 01

| Вариант 01 | Вариант 02 |
| --- | --- |
| `this.state` одним объектом в `App` | несколько `useState` плюс два пользовательских хука |
| `componentDidMount` / `componentWillUnmount` | `useEffect` с функцией очистки |
| `PureComponent` | `memo` |
| HOC `withLoading(Products)` | компонент `LoadState` с `children` |
| `createRef` + `FormData`, неуправляемая форма | `useRef` + `useState`, управляемая форма |
| флаг `mounted` полем класса | `useRef` как изменяемая ячейка |

Две ловушки, которые здесь специально обойдены и прокомментированы в коде:
апдейтер `setState` обязан быть чистым, потому что StrictMode вызывает его
дважды (см. `use-cart.ts` и `closeCheckout` в `app.tsx`), и синхронный
`setState` в теле эффекта дает лишний каскадный рендер (см. `use-catalog.ts`
и `modal.tsx`).
