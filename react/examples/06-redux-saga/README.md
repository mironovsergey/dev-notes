# 06 · Redux Saga

Та же «Лавка», что и в варианте 05, но побочные эффекты вынесены из thunk в
саги. Срезы и разметка не изменились; исчезли `createAsyncThunk` и
`unwrap`, а вместо них появились наблюдатели, воркеры и эффекты.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Watcher и worker: связь «действие → эффект» описана в одном месте | `store/sagas/catalog-saga.ts` |
| `takeLatest` отменяет предыдущий незавершенный запуск - решение гонки запросов | `store/sagas/catalog-saga.ts` |
| `cancelled()` в `finally`: отменяется сага, а сетевой запрос прерывается вручную | `store/sagas/catalog-saga.ts` |
| `call` и `put`: вызвать функцию, дождаться результата, отправить действие | все саги |
| Воркер получает действие последним аргументом - оттуда берется `payload` | `store/sagas/promo-saga.ts` |
| `select`: состав заказа сага читает из состояния, компонент его не собирает | `store/sagas/checkout-saga.ts` |
| `race` с `delay`: зависший запрос не оставит окно в состоянии «Отправляем…» | `store/sagas/checkout-saga.ts` |
| `take` внутри воркера: сценарий «заказ принят → ожидание закрытия окна → очистка корзины» | `store/sagas/checkout-saga.ts` |
| Корневая сага и `all` с **вызванными** генераторами; аргументы через `call(watcher, arg)` | `store/sagas/index.ts` |
| `configureStore({ middleware: getDefaultMiddleware({ thunk: false }).concat(sagaMiddleware) })` и обязательный `run` | `store/store.ts` |
| Компонент отправляет данные, а не функцию, и о саге не знает | `components/catalog.tsx`, `components/promo-form.tsx` |

## Чем отличается от варианта 05

| Вариант 05 (thunk) | Вариант 06 (saga) |
| --- | --- |
| `dispatch(loadCatalog())` - отправляется функция | `dispatch(catalogActions.requested())` - отправляется действие |
| жизненный цикл `pending/fulfilled/rejected` генерируется | три обычных действия среза, их отправляет воркер |
| `unwrap()` возвращает промис в компонент | промиса нет: форма читает ход запроса из состояния |
| гонку запросов приходится решать отменой вручную | `takeLatest` отменяет предыдущий запуск сам |
| «после заказа очистить корзину» - thunk с `getState` | сага останавливается на `take` и ждет нужного действия |
| таймаут запроса - руками | `race` между `call` и `delay` |

Главное следствие видно в форме промокода: с thunk она ждала промис и
держала признак проверки у себя, с сагой - отправляет действие и читает
`isChecking` и `error` из хранилища. Состояние запроса стало частью модели,
а не частной жизнью компонента.

Ловушка, на которой легко ошибиться: обработчик действия в саге
срабатывает **после** редьюсера. Сага на `checkout/closed`, читающая заказ
через `select`, увидит уже сброшенное состояние - поэтому «очистить корзину
после заказа» написано как последовательность `take` внутри воркера,
запущенного на `checkout/submitSucceeded`.
