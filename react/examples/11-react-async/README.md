# 11 · React 19 без библиотек

Та же «Лавка» без единой библиотеки состояния и данных. Каталог
разворачивается из промиса функцией `use` внутри `<Suspense>`, формы
работают через действия и `useActionState`, промокод применяется
оптимистично, а корзина живет в обычном `useReducer` с контекстом.

## Что здесь показано

| Прием | Где |
| --- | --- |
| `use(promise)` внутри `<Suspense>`: компонент написан так, будто данные уже есть | `components/catalog.tsx` |
| Промис хранится в состоянии, а не создается в рендере | `components/catalog.tsx` |
| `useTransition`: во время повторной загрузки прежний каталог остается на экране | `components/catalog.tsx` |
| Граница ошибок вместо ветвления по статусу: отклоненный промис бросается как ошибка | `components/catalog-boundary.tsx` |
| `<form action={…}>` и `useActionState`: ошибка - обычный результат действия | `components/promo-form.tsx` |
| `useOptimistic`: промокод показывается применяемым сразу, откат писать не нужно | `components/promo-form.tsx` |
| `useFormStatus` в дочерней кнопке: о ходе отправки она узнает без пропов | `components/checkout-form.tsx` |
| Значения формы читаются из `FormData`, `preventDefault` не нужен | `components/checkout-form.tsx` |
| Клиентское состояние: `useReducer` и два контекста | `model/cart-reducer.ts`, `model/cart-context.tsx` |
| Корзина хранит снимок товара, а не ссылку на каталог | `model/cart-reducer.ts` |

## Чем отличается от варианта 10

| TanStack Query | React 19 сам по себе |
| --- | --- |
| `useQuery` со статусами `pending`/`error`/`success` | `use` + `<Suspense>` + граница ошибок, ветвления нет |
| кеш по ключу, дедупликация, фоновое обновление | ничего этого нет: промис живет в состоянии компонента |
| `useMutation` с `isPending` и `error` | `useActionState`: результат действия и признак выполнения |
| оптимистичное обновление с ручным откатом в `onError` | `useOptimistic`: откат делает React |
| `invalidateQueries` после мутации | инвалидации нет - каталог перезапрашивается вручную |

Корзина здесь хранит **сам товар**, а не идентификатор: в остальных
вариантах товары лежали в общем сторе, и корзина ссылалась на них. Без
такого стора корзина снимает копию товара в момент добавления - и перестает
зависеть от того, загружен ли каталог.

Граница подхода видна по этой же таблице: средств React хватает на один
экран с одним источником данных. Как только данные нужны нескольким
экранам, должны переживать переходы и обновляться после мутаций, поверх
React нужен кеш - вариант 10.

## Ловушка, на которой легко споткнуться

**Порядок эффектов и портал.** Фокус в окне заказа сначала переводил
эффект внутри формы - и не срабатывал: эффекты выполняются от потомков к
предкам, а форма лежит внутри `Modal`, который добавляет контейнер портала
в документ своим эффектом. Фокус уходил в элемент, которого еще нет на
странице. Перевод фокуса живет в `checkout-modal.tsx`, то есть у предка
`Modal`.

## Ловушка, которую стоит знать заранее

Компонент, приостановленный на `use`, требует **дожидаемой** области `act`
в тестах: React ставит продолжение в ту область, внутри которой произошла
приостановка. Без `await act(...)` тест видит только заглушку `<Suspense>`
и падает по таймауту - именно это и случилось при переносе тестов, пока в
консоли не нашлось предупреждение «A component suspended inside an `act`
scope, but the `act` call was not awaited». Поэтому в `app.test.tsx`
обернуты и рендер, и клик по кнопке «Повторить».
