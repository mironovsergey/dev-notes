# 09 · MobX

Та же «Лавка» на изменяемом наблюдаемом состоянии. Поля сторов меняются
обычным присваиванием, производные данные - геттеры, а компоненты,
обернутые в `observer`, перерисовываются по тому, что прочитали во время
рендера. Селекторов, действий и редьюсеров здесь нет вовсе.

## Что здесь показано

| Прием | Где |
| --- | --- |
| `makeAutoObservable` с `autoBind`: поля наблюдаемы, геттеры вычисляемы, методы - действия | все сторы |
| Изменение состояния присваиванием, включая `push` и `splice` по наблюдаемому массиву | `store/cart-store.ts` |
| Вычисляемые значения вместо селекторов: строки корзины, итоги, счетчик | `store/cart-store.ts` |
| Метод вместо вычисляемого там, где нужен аргумент (`quantityOf`) | `store/cart-store.ts` |
| `runInAction` после `await` | `store/catalog-store.ts`, `store/promo-store.ts` |
| `flow` с генератором: действие продолжается после каждого `yield`, `runInAction` не нужен | `store/checkout-store.ts` |
| Корневой стор: сторы связаны через конструкторы, а не через импорты | `store/root-store.ts` |
| Обычный `createContext` для доставки стора - своих провайдеров у MobX 7 больше нет | `store/store-context.tsx` |
| `observer` на каждом компоненте, который читает стор | все компоненты |
| Точечная подписка: карточка сама читает количество, а не получает его пропом | `components/product-card.tsx` |

## Чем отличается от остальных вариантов

| Redux, Effector, Zustand | MobX |
| --- | --- |
| состояние неизменяемо, обновление возвращает новый объект | состояние изменяемое, `items.push(...)` - нормальный код |
| подписка задается селектором | подписка выводится из того, что компонент прочитал |
| производные данные - селекторы или отдельные сторы | обычные геттеры класса |
| перерисовка - результат сравнения выбранного значения | перерисовка - результат отслеживания чтения |
| асинхронность: thunk, сага, эффект или `async`-действие | `async` + `runInAction` либо `flow` |

Слой состояния - 233 строки кода: меньше, чем на Redux Toolkit (333) и
Zustand (336), больше, чем на Effector (191). Экономия - за счет того, что
правила корзины пишутся как обычный изменяемый код, а производные значения
не требуют ни мемоизации, ни объявления зависимостей.

Две ловушки, о которых стоит помнить и которые прокомментированы в коде:

- **Наблюдаемость теряется при чтении заранее.** Если бы `Products`
  передавал карточке `inCartQty` пропом, он прочитал бы наблюдаемое за нее
  и подписался бы сам - перерисовывался бы весь каталог. Поэтому количество
  читает сама карточка.
- **После `await` действие уже закончилось.** Изменения нужно завернуть в
  `runInAction` - либо писать метод через `flow`, как сделано в
  `checkout-store.ts`.
