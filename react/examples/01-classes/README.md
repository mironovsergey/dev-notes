# 01 · Классовые компоненты

«Лавка» на классовых компонентах: все состояние приложения живет в классе
`App`, дочерние компоненты получают данные через props и сообщают об
изменениях через callback-props. Это способ, которым React писали до
хуков; вариант нужен, чтобы читать и понимать старый код, а не как образец
для нового.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Владелец состояния, `setState` с функцией-обновителем и явным типом результата, возврат `null` для «изменений нет» | `src/app.tsx` |
| Жизненный цикл: запрос в `componentDidMount`, отмена через `AbortController` в `componentWillUnmount` | `src/app.tsx` |
| `PureComponent` для карточек и строк корзины: родитель рендерится на каждый ввод в поиске, карточки с теми же props - нет | `product-card.tsx`, `cart-line.tsx`, `stepper.tsx` |
| Локальное состояние там, где оно никому больше не нужно: фильтр каталога, ввод промокода | `catalog.tsx`, `promo-form.tsx` |
| Управляемая форма (промокод) и неуправляемая с `createRef` + `FormData` (оформление заказа) | `promo-form.tsx`, `checkout-modal.tsx` |
| Флаг `mounted` против `setState` после размонтирования | `promo-form.tsx` |
| Портал: контейнер создается в `componentDidMount` и удаляется в `componentWillUnmount`, `Escape` закрывает окно | `modal.tsx` |
| Граница ошибок вокруг каждого виджета с кнопкой «Попробовать снова» | `error-boundary.tsx` |
| HOC `withLoading`: состояния загрузки и ошибки вокруг сетки товаров | `with-loading.tsx` |
| Расчет итогов и операции над позициями вне React: `calculateTotals`, `toCartLines`, `withQty`, `withoutItem` из предметного слоя | `src/domain` |

Ограничение варианта: любое изменение состояния перерендеривает `App` целиком,
и производные данные (строки корзины, итоги) пересчитываются в `render`. Для
такого размера приложения это ничего не стоит; как избежать этого в больших
приложениях - в следующих вариантах.
