# 07 · Effector

Та же «Лавка» без хранилища, действий и редьюсеров: состояние описано
набором независимых юнитов - событий, сторов и эффектов, - а связи между
ними заданы оператором `sample`. Модель живет вне дерева компонентов, а
компоненты подписываются на нужные сторы через `useUnit`.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Событие как сигнал: компонент сообщает факт, а что за ним следует - решает модель | `model/cart.ts` |
| `createStore(...).on(event, fn).reset(event)` | все модули модели |
| Производные сторы через `map` и `combine` вместо библиотеки селекторов | `model/cart.ts`, `model/totals.ts` |
| `createEffect` и его события: `doneData`, `failData`, стор `pending` | `model/catalog.ts` |
| Отдельный стор «идет загрузка» не нужен: `pending` уже есть у эффекта | `components/promo-form.tsx` |
| `sample`: `clock`, `source`, `filter`, `fn`, `target` - правило «не больше остатка» живет в графе | `model/cart.ts` |
| `sample` с `filter`: пустой промокод до эффекта не доходит | `model/promo.ts` |
| `attach`: состав заказа добавляется к параметрам из сторов | `model/checkout.ts` |
| `useUnit` для сторов и событий, в том числе массивом | все компоненты |
| `fork` и `Provider`: изолированная область видимости вместо глобального состояния | `app.tsx` |

## Чем отличается от вариантов 04-06

| Redux (04-06) | Effector (07) |
| --- | --- |
| одно дерево состояния и корневой редьюсер | много независимых сторов, общего дерева нет |
| действие → редьюсер → новое состояние | событие → подписанные сторы обновляются сами |
| производные данные - `createSelector` | производные данные - тоже сторы (`map`, `combine`) |
| выборочная подписка через селектор в `useSelector` | подписка на конкретный стор: `useUnit($itemCount)` |
| асинхронность - thunk или сага | эффект с готовыми `pending`, `doneData`, `failData` |
| «что за чем следует» видно в thunk или в watcher | связи описаны отдельно, оператором `sample` |
| изоляция в тестах - новое хранилище | изоляция - `fork()`, область видимости |

Размер модели: 191 строка кода против 333 в варианте на Redux Toolkit и 396
на сагах (без комментариев и пустых строк). Экономия не только из-за
краткости: исчезли действия как отдельные объекты, слой селекторов и
описание жизненного цикла запросов.

Две вещи, о которые легко споткнуться, и обе прокомментированы в коде:

- **Порядок в графе.** Сторы обновляются раньше, чем `sample` их читает.
  Поэтому `$order` сбрасывается на `checkoutOpened`, а не на
  `checkoutClosed`: иначе связь «закрыли окно после принятого заказа →
  очистить корзину» читала бы уже пустое значение.
- **Много сторов - не повод атомизировать связанные данные.** Позиции и
  отложенное лежат в одном сторе: операции переносят товар между списками,
  и в одном обработчике это проще, чем связывать два стора через граф.
