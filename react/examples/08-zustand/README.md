# 08 · Zustand

Та же «Лавка» на сторе, который одновременно является хуком: ни
провайдера, ни действий, ни редьюсеров. Состояние разложено по срезам,
подключены `devtools`, `persist` и `immer`, а производные данные считаются
в компонентах - у Zustand нет своего слоя мемоизированных селекторов.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Стор как хук: `create<T>()(...)` и селектор прямо в компоненте | `store/store.ts`, все компоненты |
| Провайдера нет: компонент импортирует хук, дерево о сторе не знает | `app.tsx` |
| Срезы: `StateCreator<ShopStore, [['zustand/immer', never]], [], CartSlice>` | `store/cart-slice.ts` |
| Срез видит стор целиком: состав заказа читается через `get()` | `store/checkout-slice.ts` |
| Асинхронное действие - обычная `async`-функция внутри стора | `store/catalog-slice.ts` |
| `immer`: обработчики правят черновик | `store/cart-slice.ts` |
| `persist` с `partialize`: корзина переживает перезагрузку, статусы - нет | `store/store.ts` |
| `devtools`: история изменений в Redux DevTools | `store/store.ts` |
| `useShallow` там, где селектор собирает объект | `components/cart-line.tsx`, `components/checkout-modal.tsx` |
| Производные данные - в хуках с `useMemo`, а не в селекторах | `store/hooks.ts` |
| Стор вне React: `getState`, `setState`, `subscribe` | `src/store/store.test.ts` |

## Чем отличается от варианта 05 (Redux Toolkit)

| Redux Toolkit | Zustand |
| --- | --- |
| `<Provider store={store}>` над приложением | провайдера нет, стор - модуль |
| действие → редьюсер → новое состояние | действие вызывается как метод и само вызывает `set` |
| `createAsyncThunk` с `pending`/`fulfilled`/`rejected` | `async`-функция, которая сама расставляет флаги |
| `createSelector` мемоизирует производные данные | мемоизации нет: `useMemo` в компоненте или хуке |
| подписка через селектор в `useSelector` | подписка через селектор в самом хуке стора |
| `configureStore` подключает DevTools | `devtools` подключается middleware |
| изоляция в тестах - новое хранилище | глобальный стор сбрасывается `setState(initial, true)` |

Единственный вариант, где корзина переживает перезагрузку страницы: это
`persist` в четыре строки. Обратная сторона - в тестах приходится чистить
`localStorage`, иначе состояние переходит из теста в тест.

Размер слоя состояния - 336 строк кода: столько же, сколько на Redux
Toolkit. Экономия не в объеме, а в числе понятий: нет действий, редьюсеров,
диспетчеризации и отдельного слоя селекторов; почти весь объем - это сами
правила корзины и четыре асинхронных действия.

Главная ловушка Zustand видна в `store/hooks.ts`: селектор, который
**собирает** массив или объект, возвращает новую ссылку на каждом вызове.
React считает такой снимок стора изменившимся при каждом рендере, уходит в
бесконечный цикл перерисовок и останавливает его ошибкой «Maximum update
depth exceeded». Поэтому из стора берутся исходные срезы, а производные
данные считает `useMemo`; там, где нужно вытащить несколько полей сразу,
стоит `useShallow`.
