# 03 · `useReducer` и контекст

Та же «Лавка», но состояние описано редьюсером и роздано через контекст.
Пропсы с данными и колбэками исчезли: `Header`, `Cart`, `Totals`, `Delivery`,
`PromoForm` и `CheckoutModal` вообще не принимают пропсов, а получают все,
что им нужно, из контекста.

## Что здесь показано

| Прием | Где |
| --- | --- |
| Чистый редьюсер всего состояния магазина: корзина, промокод, доставка, оформление | `store/shop-reducer.ts` |
| Действия размеченным объединением: TypeScript требует разобрать все варианты | `store/shop-reducer.ts` |
| Два контекста - состояние и `dispatch`: потребители `dispatch` не перерисовываются при изменении состояния | `store/shop-context.tsx` |
| Отдельный контекст на независимую группу данных: каталог меняется редко, корзина - постоянно | `store/catalog-context.tsx` |
| `useMemo` на значение контекста: новый объект на каждом рендере перерисовал бы всех потребителей | `store/catalog-context.tsx` |
| Хуки-обертки над контекстом с понятной ошибкой вне провайдера | `store/shop-context.tsx` |
| Производные данные (строки корзины, итоги, счетчики) - в хуках-селекторах, а не в состоянии | `store/shop-context.tsx` |
| Асинхронные операции отдельными функциями, принимающими `dispatch`; редьюсер остается чистым | `store/shop-actions.ts` |
| Провайдеры собраны в одном месте | `app.tsx` |
| Карту «товар → количество» читает список, а не каждая карточка: у контекста нет выборочной подписки | `products.tsx` |

## Чем отличается от варианта 02

| Вариант 02 | Вариант 03 |
| --- | --- |
| `useState` внутри `useCart`, данные вниз через пропсы | `useReducer` + контекст, пропсов с данными нет |
| обработчики создаются в `useCallback` и передаются вниз | компоненты вызывают `dispatch` сами |
| асинхронность прямо в компоненте или хуке | функции-действия `applyPromo`, `submitOrder` с `dispatch` |
| логику корзины можно проверить только через интерфейс | редьюсер тестируется как обычная функция: `shop-reducer.test.ts`, 11 тестов без React |

Главное следствие: правила корзины («сверх остатка не добавлять», «отложенное
возвращается с тем же количеством», «после принятого заказа корзина
очищается, а способ доставки сохраняется») стали проверяемыми без рендера.

Ограничение варианта: у контекста нет выборочной подписки - любое изменение
состояния магазина перерисовывает всех его потребителей. Пока потребителей
мало, это дешево; что с этим делают библиотеки состояния - в вариантах 04-07.
