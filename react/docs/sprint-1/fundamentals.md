# Основы: React, элементы, Virtual DOM и JSX

## 1.1 Что такое React

> 📌 **React** - JavaScript-библиотека для построения пользовательских
> интерфейсов из компонентов: разработчик описывает, как интерфейс должен
> выглядеть при заданных входных данных и состоянии, а библиотека сама приводит
> DOM к этому описанию и поддерживает его в актуальном состоянии.

Ключевое слово в определении - «описывает». React реализует **декларативный**
подход к интерфейсу.

> 📌 **Декларативный подход** - описание результата (каким должен быть
> интерфейс при данном состоянии), а не последовательности шагов по его
> получению. Противоположный, **императивный** подход - явные команды:
> найти узел, изменить текст, добавить класс, удалить потомка.

Формула, к которой сводится модель React: `UI = f(state)` - разметка есть
функция от состояния. Код компонента не изменяет DOM; он возвращает описание
того, каким DOM должен быть, а приведение DOM к описанию - работа библиотеки.

Чем плох императивный подход, видно на любом интерфейсе с двумя-тремя
зависимыми элементами: каждый обработчик должен помнить, какие узлы зависят от
произошедшего события, и при добавлении нового элемента нужно править все
обработчики. В худшем случае число связей растет квадратично от числа
элементов; декларативное описание задает каждую зависимость один раз - в
месте, где элемент выводится.

### Библиотека, а не фреймворк

React решает одну задачу - построение и обновление дерева интерфейса.
Маршрутизация, загрузка данных, глобальное состояние, стили - вне библиотеки;
их выбирает разработчик. В этом конспекте - менеджеры состояния (спринт 2) и
React Router (спринт 3).

⚠️ Документация React рекомендует начинать новый проект с фреймворка -
Next.js, React Router в режиме framework или Expo, - который берет на себя
маршрутизацию, загрузку данных и серверный рендеринг. Сама библиотека при этом
не изменилась; конспект разбирает именно ее.

### История

React создан в Facebook (Джордан Уолки), открыт в 2013 году. Вехи, которые
объясняют устаревшие фрагменты в старом коде:

| Версия | Год | Что изменилось |
| --- | --- | --- |
| 16 | 2017 | Новая архитектура Fiber; фрагменты, порталы, границы ошибок |
| 16.8 | 2019 | Хуки - состояние и эффекты в функциональных компонентах |
| 17 | 2020 | Новый JSX-runtime (без `import React`), делегирование событий на корень вместо `document` |
| 18 | 2022 | `createRoot`, автоматическое пакетирование, конкурентный рендер, `StrictMode` дважды запускает эффекты |
| 19 | 2024 | `ref` как обычный prop, Actions и хук `use`, удалены `ReactDOM.render`, `propTypes` и `defaultProps` функциональных компонентов |

## 1.2 Пакеты `react` и `react-dom`, корень приложения

React разделен на две части.

| Пакет | Что содержит | Зависит от платформы |
| --- | --- | --- |
| `react` | Создание элементов, компоненты, хуки, `memo`, `StrictMode` | Нет: тот же код работает в браузере, в React Native, при серверном рендере |
| `react-dom` | Рендерер для браузерного DOM: `react-dom/client` (`createRoot`, `hydrateRoot`), `react-dom/server` (рендер в строку или поток), `createPortal`, `flushSync` | Да: только DOM |

Такое разделение и есть причина, по которой один и тот же компонент можно
отрендерить в браузере, на сервере и в мобильном приложении: меняется только
рендерер.

> 📌 **Корень (root)** - DOM-узел, содержимым которого управляет React.
> Создается вызовом `createRoot(container)`, получает дерево через
> `root.render(element)` и освобождается через `root.unmount()`.

Точка входа приложения:

```jsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

import App from './components/app';

const root = createRoot(document.getElementById('root'));

root.render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

Внутри корня React владеет содержимым полностью: любые ручные изменения этого
поддерева будут перезаписаны при следующем обновлении. Корней на странице может
быть несколько - например, React-виджет внутри страницы, написанной без React.

**`StrictMode`** - компонент без разметки, включающий дополнительные проверки
только в режиме разработки: каждый компонент рендерится дважды, а эффекты при
монтировании запускаются, очищаются и запускаются снова. Так выявляются
компоненты с побочными эффектами в рендере и эффекты без корректной очистки.
Последовательность при монтировании: `render, render, effect, cleanup, effect`.
В production-сборке `StrictMode` ничего не делает.

🕰️ **`ReactDOM.render(<App />, container)`** - точка входа React 16–17.
В React 18 вызов работал в «устаревшем режиме» с предупреждением в консоли,
в React 19 удален: `import ReactDOM from 'react-dom'; ReactDOM.render` дает
`undefined`. При переносе старого кода заменяется на `createRoot(container)`
и `root.render(<App />)`.

## 1.3 Элемент React

> 📌 **Элемент React** - неизменяемый простой JavaScript-объект, описывающий
> один узел будущего дерева интерфейса: его тип (`type` - строка с именем
> DOM-тега либо функция или класс компонента), свойства (`props`, включая
> вложенное содержимое `children`) и ключ (`key`).

Элемент создает функция `createElement(type, props, ...children)`; JSX -
синтаксис для ее вызова ([1.5](#15-jsx)). Вот как выглядит результат
`<div className="box">hi</div>` (служебные поля опущены):

```js
{
  $$typeof: Symbol(react.transitional.element),
  type: 'div',
  key: null,
  props: { className: 'box', children: 'hi' },
}
```

- `$$typeof` - символ-метка. Объект, пришедший из JSON (например, из ответа
  сервера), не может содержать `Symbol`, поэтому React отказывается рендерить
  такие объекты как элементы. Это защита от внедрения разметки через данные.
- `type` - для DOM-узла строка (`'div'`), для компонента - сама функция или
  класс. Отсюда правило заглавной буквы в именах компонентов
  ([1.6](components.md#16-компонент)): JSX компилирует `<div>` в строку, а
  `<App>` - в идентификатор.
- `props` - все атрибуты плюс `children`. С React 19 сюда же попадает `ref`.
- `key` - идентификатор среди соседей ([1.14](state-and-lifecycle.md#114-списки-и-key)).

Элемент - описание, а не DOM-узел: создать его дешево, он не знает о документе
и не имеет методов. Дерево элементов - «кадр» интерфейса на момент рендера.

**Неизменяемость.** В режиме разработки React замораживает элемент и его
`props` (`Object.freeze`); попытка `element.props.children = '…'` дает
`TypeError`. Изменить то, что показано на экране, можно только одним способом -
вернуть из компонента новое дерево элементов. Это не ограничение ради
ограничения: именно неизменяемость позволяет React сравнивать старое и новое
описание, не опасаясь, что старое кто-то поменял.

Дерево элементов из вложенных `createElement`:

```js
import { createElement } from 'react';

const tree = createElement('section', null, [
  createElement('div', { key: 'head' }, [
    createElement('h1', { key: 'h1' }, 'Заголовок'),
    createElement('h2', { key: 'h2' }, 'Подзаголовок'),
  ]),
  createElement('div', { key: 'body' }, createElement('p', null, 'Абзац')),
]);
```

```
   section
   ├── div
   │   ├── h1  «Заголовок»
   │   └── h2  «Подзаголовок»
   └── div
       └── p   «Абзац»
```

Массив потомков требует `key` у каждого элемента - в JSX эта же структура
записывается без массивов и без ключей ([1.5](#15-jsx)).

## 1.4 Virtual DOM и согласование

> 📌 **Virtual DOM** - хранимое в памяти дерево легковесных объектов,
> описывающее текущий вид интерфейса. При каждом обновлении React строит новое
> дерево, сравнивает его с предыдущим и переносит в реальный DOM только
> найденные различия.

Термин исторический: в современной документации React вместо него описываются
фазы «рендер» и «коммит», а внутренняя структура называется деревом Fiber.
Смысл не изменился: между кодом компонентов и документом стоит промежуточное
представление, и именно с ним работает разработчик.

> 📌 **Согласование (reconciliation)** - алгоритм, которым React сравнивает
> новое дерево элементов с предыдущим и вычисляет операции над DOM, которые
> приводят документ к новому описанию.

### Зачем промежуточное дерево

Операции с DOM дороги: изменение узла может вызвать пересчет стилей,
перерасчет раскладки (layout) и перерисовку части страницы. Сравнение двух
деревьев JavaScript-объектов на порядки дешевле. Поэтому выгодно сначала
вычислить, что именно изменилось, и только потом тронуть DOM - ровно в тех
местах, где различия есть.

⚠️ Virtual DOM не «быстрее DOM». Вручную написанное точечное обновление одного
узла всегда быстрее, чем построение дерева и его сравнение. Выигрыш в другом:
декларативный код получает приемлемую стоимость обновления автоматически, без
ручного отслеживания зависимостей.

### Фазы обновления

```
   триггер            рендер                               коммит
   ─────────          ──────────────────────────────       ─────────────
   изменилось   ──►   вызов компонентов, построение   ──►  применение   ──►   отрисовка
   состояние          нового дерева и сравнение его        изменений          браузером
                      с прошлым (согласование);            к DOM
                      DOM не затрагивается
```

1. **Триггер** - первый рендер корня или изменение состояния компонента
   ([1.11](state-and-lifecycle.md#111-состояние-и-usestate)).
2. **Рендер** - React вызывает функции компонентов, получает новое дерево
   элементов и сравнивает его с предыдущим (согласование). DOM на этой фазе
   не изменяется, поэтому рендер обязан быть чистым: тот же вход - тот же
   результат, никаких побочных эффектов.
3. **Коммит** - найденные различия применяются к DOM за один проход. После
   коммита браузер отрисовывает изменения, и только затем запускаются эффекты
   ([1.20](hooks.md#120-useeffect)).

### Эвристики сравнения

Лучшие известные алгоритмы точного сравнения двух деревьев из `n` узлов
работают за `O(n³)`. React сводит задачу к `O(n)` двумя допущениями:

1. **Элементы разных типов дают разные поддеревья.** Если на месте `<div>`
   появился `<section>`, React не ищет общие части: старое поддерево
   удаляется целиком вместе с состоянием компонентов, новое создается заново.
   Например, счетчик внутри обертки показывал `2`; после смены обертки с `div`
   на `section` он показывает `0`.
2. **Элементы одного типа на той же позиции - тот же узел.** React обновляет
   изменившиеся атрибуты и рекурсивно переходит к потомкам. Состояние
   компонента при этом сохраняется - даже если props стали другими. В
   `isLogin ? <Field label="Логин" /> : <Field label="E-mail" />` введенный
   в первое поле текст остается во втором: для React это один и тот же
   `Field`.

Среди соседей элементы сопоставляются по позиции, а при наличии `key` - по
ключу ([1.14](state-and-lifecycle.md#114-списки-и-key)).

## 1.5 JSX

> 📌 **JSX** - синтаксическое расширение JavaScript, позволяющее записывать
> создание элементов React в виде разметки, похожей на HTML. Браузер JSX не
> понимает: компилятор (Babel, TypeScript, esbuild, SWC) переводит его в
> обычные вызовы функций.

### Во что компилируется

```jsx
const view = (
  <section className="card">
    <h1>{title}</h1>
    <p>Абзац</p>
  </section>
);
```

Современный компилятор (React 17+, режим `automatic`) дает:

```js
import { jsx, jsxs } from 'react/jsx-runtime';

const view = jsxs('section', {
  className: 'card',
  children: [jsx('h1', { children: title }), jsx('p', { children: 'Абзац' })],
});
```

Импорт `react/jsx-runtime` компилятор добавляет сам. 🕰️ В классическом режиме
(React ≤16) тот же код превращался в `React.createElement('section', { className:
'card' }, React.createElement('h1', null, title), …)`, и поэтому в каждом файле
с JSX требовался `import React from 'react'`, даже если `React` в коде не
упоминался. В новом коде этот импорт не нужен; в старом - безвреден.

Все три записи - JSX, `jsx()` и `createElement()` - дают одинаковые элементы.

### Правила синтаксиса

| Правило | Причина |
| --- | --- |
| Один корневой элемент; несколько соседей оборачиваются во фрагмент `<>…</>` | JSX-выражение - один вызов функции, возвращающий один объект |
| Каждый тег закрыт: `<img />`, `<br />`, `<input />` | Парсер JSX строже HTML: незакрытый тег - синтаксическая ошибка |
| Атрибуты - имена свойств DOM в camelCase: `className`, `htmlFor`, `tabIndex`, `onClick` | `class` и `for` - зарезервированные слова JavaScript; остальные приведены к соглашениям DOM API |
| `aria-*` и `data-*` пишутся через дефис, как в HTML | Так их имена заданы в HTML и WAI-ARIA; React передает их в DOM без изменений |
| `style` принимает объект, а не строку: `style={{ borderRadius: '50%' }}` | Числа получают `px` (`width: 120` → `width:120px`), кроме безразмерных свойств: `opacity`, `zIndex`, `lineHeight` |
| Внутри `{}` - любое выражение, но не инструкция (`if`, `for`) | `{}` - аргумент функции; инструкция аргументом быть не может |
| Комментарий - `{/* … */}` | HTML-комментарий `<!-- -->` в JSX недопустим |

Скобки вокруг многострочного JSX после `return` нужны, когда разметка
начинается со следующей строки, и причина не в JSX, а в автоматической
расстановке точек с запятой: `return` с переносом строки возвращает
`undefined`.

### Что выводится в разметку

| Значение в `{}` | Результат |
| --- | --- |
| Строка, число | Текст (с экранированием) |
| Элемент | Вложенный узел |
| Массив | Каждый элемент по очереди; нужны `key` |
| `null`, `undefined`, `true`, `false` | Ничего |
| `0` | ⚠️ Текст `0` - число выводится, в отличие от `false` |
| Объект | Ошибка `Objects are not valid as a React child` |
| Функция | Не выводится, предупреждение в консоли |

Например, `<li>{[].length && 'items'}</li>` дает `<li>0</li>`. Условие для
списка записывается как `items.length > 0 && …` или тернарным оператором.

Текст экранируется всегда: `{'<script>alert(1)</script>'}` попадает в HTML как
`&lt;script&gt;…`. Это встроенная защита от XSS; обойти ее можно только
явно - атрибутом `dangerouslySetInnerHTML={{ __html: html }}`, название
которого напоминает о цене.

### Выражения, условия, стили

```jsx
function Weather({ isFrost, isSun }) {
  return (
    <div style={{ width: 120, borderRadius: '50%', backgroundColor: '#d0d5d2' }}>
      {isFrost && isSun ? <h2>День чудесный</h2> : <h2>День обычный</h2>}
      {isFrost && <p>Мороз</p>}
    </div>
  );
}
```

Три способа условного вывода:

| Способ | Когда |
| --- | --- |
| `cond ? <A /> : <B />` | Две ветки |
| `cond && <A />` | Одна ветка; `cond` - булево, не число |
| `if (…) { return null; }` до `return` | Компонент целиком не выводится |

Вызов функции внутри `{}` допустим, если она возвращает отображаемое значение
(элемент, строку, `null`). Асинхронные данные попадают в разметку через
состояние и эффекты ([1.20](hooks.md#120-useeffect)) или через `use` внутри
`Suspense` ([2.39](../sprint-2/react-async.md#239-use-и-suspense)).
