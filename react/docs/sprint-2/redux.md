# Redux

## 2.6 Что такое Redux

> 📌 **Redux** - библиотека для управления состоянием приложения через
> единое хранилище: все данные лежат в одном объекте, изменяются только
> отправкой действий, а новое состояние вычисляют чистые функции-редьюсеры.

Redux не зависит от React (пакет `redux` не импортирует ничего из `react`);
связку обеспечивает отдельный пакет `react-redux`.

### Три принципа

1. **Единственный источник истины.** Состояние всего приложения - один
   объект в одном хранилище. Нет вопроса «где лежат эти данные» и нет двух
   расходящихся копий.
2. **Состояние только для чтения.** Изменить его можно одним способом -
   отправить действие, объект с описанием того, что произошло. Ни компонент,
   ни запрос не пишут в состояние напрямую.
3. **Изменения описываются чистыми функциями.** Редьюсер получает текущее
   состояние и действие, возвращает новое состояние и не делает ничего
   другого: ни запросов, ни мутаций, ни обращения к `Date.now()`.

### Однонаправленный поток данных

```
                 store.dispatch(action)
   компонент ─────────────────────────────► хранилище
       ▲                                        │
       │                                        ▼
       │                              reducer(state, action)
       │                                        │
       │                                        ▼
       │                                 новое состояние
       │                                        │
       └──────── подписчики уведомлены ◄────────┘
                 (компоненты читают state)
```

Компонент никогда не получает «ручку» для записи - только `dispatch`.
Поэтому любое изменение состояния можно проследить до конкретного действия,
записать в лог, воспроизвести и отменить (на этом построены Redux DevTools -
[2.16](middleware-and-thunk.md#216-redux-devtools)).

### Что дает и чего стоит

| Дает | Стоит |
| --- | --- |
| Доступ к состоянию из любого компонента без проброса props | Шаблонный код: типы действий, генераторы, редьюсеры (сокращен в Redux Toolkit) |
| Выборочная подписка: компонент рендерится при изменении только своей части состояния ([2.11](react-redux.md#211-useselector)) | Отдельный пакет и соглашения, которые нужно выучить команде |
| Предсказуемость: каждое изменение - именованное действие; история воспроизводима | Асинхронность требует middleware ([2.14](middleware-and-thunk.md#214-middleware)) |
| Логика вне компонентов, тестируемая без рендера | Для маленьких приложений - избыточен: хватает `useReducer` и контекста |

**Неизменяемость** - не принцип, а необходимое условие: Redux и `react-redux`
определяют, изменилось ли состояние, сравнением ссылок (`===`). Редьюсер,
мутирующий объект и возвращающий его же, ломает обнаружение изменений -
пример в [2.8](#28-редьюсеры-и-combinereducers).

## 2.7 Экшены и генераторы экшенов

> 📌 **Экшен (action, действие)** - простой объект, описывающий событие в
> приложении: обязательное строковое поле `type` и, по соглашению, данные
> события в поле `payload`.

```js
{ type: 'todos/add', payload: { id: 1, text: 'Купить авокадо' } }
{ type: 'todos/toggle', payload: 1 }
{ type: 'filter/set', payload: 'done' }
```

Экшен - **факт**, а не команда: он говорит «пользователь добавил задачу», а не
«запиши задачу в массив». Как отреагировать, решает редьюсер; один экшен
могут обрабатывать несколько редьюсеров.

Соглашения:

- `type` - строка вида `домен/событие` (`todos/add`). Redux 5 требует именно
  строку: `dispatch({ type: 42 })` бросает `Action "type" property must be
  a string`. 🕰️ Константы `SCREAMING_CASE` (`ADD_TODO`) - стиль
  ранних лет Redux, встречается в старом коде.
- Данные - в `payload` (соглашение Flux Standard Action, принятое Redux
  Toolkit). 🕰️ Данные в корне экшена (`action.text`, `action.id`) - тоже
  допустимая форма, но несовместимая с экшенами, которые генерирует Toolkit.
- Экшен сериализуем: никаких функций, промисов, экземпляров классов. Иначе
  не работают DevTools и запись истории; Redux Toolkit предупреждает об
  этом в разработке ([2.18](redux-toolkit.md#218-зачем-redux-toolkit-configurestore)).

> 📌 **Генератор экшенов (action creator)** - функция, возвращающая экшен;
> избавляет от повторения `type` в каждом `dispatch` и фиксирует форму
> `payload` в одном месте.

```js
let nextId = 1;

const addTodo = (text) => ({ type: 'todos/add', payload: { id: nextId++, text } });
const toggleTodo = (id) => ({ type: 'todos/toggle', payload: id });
const setFilter = (filter) => ({ type: 'filter/set', payload: filter });

store.dispatch(addTodo('Купить авокадо'));
```

Генератор - обычная функция; `dispatch` ему не известен. Связать генератор с
`dispatch` можно вручную (`(text) => dispatch(addTodo(text))`) или
`bindActionCreators` ([2.13](react-redux.md#213-connect)). В Redux Toolkit
генераторы создаются автоматически из редьюсеров
([2.19](redux-toolkit.md#219-createslice-и-immer)).

## 2.8 Редьюсеры и `combineReducers`

> 📌 **Редьюсер** в Redux - чистая функция `(state, action) => newState`,
> которая вычисляет следующее состояние своей части хранилища; при первом
> вызове получает `undefined` и обязана вернуть начальное состояние, на
> незнакомое действие возвращает состояние без изменений.

Название - от `Array.prototype.reduce`: история действий «сворачивается» в
одно значение состояния, `actions.reduce(reducer, initialState)`.

```js
const initialTodos = [];

function todosReducer(state = initialTodos, action) {
  switch (action.type) {
    case 'todos/add':
      return [...state, { id: action.payload.id, text: action.payload.text, completed: false }];
    case 'todos/toggle':
      return state.map((todo) =>
        todo.id === action.payload ? { ...todo, completed: !todo.completed } : todo
      );
    default:
      // Чужие действия: вернуть то же состояние, той же ссылкой
      return state;
  }
}

function filterReducer(state = 'all', action) {
  return action.type === 'filter/set' ? action.payload : state;
}
```

### Правила редьюсера

| Правило | Почему |
| --- | --- |
| Начальное состояние через параметр по умолчанию `state = initial` | Redux при создании хранилища вызывает редьюсер с `undefined`; `combineReducers` проверяет результат и бросает `returned undefined during initialization` |
| `default: return state` - та же ссылка | Каждый редьюсер получает **все** действия приложения; вернуть новый объект на чужое действие - уведомить всех подписчиков без причины |
| Никаких мутаций | Изменение обнаруживается сравнением ссылок; мутированный объект - «ничего не изменилось» |
| Никаких побочных эффектов и недетерминизма | Редьюсер могут вызвать повторно (DevTools, тесты); `Date.now()`, `Math.random()`, запросы делают результат невоспроизводимым - идентификаторы и время генерируются в генераторе экшена или middleware |

Что происходит при мутации: редьюсер делает `state.items.push(…)` и
возвращает `state`. В хранилище один элемент, а компонент с
`useSelector((s) => s.items)` показывает `0` и не рендерится: ссылка на
`items` не изменилась, для `react-redux` изменения не было.

### `combineReducers`

Состояние приложения - объект с несколькими ключами, и удобно, чтобы за
каждый ключ отвечал свой редьюсер. `combineReducers` собирает их в корневой:

```js
import { combineReducers } from 'redux';

const rootReducer = combineReducers({
  todos: todosReducer,
  filter: filterReducer,
});

// Эквивалент вручную:
// (state = {}, action) => ({
//   todos: todosReducer(state.todos, action),
//   filter: filterReducer(state.filter, action),
// })
```

Каждый вложенный редьюсер получает только свой срез (`state.todos`) и все
действия. Если ни один срез не изменился, корневой редьюсер возвращает тот
же объект состояния: после `dispatch({ type: 'unknown' })` `getState()`
дает прежнюю ссылку. Форма состояния повторяет форму объекта в
`combineReducers`: `{ todos: […], filter: 'all' }`.

Часть состояния под одним ключом вместе с ее редьюсером и действиями в
терминологии Redux Toolkit называется **слайсом** (slice) -
[2.19](redux-toolkit.md#219-createslice-и-immer).

## 2.9 Хранилище

> 📌 **Хранилище (store)** - объект, который держит текущее состояние
> приложения и предоставляет три операции: прочитать состояние
> (`getState`), отправить действие (`dispatch`) и подписаться на изменения
> (`subscribe`).

```js
import { legacy_createStore as createStore } from 'redux';

const store = createStore(rootReducer);

const unsubscribe = store.subscribe(() => {
  console.log(store.getState().todos.length);
});

store.dispatch(addTodo('Купить авокадо')); // подписчик: 1
store.dispatch(toggleTodo(1));             // подписчик: 1
unsubscribe();
store.dispatch(addTodo('Еще'));            // подписчик не вызван

store.getState();
// { todos: [{ id: 1, text: 'Купить авокадо', completed: true }, { id: 2, … }], filter: 'all' }
```

| Метод | Что делает |
| --- | --- |
| `getState()` | Возвращает текущее состояние - тот самый объект, который вернул корневой редьюсер |
| `dispatch(action)` | Синхронно прогоняет действие через middleware и редьюсер, заменяет состояние и вызывает всех подписчиков; возвращает действие (или результат middleware) |
| `subscribe(listener)` | Регистрирует функцию, вызываемую после каждого `dispatch`; возвращает функцию отписки |
| `replaceReducer(next)` | Заменяет корневой редьюсер - для разделения кода и горячей замены |

`dispatch` синхронен: сразу после `store.dispatch(action)` `getState()`
возвращает уже новое состояние - в отличие от `setState` в React
([1.11](../sprint-1/state-and-lifecycle.md#111-состояние-и-usestate)).
Асинхронность добавляют middleware ([2.15](middleware-and-thunk.md#215-redux-thunk)).

### `createStore(reducer, preloadedState?, enhancer?)`

- `reducer` - корневой редьюсер.
- `preloadedState` - начальное состояние поверх умолчаний редьюсеров:
  восстановление из `localStorage`, данные с сервера при SSR.
- `enhancer` - расширитель хранилища; главный - `applyMiddleware(…)`
  ([2.14](middleware-and-thunk.md#214-middleware)). Если передать два
  аргумента и второй - функция, Redux считает его расширителем.

🕰️ **`createStore` объявлен устаревшим** в Redux 4.2 и остается таким в
Redux 5: редактор показывает его зачеркнутым, документация направляет к
`configureStore` из Redux Toolkit. Функция работает и удаляться не будет;
для кода без предупреждения есть синоним `legacy_createStore`.

### Подписка компонентов

`subscribe` - низкоуровневый механизм: подписчик получает уведомление о
**любом** изменении и сам решает, что делать. Так Redux используют без React
(обновляя DOM руками). В React-приложении `subscribe` напрямую не вызывают:
`react-redux` подписывает компоненты через `useSelector` и рендерит только
те, чей выбранный фрагмент изменился ([2.11](react-redux.md#211-useselector)).
