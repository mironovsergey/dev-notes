# Маршрутизация в SPA и History API

## 3.1 Маршрутизация: серверная и клиентская

> 📌 **Маршрутизация (routing)** - сопоставление URL с содержимым, которое
> должно быть показано по этому адресу.

Два места, где это сопоставление может происходить:

| | Серверная маршрутизация | Клиентская маршрутизация |
| --- | --- | --- |
| Кто решает, что показать | Сервер: по URL отдает отдельный HTML-документ | JavaScript в браузере: по URL рендерит нужные компоненты |
| Переход по ссылке | Полная загрузка новой страницы | Смена URL без перезагрузки; меняется часть DOM |
| Состояние приложения при переходе | Теряется (новый документ) | Сохраняется |
| Первая загрузка | Готовый HTML | Один HTML плюс JavaScript, который построит страницу |
| Прямой заход по адресу `/list/42` | Сервер знает этот путь | ⚠️ Сервер должен отдать тот же `index.html` на любой путь, иначе 404 |

> 📌 **Одностраничное приложение (SPA)** - приложение, которое загружает один
> HTML-документ и дальше обновляет его содержимое средствами JavaScript, не
> запрашивая у сервера новые страницы.

Клиентская маршрутизация решает две задачи: **синхронизировать URL и
интерфейс в обе стороны** (изменился URL - изменился экран; пользователь
перешел на другой экран - изменился URL) и **не терять поведение браузера** -
историю, закладки, кнопку «назад».

Способа изменить URL без перезагрузки два:

| Способ | Вид адреса | Как работает |
| --- | --- | --- |
| Хеш | `/#/list/42` | Часть после `#` браузер не отправляет на сервер; событие `hashchange`. 🕰️ Прием времен, когда History API не было; сегодня - для статических хостингов без настройки сервера |
| History API | `/list/42` | `pushState` меняет путь без запроса; сервер должен отдавать `index.html` на все пути |

## 3.2 History API

> 📌 **History API** - набор методов объекта `window.history` для работы с
> историей сеанса: добавить или заменить запись без перезагрузки страницы
> (`pushState`, `replaceState`) и перемещаться по записям (`back`, `forward`,
> `go`); о перемещении браузер сообщает событием `popstate`.

```
   history (стек записей текущей вкладки)

     ┌───────────────┐
     │ /list/42      │ ◄── текущая (после pushState)
     ├───────────────┤
     │ /list         │
     ├───────────────┤          back()  ──► индекс − 1
     │ /             │          forward() ──► индекс + 1
     └───────────────┘          go(n)   ──► индекс + n
```

### Запись в историю

```js
// Добавить запись: URL меняется, страница не перезагружается
window.history.pushState({ id: 'shop' }, '', '/shop');

// Заменить текущую запись: для фильтров и query-параметров, чтобы не засорять историю
window.history.replaceState({ id: 'shop', tab: 2 }, '', '/shop?tab=2');
```

| Параметр | Назначение |
| --- | --- |
| `state` | Произвольный сериализуемый объект, привязанный к записи; доступен как `history.state` и в `event.state` при возврате на эту запись |
| второй аргумент | Исторически - заголовок; спецификация называет его `unused`, браузеры игнорируют. Передается пустая строка |
| `url` | Новый адрес - относительный или абсолютный **в том же origin**; необязателен, если нужно изменить только `state` |

После `pushState({ id: 'shop' }, '', '/shop')` `location.pathname` равен
`/shop`, `history.state` - `{ id: 'shop' }`, запроса к серверу нет.
Документ при этом **не знает**, что URL изменился: `<title>`, содержимое и
фокус остаются прежними - их обновляет само приложение.

### Перемещение по истории

| Метод | Эквивалент |
| --- | --- |
| `history.back()` | Кнопка «назад»; `history.go(-1)` |
| `history.forward()` | Кнопка «вперед»; `history.go(1)` |
| `history.go(n)` | На `n` записей; `go(0)` перезагружает страницу |
| `history.length` | Число записей в сеансе; читать индекс текущей нельзя |

### Событие `popstate`

Браузер сообщает о перемещении по истории событием `popstate` на `window` -
при нажатии «назад»/«вперед» и при вызове `back`/`forward`/`go`.
⚠️ `pushState` и `replaceState` событие **не вызывают**: приложение само
знает, что изменило адрес.

Отсюда схема любого клиентского маршрутизатора: перехватить клики по
ссылкам и вызвать `pushState`; слушать `popstate` для кнопок браузера; в
обоих случаях прочитать `location.pathname` и отрендерить нужный экран.

⚠️ Более новый **Navigation API** (`window.navigation`, событие `navigate`)
объединяет оба случая в один перехватчик, но появился недавно и пока не
заменил History API в библиотеках маршрутизации.

## 3.3 Собственный маршрутизатор

Маршрутизатор на React укладывается в полсотни строк, и написать его один
раз полезно: становится видно, что именно делает библиотека.

Три части: обертка над History API с подпиской, контекст с текущим путем и
два компонента - `Route` и `Link`.

```jsx
import { createContext, useContext, useSyncExternalStore } from 'react';

/**
 * Обертка над History API: pushState плюс подписка.
 * Слушатели уведомляются и о переходах приложения, и о кнопках браузера (popstate).
 */
function createHistory() {
  const listeners = new Set();
  const notify = () => listeners.forEach((listener) => listener(window.location.pathname));
  window.addEventListener('popstate', notify);

  return {
    push(path) {
      window.history.pushState(null, '', path);
      notify(); // pushState сам popstate не вызывает: подписчики уведомляются вручную
    },
    listen(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    get location() {
      return window.location.pathname;
    },
  };
}

const history = createHistory();
const RouterContext = createContext(window.location.pathname);

function Router({ children }) {
  // Подписка на внешний источник: текущий путь читается из history, обновления приходят через listen
  const path = useSyncExternalStore(history.listen, () => history.location);
  return <RouterContext value={path}>{children}</RouterContext>;
}

function Route({ path, children }) {
  const current = useContext(RouterContext);
  return current === path ? children : null;
}

function Link({ to, children }) {
  const handleClick = (e) => {
    e.preventDefault(); // иначе браузер перезагрузит страницу
    history.push(to);
  };
  return <a href={to} onClick={handleClick}>{children}</a>;
}
```

```jsx
function App() {
  return (
    <Router>
      <nav>
        <Link to="/">Главная</Link>
        <Link to="/login">Вход</Link>
      </nav>
      <Route path="/"><h1>Главная страница</h1></Route>
      <Route path="/login"><h1>Страница входа</h1></Route>
    </Router>
  );
}
```

Что здесь важно:

- **`href` у ссылки остается.** Открытие в новой вкладке, копирование адреса
  и доступность работают как у обычной ссылки; перехватывается только
  обычный клик.
- **`useSyncExternalStore`** - штатный хук для подписки на источник данных
  вне React ([1.19](../sprint-1/hooks.md#119-хуки-и-их-правила)); он же
  используется внутри `react-redux` и Zustand. Вариант с `useState` +
  `useEffect` для подписки тоже работает, но допускает рассинхронизацию в
  конкурентном рендере.
- **`Route` сравнивает путь целиком.** Библиотечный маршрутизатор добавляет
  шаблоны с параметрами (`/list/:country`), ранжирование, вложенность,
  разбор `?query` - каждая из этих задач нетривиальна, и здесь проходит
  граница между учебным кодом и React Router.
